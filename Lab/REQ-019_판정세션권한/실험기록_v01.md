## 2. 관찰

1. 규칙 검사에서 걸리는 명령은 이 세션에서 「requires approval」 계열 메시지로 반환되었다(T0, T3, T5, T8, T9, T10, T14, T16, T19, T21, T22). 「Permission to use Bash has been denied.」는 이 세션에서 한 번도 나오지 않았다.
2. `git -C <경로> <하위 명령>`은 `Bash(git status*)`·`Bash(git log*)`·`Bash(git diff*)`에 맞지 않고 기본 읽기 전용 명령으로도 인정되지 않는다(T3, T5, T19). `-C`를 빼면 실행된다(T2, T4, T8b, T24). 공식 문서 「What a Bash rule doesn't match」는 `Bash(git push *)`가 `git -C . push`에 맞지 않는다고 적었다.
3. 복합 명령(`;`, `&&`, `|`)은 하위 명령마다 따로 검사된다. 모든 하위 명령이 `allow` 또는 기본 읽기 전용 명령이면 실행되고(T4, T6, T12), 하나라도 맞지 않으면 그 부분 때문에 확인 요청이 된다(T0, T5, T14). 공식 문서 「Compound commands」의 「A rule must match each subcommand independently」와 같다.
4. `cd <다른 폴더> && git ...`은 하위 명령이 모두 허용 대상이어도 별도 검사로 확인 요청이 된다(T8). 공식 문서 「Read-only commands」의 「`cd` with `git`」 항목과 같다.
5. 맨 앞 환경 변수 대입(`FOO=1 python -m pytest ...`)은 `Bash(python -m pytest*)`에 맞지 않는다(T9). 공식 문서 「Wrappers」는 일부 알려진 변수만 벗겨 내고 그 밖의 변수 대입 뒤로는 `allow` 규칙이 맞지 않는다고 적었다.
6. `$?` 같은 특수 변수를 쓰는 `echo`(T14)와 `python -I -c`(T16)는 `allow`에 없다.
7. PowerShell 도구: 저장소 설정에 `PowerShell(...)` 규칙이 없다. `Get-Date`, `Get-ChildItem | Select-Object`, `git log`, `git diff --no-index`는 기본 읽기 전용으로 인정되어 실행되었고(T11, T17, T20, T23), `git status`는 확인 요청이 되었다(T10, T22). 하위 식 `$()`·괄호 식을 쓴 명령은 「Command contains subexpressions」로 확인 요청이 되었다(T21). 공식 문서는 PowerShell 규칙이 `PowerShell(<명령> *)` 형식이며 Bash 규칙과 같은 모양이라고 적었다.
8. `allow`에 있는 `date`(T1, T18 `%:z` 형식 포함), `git status`(T2, T24), `git ls-files`(T6, T12), `git diff --no-index`(T7, T8b), `check_standard.py`(T15)는 단독 실행과 허용 명령끼리의 복합 실행에서 확인 없이 실행되었다.
