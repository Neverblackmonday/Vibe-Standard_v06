# 05. 비서실 – Claude Code CLI 인수인계 정책 (Handoff Policy)

> 본 문서는 비서실(Antigravity)의 역할 한계, 원스톱 실행 명령 규격, 인수인계 절차를 정의한다. 등급별 단계 차이는 `Workflow/03_라이프사이클_및_워크플로우` 「등급별 흐름」을 따른다.

## 1. 비서실의 역할 한계

| 구분 | 허용 | 금지 |
| :--- | :--- | :--- |
| 작업 경로 | `Departments/Secretariat/` 아래 `assets/`, `docs/requests/`, `results/`, `workspace/`. 핫픽스는 대표님이 사전 승인한 대상 파일 | 그 밖의 경로 수정 |
| 작업 내용 | 지시 접수, 조사, 브리핑, REQ와 전수 점검표 작성, 실행 명령 안내, 점검표 근거 대조, 핫픽스 전결 | 핫픽스 밖의 코드·명세(EC·PRD·TAD) 작성, 판정서 작성 |
| 승인 | REQ 초안과 핫픽스 대상 목록을 대표님께 제출 | `approved:`, `confirmed:` 대리 기재 |
| 실행 | 원스톱 실행 명령을 대표님께 안내 | Claude Code CLI 직접 실행, 커밋, 푸시 |

승인된 REQ의 내용을 바꿔야 하면 비서실이 수정안을 작성해 대표님의 재승인을 받고, 재승인 때 `approved:` 날짜를 갱신한다.

## 2. 인수인계 절차

```text
① 비서실: REQ 초안과 전수 점검표 작성 → 작성 세션과 다른 세션의 판정 → 대표님께 제출
② 대표님: REQ 검토 → approved: "YYYY-MM-DD" 기재
③ 비서실: REQ 「작업자 인수인계 및 Claude Code CLI 실행 명령」 절의 원스톱 실행 명령을 안내
④ 대표님: 저장소 루트에서 명령을 한 번 실행 → 원스톱 파이프라인이 workflow: 끝까지 무인 진행
⑤ 비서실: 최종 판정서의 점검표 번호별 근거를 대조해 대표님께 보고
⑥ 대표님: 최종 판정서와 git diff 확인 → 최종 승인 → 커밋 요청
```

- 실행 위치는 저장소 루트다. 저장소 밖에서 실행하면 `CLAUDE.md`와 `.claude/` 설정이 적용되지 않는다.
- 파이프라인이 중단 조건으로 멈추면 대표님이 결정한 뒤 같은 명령을 다시 실행한다. 오케스트레이터는 기존 산출물(EC `status:`, 판정서 `result:`)로 진행 위치를 판단해 이어서 진행한다.
- 공식 진행 상태는 각 단계 산출물로만 판단한다. 비서실의 `workspace/` 기록은 근거로 쓰지 않는다.

## 3. 원스톱 실행 명령

REQ 「작업자 인수인계 및 Claude Code CLI 실행 명령」 절에는 아래 명령 하나만 기재한다. 메인 세션이 오케스트레이터가 되어 부서 서브에이전트를 기동하므로 `--agent`를 지정하지 않는다.

```bash
claude --model claude-opus-5-5 --effort <등급별 값> --permission-mode acceptEdits "Departments/Secretariat/docs/requests/REQ-xxx.md 원스톱 파이프라인을 실행하라. Workflow/03의 「원스톱 파이프라인」 절을 따른다."
```

| 요소 | 규격 |
| :--- | :--- |
| `--model` | `claude-opus-5-5` (`Workflow/04_모델_운용_기준` 「모델과 effort」) |
| `--effort` | REQ `tier:`에 따라 비서실이 채운다. Critical·Major `high`, Minor `medium` |
| `--permission-mode acceptEdits` | 파일 편집 확인을 생략한다. 거버넌스 파일 쓰기 차단(`deny`)과 삭제·이동·커밋·푸시 확인(`ask`)은 그대로 적용된다 |
| 지시문 | REQ 경로(확장자 포함)와 따를 절 제목. 매뉴얼 본문이나 REQ에 없는 작업을 넣지 않는다 |

### 3.1 작성 시 금지 사항
- 인증 정보(API 키, 토큰)를 명령에 넣지 않는다.
- `--dangerously-skip-permissions` 등 권한 통제 전체를 끄는 옵션을 쓰지 않는다. `deny`·`ask` 통제가 무력화되기 때문이다.
- 단계별 명령을 따로 기재하지 않는다. 단계 인계는 오케스트레이터가 맡는다.
