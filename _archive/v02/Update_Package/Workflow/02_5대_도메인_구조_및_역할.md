# 02. 5대 도메인 구조 및 역할 (Domain Structure & Roles)

> 본 문서는 부서별 책임과 산출물, 공통 폴더 규격, 작업 구역 권한을 정의한다. 부서 목록의 원천은 `AGENTS.md` 「부서 구조」다.

## 1. 부서 구성

핵심 도메인은 비서실·설계·개발·품질·운영 5개 부서이고, 마케팅·비주얼은 REQ `workflow:`에 기재된 경우에만 기동하는 지원 부서다. 비서실은 안건 기획과 최종 보고, 설계·개발·품질은 원스톱 파이프라인의 단계, 운영은 배포를 맡는다. 서브에이전트 정의는 `.claude/agents/<부서>.md`(`secretariat`, `design`, `development`, `quality`, `operations`, `marketing`, `visual`)에 둔다.

## 2. 부서별 책임과 산출물

| 부서 | 책임 | 산출물 (부서 폴더 기준) | 금지 |
| :--- | :--- | :--- | :--- |
| 비서실 | 지시 접수, 조사, 브리핑, REQ와 전수 점검표 작성, 원스톱 실행 명령 안내, 점검표 근거 대조, 핫픽스 전결 | `assets/inbox/`(요구 메모), `assets/research/`(조사 원자료), `assets/briefings/`(브리핑), `docs/requests/REQ-xxx.md`, `results/HOTFIX-xxx.md` | 핫픽스 밖의 코드·명세 작성, 판정서 작성, `approved:`·`confirmed:` 대리 기재 |
| 설계 | EC 작성, 고객 제품 PRD·TAD 작성·개정, 거버넌스 적용본 작성 | `docs/tad/EC-xxx.md`, `docs/prd/`, `docs/tad/`, `assets/live/`(설계 파라미터), `results/`(설계 결과서), `workspace/`(적용본) | 코드 작성, 자기 산출물 판정, 표준 자체 설계를 `docs/prd/`·`docs/tad/`에 기록 |
| 개발 | 승인된 EC·명세 범위 안의 구현과 테스트, 표준 검사 스크립트 유지보수 | `assets/src/`, `assets/tests/`(`test_*.py`), `assets/scripts/check_standard.py`, `results/DEV-xxx.md` | scope 밖 수정, 요청하지 않은 기능 추가, 자기 산출물 판정 |
| 품질 | EC 판정, 최종 판정, 점검표 번호별 근거 기재 | `results/RES-xxx-EC.md`, `results/RES-xxx.md`, `docs/`(품질 기준서), `assets/`(픽스처) | 결함 직접 수정. 수정은 해당 부서에 반려한다 |
| 운영 | 런타임 파라미터, 배포 패키지 구성, 운영 기록 | `assets/live/`, `assets/releases/`, `assets/logs/`, `docs/`, `results/` | 승인되지 않은 인프라 변경과 파라미터 수정 |
| 마케팅 | 전략·기획, 홍보 자산 | `docs/`, `assets/banners/`, `assets/media/`, `results/` | 시스템 코드와 아키텍처 문서 수정 |
| 비주얼 | 디자인 시스템, 디자인 에셋 | `docs/`, `assets/icons/`, `assets/fonts/`, `assets/images/`, `results/` | 소스코드 직접 구현 |

서식 원천은 각 문서 폴더의 템플릿이다(`REQ_TEMPLATE.md`, `EC_TEMPLATE.md`, `PRD_TEMPLATE.md`, `TAD_TEMPLATE.md`, `RES_TEMPLATE.md`, `HOTFIX_TEMPLATE.md`). 템플릿 위치는 `Workflow/07_엔지니어링_변경통제_및_서식_명세` 「문서 체계」를 따른다.

### 2.1 비서실 전수 점검표 책무
1. REQ 작성 시 「검증 및 완료 기준」 절에 전수 점검표를 작성하고, 점검 번호를 「요청 원문」 절의 지시 항목과 1:1로 대응시킨다.
2. 최종 판정서가 발행되면 대표님께 최종 보고하기 전에 점검 번호마다 근거(파일·절·검증 결과)가 있는지 대조한다. 근거가 빈 번호가 있으면 그 사실을 함께 보고한다.

## 3. 공통 1차 하위폴더 규격

```text
Departments/<부서>/
├── docs/       # 기획서, 명세, 가이드 등 정제된 문서 (버전 번호 없는 파일명)
├── assets/     # 코드, 테스트, 스크립트, 파라미터, 조사 자료, 배포본 등 실제 자산
├── results/    # 부서가 공식 발행한 결과서와 판정서
└── workspace/  # 임시 작업 산출물, 중간 메모, 거버넌스 적용본
```

빈 폴더는 `.gitkeep`으로 유지한다. 최종 산출물은 `docs/`, `assets/`, `results/`에만 두고 `workspace/`의 중간 산출물과 섞지 않는다.

## 4. 작업 구역 권한

| 구분 | 수정 가능 경로 |
| :--- | :--- |
| REQ 승인 전 | `Departments/Secretariat/assets/inbox/`, `Departments/Secretariat/docs/requests/`(REQ 초안), 각 부서 `workspace/` |
| REQ 승인 후 | 각 단계 서브에이전트는 REQ `scope:` 가운데 자기 단계 경로와 자기 부서 `results/`·`workspace/` |
| 핫픽스 | 대표님이 사전 승인한 대상 파일(3개 이하)과 `Departments/Secretariat/results/` |
| 대표님 전용 | `CEO/References/`(AI 읽기 전용), 거버넌스 파일(`AGENTS.md` 「핵심 원칙」의 거버넌스 구역) |

거버넌스 파일의 개정 절차는 `Workflow/06_거버넌스_엔지니어링_아키텍처` 「거버넌스 파일 개정 절차」를 따른다.
