# PRD: 제품 요구사항 정의서 제목

> 작성 방법: 이 파일을 복사해 `Departments/Design/docs/prd/<번호>_<주제>.md`(예: `01_개요.md`)로 저장한다. 파일명에 버전 번호를 붙이지 않는다. 서식 규격은 `Workflow/07_엔지니어링_변경통제_및_서식_명세` 5절을 따른다.

## 1. 제품 개요
- **해결할 문제**: 사용자가 현재 겪는 문제를 기재한다.
- **대상 사용자**: 주요 사용자 유형과 사용 환경을 기재한다.
- **제품 목표**: 측정 가능한 목표를 기재한다 (예: 주문 등록 시간 5분 이내).

## 2. 범위
| 구분 | 항목 |
| :--- | :--- |
| 포함 | 이번 제품에서 제공하는 기능 |
| 제외 | 이번 제품에서 제공하지 않는 기능과 사유 |

## 3. 사용자 시나리오
| 번호 | 사용자 | 상황 | 행동 | 기대 결과 |
| :---: | :--- | :--- | :--- | :--- |
| US-01 | 사용자 유형 | 사용 상황 | 사용자 행동 | 시스템 반응 |

## 4. 기능 요구사항
| 번호 | 요구사항 | 우선순위 | 수용 기준 | 관련 시나리오 |
| :---: | :--- | :---: | :--- | :---: |
| FR-01 | 시스템이 제공해야 하는 기능 | 필수 | 검증 가능한 통과 조건 | US-01 |

우선순위는 `필수`, `권장`, `선택` 가운데 하나로 기재한다.

## 5. 비기능 요구사항
| 번호 | 분류 | 요구사항 | 측정 기준 |
| :---: | :--- | :--- | :--- |
| NFR-01 | 성능 | 응답 시간 요구 | 측정 방법과 기준값 |
| NFR-02 | 보안 | 개인정보 처리 요구 | 확인 방법 |

## 6. 제약 조건 및 가정
- **제약 조건**: 기술, 일정, 법규상 제약을 기재한다.
- **가정**: 확인되지 않았으나 전제로 삼은 사항을 기재한다. 가정은 7절 미결 사항과 연결한다.
