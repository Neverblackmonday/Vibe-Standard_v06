## 3. 세부 설계

### 3.1 `Audits/` (외부 감사실) 아키텍처 및 네이밍/삭제 규격 (결함 N3 해소)
1. **폴더 위상**: `CEO/`, `Departments/`, `Workflow/`와 함께 루트 4대 대문자 폴더로 격리 배치 (`Audits/`).
2. **날짜 기반 감사 문서 명명 체계**:
   - 규칙: `AUDIT_YYYYMMDD_<주제>_v01.md` (예: `Audits/AUDIT_20261006_표준가치분석_v02.md`).
3. **`Claude outputs/` 마이그레이션 및 삭제 절차**:
   - 기존 Git 추적 파일 3건(`VibeStandard_v02_표준적합성검토_v01~v03.md`) 및 워크스페이스 보관 파일 2건을 `Audits/` 아래로 정규 이동.
   - `git rm -r "Claude outputs"` 실행으로 Git 추적에서 공식 삭제 (머리말 `scope:`에 `Claude outputs`가 명시되어 있으므로 `check_standard.py`의 Scope Quarantine 정상 통과 보장).
4. **배포본 격리 정책**:
   - 고객 배포본(`Vibe Standard_v02_sample`)에는 `Audits/` 폴더와 `AUDIT_TEMPLATE.md` 서식만 배포.
   - 자사 내부 감사 산출물(`AUDIT_*.md`)은 `.gitattributes`에 `Audits/AUDIT_* export-ignore`를 지정하여 원천 비공개 보장.

### 3.2 템플릿 보관소 집약 통합 (`Workflow/templates/`) 설계 (결함 N2 해소)
1. **신설 목적**: 각 부서 폴더에 분산되어 고객이 찾기 어려웠던 템플릿 파일들의 원천을 `Workflow/templates/`로 단일화 집약.
2. **배치 목록**:
   - `Workflow/templates/REQ_TEMPLATE.md`
   - `Workflow/templates/RP_TEMPLATE.md`
   - `Workflow/templates/HOTFIX_TEMPLATE.md`
   - `Workflow/templates/PRD_TEMPLATE.md`
   - `Workflow/templates/TAD_TEMPLATE.md`
   - `Workflow/templates/EC_TEMPLATE.md`
   - `Workflow/templates/RES_TEMPLATE.md`
   - `Workflow/templates/AUDIT_TEMPLATE.md`
3. 각 템플릿 내부에는 `체크리스트(Checklist)` 테이블을 필수 기본 항목으로 완비.

### 3.3 문서 섹션별 개정 번호 마킹(Change Tracking Tag) 규격
1. **규칙**: 문서 버전이 리비전될 때(예: `_v03`), 이번 리비전에서 실제로 변경된 섹션 제목 끝에만 현행 버전 태그 `(v03)`를 표기함.
2. **구 버전 태그 자동 청소**: 직전 리비전 태그(`(v02)`)는 차기 리비전 시 자동으로 삭제하여 현행 변경점만 선명히 강조 유지.
