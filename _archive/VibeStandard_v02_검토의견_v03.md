## 2. 즉시 수정할 결함: 파일 손상

### D1. 한글이 `?`로 바뀐 파일 5건

아래 5건은 한글이 모두 `?` 문자로 저장되어 있습니다.

- 파일 안에는 원래 글자가 남아 있지 않습니다.
- 파일을 만들 때 쓴 원문(스크립트나 대화 기록)이 있으면 그 원문으로 다시 저장합니다. 없으면 새로 작성합니다.

| 파일 | `?` 개수 | 영향 |
|---|---|---|
| `setup.cmd` | 104 | 안내 문구가 깨지고, 첫 커밋 메시지가 `chore: ??? ?? ?? v02 ???`로 기록됩니다 |
| `.githooks/pre-commit` | 54 | 안내 문구가 깨집니다 |
| `Departments/Development/assets/scripts/check_standard.py` | 223 | 주석과 출력 문구가 깨집니다. 문법 검사(`py_compile`)는 통과합니다 [실측] |
| `Departments/Secretariat/docs/requests/REQ_TEMPLATE.md` | 233 | 서식의 절 제목과 안내문을 읽을 수 없습니다 |
| `Departments/Quality/results/RES_TEMPLATE.md` | 121 | 위와 같습니다 |

`?` 개수는 각 파일에서 `?` 바이트를 센 값입니다 [실측]. 이 개수에는 원래부터 있던 `?`도 들어 있습니다. 예를 들어 `pre-commit`의 `RESULT=$?`가 그렇습니다. 따라서 이 개수를 손상된 글자 수로 보지 않습니다.

### D2. 백틱이 사라지고 제어 문자가 들어간 파일 4건

대상 파일은 `AGENTS.md`와 `.claude/agents/`의 `marketing.md`·`quality.md`·`visual.md`입니다.

- **현상:** `AGENTS.md`와 `.claude/agents/*.md`에는 백틱이 하나도 없고, 그 자리에 제어 문자가 들어가 있습니다 [실측].

| 파일 | 벨 문자(0x07) | 폼피드(0x0C) |
|---|---|---|
| `AGENTS.md` | 18개 | 2개 |
| `marketing.md` | 1개 | — |
| `visual.md` | 2개 | — |
| `quality.md` | — | 1개 |

- **결과:**
  - `assets/`가 「(벨)ssets/」로 바뀌었습니다.
  - `feat:`가 「(폼피드)eat:」로, `fail`이 「(폼피드)ail」로 바뀌었습니다.
  - `results/`는 줄바꿈과 「esults/」로 쪼개졌습니다. 이 때문에 `AGENTS.md` 1절 표의 행이 중간에서 끊깁니다. 예를 들어 `AGENTS.md` 20행은 `esults/: RES-001.md …`로 시작하고, `quality.md` 16행은 `esult: pass … (폼피드)ail(…)`입니다.
- **추정 원인(확인 불가):** PowerShell 큰따옴표 문자열 안에서 백틱은 이스케이프 문자입니다. `` `a ``는 벨, `` `f ``는 폼피드, `` `r ``은 CR로 바뀝니다. 이 CR이 저장할 때 줄바꿈으로 기록된 것으로 보입니다. 파일에는 단독 CR이 0개이고, 모두 CRLF로 저장되어 있습니다.
- **조치:** 백틱을 복원해 다시 작성합니다. 파일을 만들 때는 PowerShell의 작은따옴표 문자열이나 here-string(`@' … '@`)을 쓰거나, 편집기로 직접 저장합니다.

### D3. `pre-commit`이 CRLF 줄바꿈이라 실행되지 않음

- **현상:** `.githooks/pre-commit`은 13줄 모두 CRLF로 끝납니다 [실측].
- **재현:** 같은 형태의 파일로 실행해 보았습니다 [실측].

| 실행 방법 | 결과 | 종료 코드 |
|---|---|---|
| 직접 실행 | `cannot execute: required file not found` | 127 |
| dash(`sh`)로 실행 | `Syntax error: end of file unexpected (expecting "then")` | 2 |
| bash로 실행 [판정 재현] | `syntax error: unexpected end of file` | 2 |
| 이 파일을 훅으로 연결하고 `git commit` [판정 재현] | `fatal: cannot exec '.githooks/pre-commit': No such file or directory`, 커밋 실패 | 1 |

  - Windows의 Git for Windows 환경에서 같은 결과가 나오는지는 확인 불가입니다.
- **조치:**
  1. `pre-commit`을 LF로 저장합니다.
  2. `.gitattributes`에 `.githooks/* text eol=lf`를 추가합니다. v01 `.gitattributes` 5행에 있던 규칙인데, v02에서는 빠졌습니다.

- **조치:** 1절 표의 「RES-설계」 표기를 넓혀 `RES-{부서}-{번호}.md` 같은 공통 규칙으로 정합니다. 템플릿을 비서실·품질에만 둘지, 공통 위치로 옮길지도 함께 정합니다.

- **`touch` 처리:** `touch`는 내용을 덮어쓰지 않고 시각을 바꾸거나 빈 파일을 만듭니다. v01과 맞추려는 목적 외에는 꼭 넣을 이유가 없으므로 선택 사항입니다.

### S11. 초기화 순서

- **현상:** `setup.cmd`는 `git add .`로 폴더 전체를 첫 커밋에 넣습니다.
- **영향:** `Claude outputs/`를 지우기 전에 실행하면 이 폴더도 첫 커밋에 들어갑니다.
