* **개선안**:

### 2.2 [지적 2] 템플릿과 거버넌스 파일 혼재 -> **전적으로 맞음 (치명적 설계 결함 인정)**
* **검토 의견**:
  1. `PROJECT.md`는 프로젝트마다 당연히 수정되어야 하는 문서인데, 검사 스크립트가 거버넌스 불변 파일로 묶어 커밋을 차단하는 것은 명백한 오버엔지니어링입니다.
  2. 대표님이 직접 거버넌스 파일(`AGENTS.md`, 스크립트 등)을 수정하려 해도 커밋 훅(`check_standard.py`)에 걸려 `--no-verify` 없이는 커밋이 불가능한 교착이 발생합니다.
* **개선안**:
  - `PROJECT.md`를 거버넌스 불변 목록에서 즉시 제외.
  - 거버넌스 파일 수정 차단을 `check_standard.py`(Git 훅)에서 제거하고, **`.claude/settings.json`의 `deny` 권한 목록으로 일원화**.
  - 이렇게 하면 AI 에이전트는 거버넌스 파일을 건드릴 수 없지만, 대표님은 일반 Git 커밋으로 언제든지 자유롭게 규정을 개정할 수 있습니다.

### 2.3 [지적 3] 규정과 실제 강제 수준의 괴리 -> **전적으로 맞음 (수용)**
* **검토 의견**: 노 훅 아키텍처이므로 런타임 실시간 차단이 아닌 Git 커밋 시점에만 검사가 동작하며, REQ의 `approved:`도 에이전트가 직접 써넣을 위험이 존재합니다.
* **개선안**:
  - `AGENTS.md`의 문구를 "런타임 차단"에서 "Git 커밋 시점 기계 검사 및 대표님의 커밋 전 최종 승인"으로 현실에 맞게 정합화.

### 2.4 [지적 4] 검사 스크립트 오탐 및 미탐 결함 -> **전적으로 맞음 (즉시 패치 필요)**
* **F4-3 (치명적 허점)**: `is_whitelisted()` 함수가 `if "results" in parts`처럼 단순 단어 포함 여부로 검사하여, 소스코드 경로에 `src/results/exploit.py`가 있으면 승인 없이 통과되는 버그 확인.
  - **해결책**: `parts[0] == "Departments" and parts[2] in ("results", "workspace")`와 같이 정확한 디렉터리 깊이(`depth 2`) 기반으로 엄격하게 한정.
* **F4-4 (초안 REQ 오탐)**: 신규 REQ 초안(`REQ-002.md`, 미승인)이 있는 상태에서 기존 승인된 안건(`REQ-001.md`) 작업을 커밋하려 할 때, 파일명 정렬 상 최신인 REQ-002를 보고 전체 커밋을 차단하는 오탐 확인.
  - **해결책**: 무조건 마지막 REQ를 보는 것이 아니라, 변경된 파일들의 `scope:`를 포함하고 있는 **해당 안건의 REQ**를 역추적하여 검증하도록 스크립트 개선.
