# 04. 모델 운용

> 이 문서가 정하는 것: 단계별 모델과 effort, 토큰을 줄이는 타깃 컨텍스트 규칙, 모델 메타데이터 기록.
> 다른 문서가 정하는 것: 실행 명령의 형식 → `Workflow/05_인수인계_및_실행명령`.

## 1. 모델

| 대상 | 모델 | 모델 ID |
| :--- | :--- | :--- |
| Claude Code 오케스트레이터와 파이프라인 안의 모든 서브에이전트 | Claude Opus 5.5 | `claude-opus-5-5` |
| 비서실 | 제한 없음. 모델을 정하지 않는다. 비서실은 핫픽스 대상 파일을 수정하고 HOTFIX를 작성하지만 독립 판정 대신 대표님 사후 확인을 받으며(`Workflow/03_라이프사이클` 「핫픽스 트랙」 3항), 실제 실행 모델은 머리말에 기록한다(4절) | — |

- 서브에이전트 정의 파일(`.claude/agents/*.md`)은 머리말에 `model: inherit`를 적어 오케스트레이터의 모델을 이어받는다. 모델 이름을 적지 않는다.

- `--model`에는 별칭(`opus`)이 아닌 모델 ID를 쓴다.

## 2. effort

- 기본값은 `medium`이다.
- `high` 이상은 대표님이 REQ 「결정 사항 및 선택지」 표에서 승인한 경우에만 쓴다.
- 허용 값은 `low`, `medium`, `high`, `xhigh`, `max`이다.

## 3. 타깃 컨텍스트 규칙 (REQ-014_v01)

1. 서브에이전트 지시문에는 REQ 경로, EC 경로, 대상 파일 경로, 단계명, 실행 명령의 effort 표기(`effort: <값>`. `Workflow/05_인수인계_및_실행명령` 「실행 명령」)만 넣고 매뉴얼 본문을 붙이지 않는다.
2. 매뉴얼은 필요한 절만 찾아 읽는다. 각 매뉴얼 첫머리의 「이 문서가 정하는 것」으로 읽을 문서를 고른다.
3. 재판정 지시문에는 직전 판정서의 결함 표와 문체 지적 표, 반려 부서 결과서의 수정 목록, 변경분, 대표님 답 뒤 재판정 횟수를 새로 세는 재판정이면 그 사실과 직전 판정서 경로(`Workflow/03_라이프사이클` 「재판정 한도」)만 넣는다. 변경분은 기록 문서 새 버전(REQ·EC 등)은 `git diff --no-index <직전 버전> <새 버전>`, 거버넌스 적용본은 `git diff --no-index <직전 판정 대상 적용본 폴더> <새 적용본 폴더>`, 추적 중인 그 밖의 파일은 `git diff HEAD -- <경로>`로 구한다. 적용본 폴더는 판정 지적을 반영할 때마다 버전을 올리므로(`Workflow/06_통제장치_및_배포` 「거버넌스 파일 개정 절차」 4항) 두 적용본 폴더는 `REQ-xxx_적용본_v01`과 `_v02`처럼 이웃한 버전이다. 새 파일은 `git status --porcelain -uall`로 찾아 전문을 넣는다. 단, 직전 버전이 있는 기록 문서 새 버전과 거버넌스 적용본은 위의 `--no-index` 비교로 변경분을 구하므로 전문을 넣지 않는다. `git diff HEAD`는 마지막 커밋 이후의 누적 차이이므로 직전 판정 이후의 변경은 수정 목록으로 특정한다. 문체 반영 대조(`Workflow/03_라이프사이클` 「판정 지적의 구분과 문체 지적 처리」)의 지시문도 같은 구성(직전 판정서의 문체 지적 표, 변경분)으로 만든다.
4. 작성 과정의 대화 내용은 판정 세션에 넘기지 않는다.

## 4. 모델 메타데이터 기록

공식 문서(REQ, EC, DEV, RES, HOTFIX)의 머리말에 작성하거나 판정한 모델과 effort를 아래 기준으로 적는다.

- **모델**: 확인할 수 없으면 `"확인 불가"`로 적는다. 단, RES의 `auditor.model`에는 `"확인 불가"`를 적지 않는다. 판정 모델을 확인할 수 없으면 판정서를 발행하지 않고 오케스트레이터에 보고한다.
- **effort(REQ, EC, DEV, RES)**: 실행 명령 지시문의 effort 값을 출처와 함께 `"<값> (실행 명령 기준)"`으로 적는다(예: `"medium (실행 명령 기준)"`). PM은 자기 지시문의 표기(`Workflow/05_인수인계_및_실행명령` 「실행 명령」), 서브에이전트는 PM 지시문의 표기(3절 1항)를 출처로 쓴다. 출처에서 값을 얻을 수 없을 때만 `"확인 불가"`로 적는다.
- **effort(HOTFIX)**: 위 기준의 대상이 아니다. HOTFIX는 비서실이 실행 명령 없이 작성하므로 실행 명령이라는 출처가 없다. 실제로 적용한 effort를 적고, 확인할 수 없으면 `"확인 불가"`로 적는다.

```yaml
author:            # RES는 auditor:
  agent: "Design"
  model: "Claude Opus 5.5"
  effort: "medium (실행 명령 기준)"
```
