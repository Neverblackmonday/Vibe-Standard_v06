# 04. 모델 운용

> 이 문서가 정하는 것: 단계별 모델과 effort, 토큰을 줄이는 타깃 컨텍스트 규칙, 모델 메타데이터 기록.
> 다른 문서가 정하는 것: 실행 명령의 형식 → `Workflow/05_인수인계_및_실행명령`.

## 1. 모델

| 대상 | 모델 | 모델 ID |
| :--- | :--- | :--- |
| Claude Code 오케스트레이터와 파이프라인 안의 모든 서브에이전트 | Claude Opus 5.5 | `claude-opus-5-5` |
| 창구 | 제한 없음. 판정서와 REQ를 작성하지 않으므로 모델을 정하지 않는다 | — |

- 서브에이전트 정의 파일(`.claude/agents/*.md`)은 머리말에 `model: inherit`를 적어 오케스트레이터의 모델을 이어받는다. 모델 이름을 적지 않는다.
- **판정 모델**: 판정서(`RES-*`)의 `auditor.model`은 `Claude Opus 5.5`여야 한다. 판정서를 작성할 수 있는 주체는 `AGENTS.md` 「불변 원칙」 4항을 따른다.
- `Claude Fable 5.1`은 쓰지 않는다(대표님 결정).
- `--model`에는 별칭(`opus`)이 아닌 모델 ID를 쓴다.

## 2. effort

- 기본값은 `medium`이다.
- `high` 이상은 대표님이 REQ 「결정 사항 및 선택지」 표에서 승인한 경우에만 쓴다.
- 허용 값은 `low`, `medium`, `high`, `xhigh`, `max`이다.

## 3. 타깃 컨텍스트 규칙

1. 서브에이전트 지시문에는 REQ 경로, EC 경로, 대상 파일 경로, 단계명만 넣고 매뉴얼 본문을 붙이지 않는다.
2. 매뉴얼은 필요한 절만 찾아 읽는다. 각 매뉴얼 첫머리의 「이 문서가 정하는 것」으로 읽을 문서를 고른다.
3. 재판정 지시문에는 직전 판정서의 결함 표, 반려 부서 결과서의 수정 목록, 변경분만 넣는다. 변경분은 기록 문서(REQ·EC 등 새 버전 파일)는 `git diff --no-index <직전 버전> <새 버전>`, 거버넌스 적용본은 `git diff --no-index <원본> <적용본>`, 추적 중인 그 밖의 파일은 `git diff`로 구한다. 새 파일은 `git status --porcelain -uall`로 찾아 전문을 넣는다. `git diff`는 HEAD 대비 누적 차이이므로 직전 판정 이후의 변경은 수정 목록으로 특정한다.
4. 작성 과정의 대화 내용은 판정 세션에 넘기지 않는다.

## 4. 모델 메타데이터 기록

공식 문서(REQ, EC, DEV, RES, HOTFIX)의 머리말에 실제로 작성하거나 판정한 모델과 effort를 적는다. 확인할 수 없으면 `"확인 불가"`로 적는다. 단, RES의 `auditor.model`에는 `"확인 불가"`를 적지 않는다. 판정 모델을 확인할 수 없으면 판정서를 발행하지 않고 오케스트레이터에 보고한다.

```yaml
author:            # RES는 auditor:
  agent: "Design"
  model: "Claude Opus 5.5"
  effort: "medium"
```
