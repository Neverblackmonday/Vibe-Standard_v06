# 02. 부서 구조 및 작업구역

> 이 문서가 정하는 것: 저장소 구조, 부서별 책임과 산출물, 비서실·창구의 책무, 작업 구역(누가 언제 어디를 수정할 수 있는가).
> 다른 문서가 정하는 것: 부서별 권한 한계의 원칙 → `AGENTS.md` 「부서와 권한 한계」, 산출물 이름·번호 → `Workflow/07_문서_서식_및_번호`.

## 1. 저장소 구조

```text
[저장소 루트]
├── AGENTS.md            # 최상위 규정
├── CLAUDE.md            # Claude Code 진입 파일 (@AGENTS.md 한 줄)
├── setup.cmd            # 최초 1회: Git 초기화, 훅 경로 설정, 첫 커밋
├── .gitattributes       # 줄바꿈 규칙, 배포본 제외 규칙
├── .gitignore
├── .claude/             # settings.json(권한), agents/(부서 서브에이전트)
├── .githooks/pre-commit # 커밋 전 check_standard.py 실행
├── Workflow/            # 매뉴얼 01~07, templates/(서식)
├── Audits/              # 외부 검토 보고서
├── CEO/References/      # 대표님 전용 자료 (CEO/ 전체가 대표님 구역)
├── Departments/         # 부서 작업 공간 (3절)
├── Update_Package/      # 업데이트 패키지 자리 (보류, Workflow/06 「배포본과 업데이트 패키지」)
└── _archive/            # 지난 버전 기록 (읽기 전용)
```

## 2. 부서별 책임과 산출물

| 부서 | 서브에이전트 | 책임 | 산출물 (부서 폴더 기준) |
| :--- | :--- | :--- | :--- |
| 비서실 | `secretariat` | REQ와 체크리스트 작성, 핫픽스 수행 | `docs/requests/REQ-*`, `results/HOTFIX-*`, `assets/inbox/`(요구 메모), `assets/research/`(조사 자료), `assets/briefings/`(보고 자료) |
| 설계 | `design` | EC 작성, 고객 제품 PRD·TAD 작성·개정, 거버넌스 적용본(매뉴얼·규정) 작성 | `docs/tad/EC-*`, `docs/prd/`, `docs/tad/`, `assets/live/`(설계 파라미터), `results/`, `workspace/`(적용본) |
| 개발 | `development` | 승인된 범위의 구현과 테스트, 거버넌스 적용본(스크립트·설정) 작성 | `assets/src/`, `assets/tests/`, `results/DEV-*`, `workspace/`(적용본) |
| 품질 | `quality` | REQ 판정, EC 판정, 최종 판정 | `results/RES-*` |
| 운영 | `operations` | 런타임 파라미터, 배포 묶음, 운영 기록 | `assets/live/`, `assets/releases/`, `assets/logs/`, `docs/`, `results/` |
| 마케팅 | `marketing` | 전략·기획, 홍보 자산 | `docs/`, `assets/banners/`, `assets/media/`, `results/` |
| 비주얼 | `visual` | 디자인 시스템, 디자인 에셋 | `docs/`, `assets/icons/`, `assets/fonts/`, `assets/images/`, `results/` |

- 서브에이전트 정의는 `.claude/agents/<서브에이전트>.md`에 둔다. 정의 파일은 역할과 참조할 절만 적고, 이 문서의 책임·산출물을 다시 적지 않는다.
- 설계 파라미터(`Design/assets/live/`)는 명세가 정하는 기준값이고, 런타임 파라미터(`Operations/assets/live/`)는 운영 중 바뀌는 값이다.

### 2.1 비서실 세션과 창구의 책무

| 주체 | 책무 |
| :--- | :--- |
| 창구 (코워크, Antigravity 등) | ① 대표님과 대화해 요구를 모으고 `Departments/Secretariat/assets/inbox/`에 요구 메모를 남긴다 ② 실행 명령을 대표님께 안내하거나 실행한다(`Workflow/05_인수인계_및_실행명령`) ③ 최종 판정서의 체크리스트 번호별 근거를 대조해 대표님께 보고한다 ④ 핫픽스 대상 목록을 대표님께 제시해 사전 승인을 받는다 ⑤ 대표님에게서 직접 받은 승인 문구로 승인 기록을 남기고 승인 필드와 「결정」 열을 기재한다(`Workflow/07_문서_서식_및_번호` 「승인 기록」) |
| 비서실 세션 (Claude Code `secretariat`) | ① 요구 메모로 REQ와 체크리스트를 작성한다(`Workflow/03_라이프사이클` 「REQ 작성 파이프라인」) ② 사전 승인된 핫픽스를 수정·검증하고 HOTFIX를 작성한다 |

- 창구는 요구 메모, 승인 기록, 승인 필드와 「결정」 열(4절), 검토 보고서 외에는 저장소 파일을 수정하지 않는다. 창구의 검토 보고서는 `Audits/`에 둔다.
- 승인 필드(`approved:`, `confirmed:`)와 REQ 「결정」 열은 `Workflow/07_문서_서식_및_번호` 「승인 기록」을 따라 기재한다. 서브에이전트(비서실 세션 포함)는 기재하지 않는다.

## 3. 공통 1차 하위폴더

```text
Departments/<부서>/
├── docs/       # 정제된 문서(기획서, 명세, 안건)
├── assets/     # 실제 자산(코드, 테스트, 스크립트, 파라미터, 조사 자료)
├── results/    # 공식 결과서와 판정서
└── workspace/  # 중간 산출물, 메모, 거버넌스 적용본
```

빈 폴더는 `.gitkeep`으로 유지한다. 비서실 `assets/`에는 바로 아래에 파일을 두지 않고 하위 폴더(`inbox/`, `research/`, `briefings/`)에만 둔다. 최종 산출물은 `docs/`, `assets/`, `results/`에만 둔다.

## 4. 작업 구역

| 구분 | 수정할 수 있는 경로 | 수정 주체 |
| :--- | :--- | :--- |
| REQ 승인 전 | `Departments/Secretariat/assets/inbox/`(요구 메모) | 창구 |
| 승인 기재 | `Departments/Secretariat/assets/inbox/`(승인 기록), 대상 REQ의 승인 필드와 「결정」 열, 대상 HOTFIX의 `confirmed:`(`Workflow/07_문서_서식_및_번호` 「승인 기록」) | 창구, 오케스트레이터 |
| REQ 승인 전 | `Departments/Secretariat/assets/`, `Departments/Secretariat/docs/requests/`, `Departments/Secretariat/workspace/` | 비서실 세션 |
| REQ 승인 전 | `Departments/Quality/results/`(REQ 판정서), `Departments/Quality/workspace/` | 품질 서브에이전트 |
| REQ 승인 후 | REQ `scope:` 가운데 자기 단계의 경로와 자기 부서 `results/`·`workspace/` | 각 단계 서브에이전트 |
| 핫픽스 | 대표님이 사전 승인한 대상 파일과 `Departments/Secretariat/results/` | 비서실 세션 |
| 외부 검토 | `Audits/` | 창구 등 저장소 밖 세션 |
| 대표님 전용 | `CEO/`, 거버넌스 파일, `_archive/` | 대표님 |

- 커밋 전 검사가 scope 대조에서 빼는 경로는 이 표와 별개의 구현 목록이며, 원천은 `check_standard.py`다(`Workflow/06_통제장치_및_배포` 「커밋 전 검사」).
