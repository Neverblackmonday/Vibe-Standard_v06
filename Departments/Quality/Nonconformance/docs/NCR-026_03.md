# NCR-026_03: 부적합 기록

## 1. 부적합 요약
- **사건**: 중단. EC 작성 단계에서 설계 서브에이전트가 `git --version`(Bash)을 실행하려 했으나 권한 확인 요청(「This command requires approval」)이 승인되지 않아 실행되지 않았다. 설계는 `EC-026_v01.md` 6절 「실행하지 못한 명령」 1행에 이 명령을 적고 마지막 칸을 「대신하지 않음(값이 필요 없어짐)」으로 적었다. PM은 이 행이 `Workflow/03_라이프사이클` 5.4절 2항 끝 문장(확인 요청 승인 뒤 실행)과 3항(대신함) 어디에도 해당하지 않아 7절 5항 단서의 예외에 들지 않는다고 보고, EC 산출물을 받은 뒤 EC 판정 전에 멈췄다.
- **근거 문서**: `Departments/Secretariat/workspace/실행기록_REQ-026.md`(시각 `2026-10-11T21:26:48+09:00`의 「EC 작성」 산출물 수령·중단 행), 멈춘 단계의 최신 산출물 `Departments/Design/docs/tad/EC-026_v01.md`(6절 1행, 357행)
- **중단 조건**: `Workflow/03_라이프사이클` 「중단 조건」 5항(`allow` 목록 밖 명령의 권한 확인 요청)

| :---: | :--- | :---: | :--- |
| 1 | 설계 세션이 `allow` 목록 밖 명령 `git --version`을 실행해 권한 확인 요청이 생기고, 승인되지 않아 실행되지 않음 | `C8` | ① **`allow` 목록 밖 명령(확인함)**. `.claude/settings.json`의 Git 규칙은 `Bash(git status*)`·`Bash(git diff*)`·`Bash(git log*)`·`Bash(git show*)`·`Bash(git ls-files*)`(4~8행)와 `ask`의 `git commit`·`git push`(55·56행)뿐이다. `git --version`은 어느 규칙에도 맞지 않고, 실제로 권한 확인 요청이 생겼으므로 Claude Code 기본 읽기 전용 명령에도 들지 않는다. `Workflow/06_통제장치_및_배포` 2.1절 「명령 형태」 「원리」(50행)와 `.claude/agents/design.md` 19행은 앞부분이 `allow` 규칙이나 기본 읽기 전용 명령과 맞아야 한다고 이미 정한다. 따라서 규칙의 빈틈이 아니라 실행 전에 명령을 `allow` 목록과 대조하지 않은 실행 절차 위반이다. ② **값을 얻으려는 목적 자체가 판단에 필요 없었음(확인함)**. 설계는 비서실 PC Git의 `--trailer` 옵션 지원 여부를 보려고 실행했다(EC 357행). 그러나 이 명령은 PM 세션이 도는 PC의 Git 버전만 보여 주며 비서실 PC의 Git 버전을 직접 보여 주지 않는다. EC는 `--trailer`를 쓰지 않고 둘째 `-m` 인자로 근거 줄을 적도록 정했고(3.2절 G4, 121행), EC 본문에서 이 명령의 결과에 기대는 값은 없다(Grep 도구, 패턴 `trailer|Git 버전|--version`, 결과는 121행과 357행뿐). 설계 판단에 쓰지 않을 값을 얻으려고 목록 밖 명령을 시도한 것이 이번 멈춤의 직접 원인이다. ③ **5.4절에 「값이 필요 없어져 대신하지 않음」의 처리가 없음(확인함)**. 5.4절은 승인 뒤 실행(2항 끝 문장), 대신함(3항), 대신할 수 없음(4항)만 두고, 5항은 대신하지 못했으면 마지막 칸을 「대신하지 못함」으로 시작하게 한다. 설계는 정해진 문구 대신 「대신하지 않음」을 적었고, PM은 이를 예외에 들지 않는 행으로 보고 7절 5항대로 멈췄다. 결과에 기대는 값이 없는 시도 명령도 같은 멈춤으로 이어지는 구조다. ④ **영향**. EC 본문의 값 가운데 이 명령으로 채운 것이 없으므로 EC 내용에 빠진 확인은 없다고 본다. EC 판정은 아직 실행하지 않았다 |
