**② 실행 부분의 처리(EC-019 3.6절 「띄우지 않는 경우 ②의 확인 구분과 사유를 ACC에 적는다」)**
- 인수 시험은 중첩 세션(`claude -p`, EC-019 3.4절 3번의 방법)을 띄우지 않는다. 사유: ① 중첩 세션은 인증·네트워크·모델 호출에 기대므로 구현 단계와 최종 판정에서 다시 실행할 때마다 결과가 같다고 볼 수 없다(EC-019 4절 위험 4·5). ② R1~R7은 사례마다 수정 전 사본과 적용본 사본의 세션을 여러 번 띄워야 해 실행 비용이 크고, 개발이 같은 시험을 이미 구현 단계 산출물로 수행한다(EC-019 3.4절 3번).
- 대신 시험은 재현 시험이 기대는 설정 조건을 결정적으로 확인한다.
  - `test_c8_2_target_commands_allowed_in_bash_and_powershell`: 대상 명령(D3, 03 적용본 5.2절 1항)을 06 적용본 2.1절 「명령 형태」대로 적은 명령이 적용본 `allow`의 Bash 규칙과 PowerShell 규칙에 모두 맞는다(시각 조회 `date`는 Bash만. PowerShell `Get-Date`는 기본 읽기 전용이어서 등록 대상이 아니다. 06 적용본 2.1절 「명령 도구」). 원인 E(R1·R2)의 조치를 확인한다.
  - `test_c8_2_case_forms_not_allowed_by_settings`: 원인 A~D의 수정 전 형태(`git -C <경로>`, `cd <폴더>`, 맨 앞 환경 변수 대입, `echo "exit=$?"`)가 적용본 `allow` 규칙에 맞지 않는다. 형태 문제를 규칙 완화로 가리지 않았는지 확인한다(EC-019 2.3절 「`Bash(...)` 규칙의 추가」, 3.4절 3번 「원인 대조」).
- 규칙 일치 판단은 Claude Code 권한 규칙의 접두 일치를 단순화한 것이다(끝의 ` *`는 단어 경계이며 인자 없는 명령도 맞는 것으로 보고, 그 밖의 `*`는 임의 문자열). 인자 없는 `check_standard.py`가 `PowerShell(… *)` 규칙에 실제로 맞는지는 이 시험이 아니라 개발의 R2가 확인한다(EC-019 F5). 실제 세션에서의 허용·거부는 `DEV-019_v02` R1~R7을 최종 판정이 열람해 확인한다.
- 대상 명령 목록은 시험 파일의 `GIT_AND_CHECK_COMMANDS`·`BASH_ONLY_COMMANDS`, 수정 전 형태 목록은 `CASE_FORM_COMMANDS`다.

**④의 시험 범위**
- `test_c8_4_deny_same_as_original`, `test_c8_4_ask_not_reduced`는 체크리스트 8 ④ 문구 그대로다.
- `test_c8_4_only_powershell_rules_added_to_allow`는 EC-019 3.4절 2번 ①(「바뀐 곳이 `allow`의 `PowerShell(...)` 추가뿐이다」, 2.2절 5번 「`deny`·`ask`는 바꾸지 않는다」)과 EC-019 5절 완료 기준 4가 체크리스트 8 ④의 확인으로 정한 범위다. 기존 `allow` 항목의 순서·내용 유지, 더한 항목이 모두 `PowerShell(`로 시작함, `ask` 동일, `permissions` 밖 설정과 `permissions`의 키 구성 동일을 확인한다.
- JSON 문법(EC-019 3.4절 1번 ①의 `python -m json.tool` 확인)은 시험의 `applied` 픽스처가 적용본을 `json.loads`로 읽을 때 함께 확인된다. 문법이 맞지 않으면 모든 시험이 픽스처 단계에서 실패한다.
