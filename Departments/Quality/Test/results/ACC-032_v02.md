- `onestop`(대상 REQ `created_at: "2026-10-20T10:00:00+09:00"`, scope `Workflow/02_x.md`): 다른 안건·대상 커밋 없음(0), 다른 진행 중 안건의 EC 산출물·DEV 산출물이 작업 트리에 있음(1), REQ 판정서만 있음(0), 끝난 안건 커밋이 작성 시각 뒤·scope 경로(1)·작성 시각 앞(0)·다른 경로(0)·03 특례 경로(1), `created_at` 없는 버전은 `created` 날짜 0시부터(1), 끝나지 않은 안건의 커밋(0), 없는 REQ 경로(2).

**시험 설계의 전제(EC가 형식을 정하지 않아 시험이 정한 것)**
- 「REQ 번호」(`--number <REQ 번호>`, EC 3.6절 6번)는 `REQ-950`처럼 `REQ-`를 붙인 형태로 넘긴다. 이 표준이 「REQ 번호」를 그 형태로 쓰기 때문이다(`Workflow/03_라이프사이클` 최종 판정 기준 7의 「REQ 번호와 `_`로 시작」).
- 준비 명령의 스테이징 목록은 경로와 05 1.1절 6번의 분류 번호(①~⑪ 원문자)를 한 줄에 적고, 분류하지 못한 변경은 「분류하지 못한」이 들어간 줄 뒤에 적으며, 커밋 메시지는 줄마다 그대로 출력한다고 본다(EC 3.6절 5번 「출력」).
- 옛 경로 잔존 검사의 실패 출력은 `<경로>:<줄 번호>`를 담는다(EC 3.6절 2번 ④).
- 설치 점검은 사용자 홈을 표준 방식(Windows의 `USERPROFILE`, 그 밖의 `HOME`)으로 찾는다고 본다. 개발부가 홈을 바꾸는 별도 인자·환경 변수를 두어도 기본 동작이 표준 방식이면 시험 결과는 같다.
- 결과서에서 반영 명령은 4절 표 줄의 인라인 코드(`python -I …`, `cp "…" "…"`)로, 삭제 대상은 제목에 「삭제 대상」이 있는 절의 인라인 코드 경로로 읽는다(EC 3.10절 8번, 3.13절 ④⑦).

**구현 시간**
- 반영 뒤 상태를 만드는 커밋은 이동한 파일 전체를 스테이징하므로, 새 커밋 전 검사가 파일마다 내용을 읽으면 수 분이 걸릴 수 있다. 시험의 명령 시간 제한은 명령마다 30분이다.

## 3. 시험 파일
> 해시는 `git diff --no-index --full-index /dev/null <파일>` 출력의 `index` 줄에서 `..` 뒤의 값이다. 최종 판정이 같은 명령으로 대조한다.

| 경로 | 해시 |
| :--- | :--- |
| `Departments/Quality/assets/acceptance/REQ-032_v02/test_req032.py` | `b6b7ff054cc8f0c2ab6aece8db948aba602db5c2` |

- 해시 조회: 저장소 루트에서 Bash 도구로 `git diff --no-index --full-index /dev/null <파일> | grep ^index`를 파일 세 개에 차례로 실행했다(한 명령 줄. 끝에 `date -Iseconds`, 결과 `2026-10-17T00:54:45+09:00`). 명령마다 Git이 `warning: in the working copy of '<파일>', LF will be replaced by CRLF the next time Git touches it`을 출력했다. 해시를 구한 뒤 시험 파일을 고치지 않았다.
- 직전 폴더 `REQ-032_v01`의 파일은 고치지 않았다(`ACC-032_v01` 3절의 해시 그대로).
- `pytest.ini`는 `addopts = -p no:cacheprovider`만 둔다(`ACC-031_v01` 3절과 같은 내용, 같은 해시).
- `conftest.py`의 `--acc-design-dir`, `--acc-dev-dir`, `--acc-dev-result`, `--acc-rpt-result`는 결함 사본으로 Red를 확인할 때만 쓰는 옵션이다. 현행 인수 시험 실행(구현 단계, 최종 판정)에서는 주지 않는다.
- 시험은 이 저장소에서 파일을 읽고 `git ls-files`·`git status`·`git show 655a45d:<파일>`을 조회만 한다. 시험 저장소(반영 뒤 상태, 겹침·착수 판단용 저장소, 첫 커밋 저장소)와 시험용 사용자 홈은 pytest `tmp_path` 아래에만 만든다. 시험 저장소 안의 커밋·스테이징·삭제는 `Workflow/06_통제장치_및_배포` 2.1절(설계 적용본)의 예외(pytest `tmp_path` 아래 시험 저장소 안의 명령)에 든다.

## 7. 실행하지 못한 명령
> 판정 세션 밖 서브에이전트가 이 문서를 작성하는 단계에서 실행하지 못한 명령과, 권한 확인 요청이 승인되어 실행한 명령을 적는다. 기준과 오케스트레이터의 확인은 `Workflow/03_라이프사이클` 「판정 세션 밖의 명령 실행」을 따른다. 대신하지 못했으면 마지막 칸을 「대신하지 못함」으로 시작하고, 승인되어 실행했으면 「확인 요청 승인 뒤 실행」을 적는다. 없으면 표 대신 「없음」을 적는다.

없음

- 이 세션의 명령(`ls`, `mkdir`·`cp`(새 폴더와 새 파일 생성), `python -m pytest`, `git diff --no-index`, `date -Iseconds`, `grep`, `head`, `cat`, PowerShell 환경 변수 조회)은 저장소 루트에서 실행했고 권한 확인 요청 없이 실행되었다. `mkdir`·`cp`·`ls`·`grep`·`head`·`cat`을 `&&`·`|`·`;`로 묶은 명령이 있었다(새 폴더 생성과 복사, 해시 조회, 이 문서를 스크래치 폴더의 앞부분·뒷부분 파일로 나눠 쓴 뒤 합치기). 스크래치 폴더 경로는 절대 경로로 적었다.
