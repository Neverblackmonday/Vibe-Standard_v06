2. 03 적용본 5절 기준 7은 「범위 대조 때 조회한 작업 트리」에서 일회성 파일을 찾게 한다. `.gitignore`가 무시하는 파일(예: `Departments/Development/workspace/REQ-013_재현시험_20261009a.log`)은 `git status --porcelain -uall`에 나오지 않아 목록에서 빠질 수 있다. 이 파일은 커밋되지 않으므로 커밋 전 검사와 커밋 내용에는 영향이 없고, 작업 트리에 남는 것만 다르다.
3. `check_standard.py` 311행의 실패 안내 문구는 `git restore --staged <경로>`를 조치로 제시한다. 05 적용본 8.1절 4항 ①은 비서실이 대표님 지시 없이 `git restore`를 쓰지 않게 하고, 5항은 실패하면 멈추고 보고하게 하므로, 비서실은 이 안내를 따르지 않고 멈춘다. 두 문장은 주체(대표님·PM의 조치 안내와 비서실의 절차)가 달라 동작 모순은 없으나, 같은 상황에서 서로 다른 행동을 적고 있다. `check_standard.py`는 REQ `scope:` 밖이므로 고치지 않았다.
4. 05 적용본 1.1절 6번 ⑤는 결과서 「변경 파일」 절의 경로를 스테이징 대상으로 남긴다. 결과서 「변경 파일」 절에 적힌 일회성 스크립트(예: `RPT-015_v01` 2절 15·16번)가 최종 판정서 「삭제 대상」에도 적혀 5번 정리에서 지워지면, 미추적 파일은 `git status`에 나오지 않아 스테이징할 것이 없고, 추적 중인 파일은 `git rm`으로 이미 스테이징되어 ⑥으로 들어간다. 3.1절 ①의 모의 실행에서 정리 뒤 `git status`에 지운 미추적 파일이 나오지 않았다.
