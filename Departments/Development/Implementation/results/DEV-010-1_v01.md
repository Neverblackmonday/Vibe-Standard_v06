반영은 대표님이 최종 승인 때 Git Bash에서 저장소 루트로 이동해 실행한다(`Workflow/06_통제장치_및_배포` 「거버넌스 파일 개정 절차」 5항). 폴더 이름 끝의 `.적용본`은 반영할 때 뗀다. 설계 적용본(`AGENTS.md`, `Workflow/03`·`05`·`06`·`07`)의 반영 명령은 `Departments/Design/results/RPT-010-1_v01.md` 8절에 있다.

| 적용본 경로 | 원본 경로 | 반영 명령 |
| :--- | :--- | :--- |
| `Departments/Development/workspace/REQ-010-1_적용본_v01/Departments/Development/assets/scripts.적용본/check_standard.py` | `Departments/Development/assets/scripts/check_standard.py` | `cp "Departments/Development/workspace/REQ-010-1_적용본_v01/Departments/Development/assets/scripts.적용본/check_standard.py" "Departments/Development/assets/scripts/check_standard.py"` |
| (없음. 폐지) | `.claude/agents/secretariat.md` | `git rm ".claude/agents/secretariat.md"` |

**반영 시점과 순서** (REQ 요청 항목 2, D3. `RPT-010-1`과 같은 문구)

1. 시점: REQ-010 적용본과 같은 최종 승인 때 반영한다.
2. REQ-010 적용본 11개 파일을 `RPT-010_v01` 6절 명령으로 반영하고, 그 변경만 스테이징해 REQ-010 커밋(`feat: [REQ-010] …`)을 만든다.
3. 이어서 이 안건의 적용본을 반영한다. 03·05·06·07은 2항의 반영본을 덮어쓴다. `AGENTS.md` 적용본과 검사기 적용본을 복사하고, `secretariat.md`를 삭제한다. 그 변경과 `EC-010-1`을 스테이징해 이 안건 커밋(`feat: [REQ-010-1] …`)을 만든다.
4. 2항과 3항 사이에 이 안건의 적용본을 반영하지 않는다. 2항의 커밋에 이 안건의 변경이 섞이면 어느 REQ의 scope도 변경 파일 전체를 덮지 못한다(REQ 2절 배경).

## 7. 확인하지 못한 항목
- **사례 G의 기록 순서 의존성**: `load_records()`는 REQ를 HOTFIX보다 먼저 목록에 넣으므로, 사례 G는 「파일 수를 넘은 HOTFIX를 건너뛰고 뒤의 REQ로 통과」하는 순서를 실행하지 않는다. 결과(REQ로 통과)는 확인했으나 HOTFIX가 앞에 오는 순서는 현재 코드에서 생기지 않아 시험하지 않았다.
- **이름 변경·삭제가 섞인 HOTFIX의 파일 수**: 검사기는 이름 변경을 원래 경로와 새 경로 두 줄로 센다(원본과 같은 동작, 06 4절 표 순서 2). 그래서 파일 2개의 이름을 바꾼 HOTFIX는 4개로 세어 실패한다. 핫픽스 대상 조건에 「새 파일 없음」이 있어 이름 변경은 대상 밖으로 보았고, 이 경우는 시험하지 않았다(확인 불가).
- **`acceptEdits` 모드에서 `deny`·`ask`가 그대로 적용되는지의 실측**: 이 단계에서 실측하지 않았다(4.4절 4번). 06 적용본 2.1절 서술은 현행 05 3절의 서술을 옮긴 것이다.
- **일부 조회의 초 단위 시각**: Grep 도구 조회와 일부 `grep` 실행은 초 단위 시각을 기록하지 못해 「전후」로 적었다.
