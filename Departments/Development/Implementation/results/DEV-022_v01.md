## 6. 실험 결과 (실험 단계를 맡은 경우만)
> 뒤 단계에서 이 결과서의 다음 버전을 쓰면 이 절을 그대로 옮긴다(`Workflow/03_라이프사이클` 「실험 단계」).

- **실험 목적**: 세션별 모델 지정과 실제 실행 모델 확인의 실측. ① 오케스트레이터와 다른 모델로 서브에이전트가 실행되는지 ② `model: inherit`의 상속 ③ 실행 모델을 확인하는 수단(REQ-022_v02 4절 「실험」 행, D5·D6·D12).
- **`Lab/` 경로**: `Lab/REQ-022_모델지정` (기록 파일 `Lab/REQ-022_모델지정/실험기록_v01.md`. 아래 T·F 번호는 이 파일 2·3절의 번호다)
- **요지**:
  - **실측 범위의 한계**: 실험 세션(개발 서브에이전트)은 `Agent` 도구가 없고 `claude` 명령이 확인 요청으로 막혀, D12가 허용한 Sonnet 시험 세션을 띄우지 못했다(T2·T3). ①과 ③은 실측하지 못했고 공식 문서로만 확인했다. EC는 아래 ①·③을 실측 결과가 아닌 문서 근거로 인용해야 한다.
  - **① 다른 모델의 서브에이전트(문서 근거)**: 서브에이전트 모델은 ⓐ 호출마다 주는 `model` 인자 ⓑ 정의 파일 `model`(`inherit`는 주 대화 모델) ⓒ `CLAUDE_CODE_SUBAGENT_MODEL` ⓓ 주 대화 모델 순으로 정해진다(F2). 따라서 정의 파일을 `model: inherit`로 두어도 오케스트레이터가 단계마다 호출 인자로 모델을 줄 수 있고, 정의 파일에 모델을 고정하면 분류별로 바꿀 수 없다. `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`가 켜져 있으면 호출 인자와 정의 파일이 무시된다(F4). 이 저장소의 `.claude/settings.json`에는 `model`·`env` 키가 없다(T1).
  - **별칭과 모델 ID(문서 근거)**: `opus`·`sonnet`·`fable` 별칭은 시간이 지나며 최신 권장 버전으로 바뀌고, 버전을 고정하려면 전체 모델 ID를 쓴다(F6·F7). 호출 인자나 정의 파일에 주 대화와 같은 계열의 별칭(예: 주 대화가 Opus일 때 `opus`)을 적으면 별칭이 가리키는 버전이 아니라 주 대화의 정확한 모델로 실행된다(F3). Sonnet 5.5의 전체 모델 ID는 확인하지 못했다.
  - **effort(문서 근거)**: 서브에이전트 정의 파일에 `effort`를 적을 수 있고 세션 effort보다 앞선다(F9). 정의 파일에 `effort`가 없을 때 서브에이전트가 세션 effort를 이어받는지는 문서에 없다.
  - **② `model: inherit`의 상속(일부 실측)**: `model: inherit`인 이 세션에 Claude Code가 넣은 시스템 안내문이 `claude-opus-5-5`를 적었다(T14). REQ 6절의 오케스트레이터 모델과 같다. 오케스트레이터 모델이 Opus가 아닐 때 따라 바뀌는지는 시행하지 못했다.
  - **③ 실행 모델 확인 수단(문서 근거)**: 대화형 세션의 `/tasks`가 실행 중 서브에이전트의 모델과 effort를 보여 준다(F5, v2.1.242 이상). `claude -p`의 `stream-json` `system/init` 이벤트에 모델이 있고, `json` 출력에 모델별 비용 내역이 있다(F10·F11). 세 수단은 세션 밖에서 읽는 값이지만 이 실험에서 시행하지 못했다. 판정서 머리말의 `auditor.model`은 여전히 세션이 적는 자기 보고값이다.
  - **뒤 단계 실측 방법(제안)**: 실험 기록 5절. 대화형 Claude Code에서 오케스트레이터가 `Agent` 호출에 `model` 인자를 주어 시험 서브에이전트를 띄우고 `/tasks`로 모델을 읽는 방법 등이다. 대표님 확인이 필요한 명령이 들어 있다.
- **정규 경로로 복사·이동하지 않았다는 확인**: 실험 파일은 `Lab/REQ-022_모델지정/실험기록_v01.md` 하나이며 정규 경로로 복사·이동하지 않았다. 커밋 전 검사가 이 파일을 `Lab/` 변경으로 분류했다(3절).
