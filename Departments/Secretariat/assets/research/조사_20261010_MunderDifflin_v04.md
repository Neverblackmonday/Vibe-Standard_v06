## 3. 작동 구조에서 주목할 부분

- **메시지 전달**: 하이브(hive)는 일반 파일로 된 로컬 git 저장소입니다. 각 에이전트는 자기 `outbox/`에 파일을 쓰고, 하네스의 라우터가 받는 쪽 `inbox/`로 전달합니다. 에이전트는 하이브의 git을 직접 다루지 않고, 단일 커미터가 하이브 저장소의 커밋을 전담해 `index.lock` 손상을 막습니다(그 커미터가 라우터와 같은지는 확인 불가). 공유 블랙보드와 추가 전용(append-only) 이벤트 로그가 있습니다.
- **사람 승인(「Human gates」)**: 지출, 범위 변경, 파괴적 작업은 승인 큐로 올라갑니다. GOD 에이전트는 일상 요청을 자체 처리하고 치명적인 항목만 사람에게 올립니다. 에이전트별 자율 범위를 따로 설정합니다.
- **서킷 브레이커**: 루프, 오류 폭주, 예산 초과를 감지하면 「steer(방향 수정) → constrain(제한) → stop(정지)」 순서로 개입합니다.
- **비용 관리**: 에이전트별 토큰 예산과, 실행 기록에서 계산한 실제 비용을 원장(ledger)에 남깁니다.
- **기억**: 에이전트별 마크다운 메모리를 공유 검색 저장소(「palace」)로 모읍니다. 저장 경로는 README에 명시되지 않아 확인 불가입니다.
- **브리핑 양식**: 가이드는 Michael에게 「결과 · 맥락 · 제약 · 질문」 네 줄로 지시하라고 안내합니다(가이드 4단계).

### 4.2 충돌·위험 항목

1. **지침 원천 이중화**: 역할 정의, 스킬, 기억이 앱 내부에 따로 쌓입니다. 「단일 원천」 원칙과 정면으로 충돌해, 지침이 `AGENTS.md`와 앱 설정 두 곳에서 따로 바뀔 수 있습니다.
2. **자율 처리 범위**: GOD 에이전트가 일상 요청을 사람 없이 처리하는 구조입니다. 사용자 전역 지침(v29, 2부 9절)의 「파일 삭제·덮어쓰기 전 사용자 승인」, 「Git 커밋 및 푸시는 명시적 요청 시에만 수행」을 지키려면 에이전트별 자율성 설정을 엄격하게 잡아야 하며, 설정만으로 충분히 막히는지는 확인 불가입니다.
3. **Git 동작**: 하이브 저장소 커밋은 하네스가 자동으로 합니다(하이브는 에이전트 간 메시지를 기록하는 저장소이므로 프로젝트 저장소 커밋과는 별개). 프로젝트 저장소에 대한 커밋 여부는 각 에이전트 CLI의 권한 설정에 달려 있습니다. worktree는 README상 선택(Optional) 기능이며, 사용 시 브랜치를 어떻게 만드는지는 확인 불가입니다.
4. **성숙도**: 개발사가 pre-release라고 밝혔고 3주 사이 세 차례 릴리스가 있었습니다. 이전 버전(0.3.8)의 사용량 한도 가드 결함으로 해당 기능이 전면 제거된 이력이 있습니다. README는 macOS 빌드의 서명·공증(signed & notarized)만 언급하고 Windows 빌드는 언급하지 않아, Windows 설치 파일의 코드 서명 여부는 확인 불가입니다. 저장소 이름이 `chaitanyagiri/munder-difflin`에서 `HarnessMD/munder-difflin`으로 바뀐 흔적이 있습니다(README 내부 링크 불일치).
5. **한국어**: UI는 영어·간체 중국어·아랍어만 지원하고, 받아쓰기는 현재 영어만 지원합니다(다른 언어는 이후 릴리스에서 모델 다운로드로 추가 예정). 중국어·일본어 IME에서 Enter로 후보를 고를 때 메시지가 먼저 전송되던 문제가 v0.4.6에서 수정됐습니다. 한국어 입력에도 해당하는지는 확인 불가입니다.
6. **사용량 소모**: 에이전트를 병렬로 돌리면 여러 에이전트가 같은 구독 한도를 나눠 씁니다. 가이드도 밤샘 작업 전 토큰 상한 설정을 권합니다.
7. **텔레메트리**: 공식 빌드는 익명 사용 이벤트를 기본 전송합니다. 프롬프트·코드·파일 경로·에이전트 출력은 미전송이라고 명시합니다. 설정 토글, `DO_NOT_TRACK`, 소스 빌드로 끌 수 있습니다.
8. **데이터 전송**: 프롬프트와 에이전트가 읽은 파일은 선택한 AI 서비스로 전송됩니다. 품질 자동화 시스템처럼 고객사 데이터가 있는 프로젝트는 사전 확인이 필요합니다.

### 4.3 기존 도구와의 관계

사용자 PC 홈 폴더의 최상위 이름 목록에서 `.pixel-agents` 폴더를 확인했습니다(2026-10-10, 연결된 PC의 장치 정보 조회. 폴더 내용은 열람하지 않음). Pixel Agents(`pablodelucca/pixel-agents`, MIT)는 Claude Code 터미널을 픽셀 캐릭터로 **보여주기만** 하는 VS Code 확장이고, 작업 배분 기능은 없습니다. Munder Difflin은 시각화에 더해 **작업 배분과 에이전트 간 통신**까지 하는 상위 범주입니다. 자체 AI 오피스 계획이 「보여주기」인지 「일을 시키기」까지인지에 따라 참고할 대상이 달라집니다.
