브리핑: ORD-013 안전 항목 REQ 승인(REQ-036)

결론

PM이 ORD-013 요구 항목 1~4(PowerShell 커밋·푸시 확인, 줄바꿈 기본 규칙, EC 결정 범위 대조 칸, 판정 서브에이전트의 모델)를 REQ-036_v02.md(Critical)로 작성했습니다. REQ 판정은 최초 판정에서 fail(변경 목록 누락 1건)이었고, 재판정 1차에서 pass(결함 0건, 문체 지적 1건 이월)로 끝났습니다. 비서실은 D1~D6을 모두 권고안대로 승인하시기를 권고합니다.

대표님이 할 일

  • 승인 문구 입력: REQ-036_v02 승인, D1~D6 권고안
  • 대안을 택하시는 항목이 있으면 번호와 대안을 함께 입력하십시오(예: REQ-036_v02 승인, D1은 대안, 나머지 권고안).
  • 별도 입력(이 승인과 따로): v06 REQ-035 흡수 종결 문구 v06 REQ-035(안전 항목) 흡수로 종료. 흡수 안건 REQ-036. 종결 기록 커밋해라

1. 결정 표 비교 (D1~D6)

번호정할 일권고안대안과 영향
D1 PowerShell 도구의 삭제·이동 명령도 실행 전 확인을 받게 할지 넣습니다. PowerShell 도구도 Bash 도구와 같은 범위(삭제·이동·커밋·푸시)에서 확인 화면이 뜹니다. 도구에 따라 확인 범위가 달라지지 않습니다. 커밋·푸시만 넣습니다. PowerShell 도구의 삭제·이동은 지금처럼 확인 없이 실행될 수 있습니다.
D2 workspace 스크립트 안의 커밋 경로를 그대로 둘지 그대로 둡니다. 대표님이 승인한 기존 완화이고, 커밋 전 검사의 범위 대조가 위험을 줄입니다. 이번 REQ는 PowerShell 도구의 빈틈만 메웁니다. 스크립트 안의 커밋도 확인·차단 대상에 넣습니다. 검사 스크립트나 Git 훅을 고쳐야 하면 범위 밖이어서 파이프라인이 멈추고, ORDER·REQ 새 버전으로 범위를 넓혀야 합니다.
D3 기본 줄바꿈의 종류 LF. 저장소에 커밋된 내용이 이미 모두 LF입니다. 기존 예외(*.bat·*.cmd는 CRLF, .githooks/*는 LF)는 유지합니다. CRLF. 지금 이 PC의 작업 파일 대다수와 같지만, 셸 실행 파일과 다른 PC 환경에서 줄바꿈이 달라집니다.
D4 이미 내려받아 둔 작업 파일을 새 규칙에 맞추는 시점 최종 승인 커밋 뒤 대표님이 저장소 루트에서 직접 맞추십니다. 대상은 작업 파일 989개이고 거버넌스 파일이 들어 있어 에이전트는 실행할 수 없습니다. 실행할 명령과 임시 복제본에서 미리 돌려 본 결과는 개발 결과서에 나옵니다. 저장소 내용은 바뀌지 않아 커밋할 것은 생기지 않습니다. 따로 맞추지 않습니다. 파일을 다시 내려받을 때부터 새 규칙이 적용되며, 그 전까지 이 PC의 작업 파일은 CRLF와 LF가 섞입니다.
D5 판정 서브에이전트가 정해진 판정 모델과 다른 모델로 실행되는 것을 미리 막을지, 뒤에 무효로 처리할지 미리 막습니다. 지금의 사후 대조(다르면 무효로 보고 다시 판정)도 그대로 둡니다. 사후 대조는 판정 세션이 스스로 적은 모델 값에 기대므로 그것만으로는 놓칠 수 있습니다. 뒤에 무효로 처리합니다. 미리 막는 장치는 두지 않고, 사후 대조를 자기 보고 밖의 근거로도 확인하게 보강합니다.
D6 Workflow/04 「서브에이전트 정의」 항을 어디까지 고칠지 판정을 맡는 품질 서브에이전트 정의만 고칩니다. 다른 부서 정의는 지금대로 둡니다. 모든 부서 정의에 같은 방식을 적용합니다. 판정 밖 단계의 모델도 표와 맞게 되지만, 요구 항목 4 밖으로 범위가 넓어집니다.

3. 비서실 검토 의견

  • 번호와 내용: 번호 036은 규정(요청 폴더의 가장 큰 번호 + 1)과 ORDER 3절 16항에 맞습니다. D1~D6은 REQ-035_v03에서 그대로 이어졌고, 6절 실행 명령은 현행본 REQ-036_v02.md를 가리킵니다.
  • D5 진행 중 멈춤 가능성: 판정 모델이 분류와 단계마다 다르므로, 정의 파일에 모델 하나를 고정하는 것만으로는 막지 못할 수 있습니다. EC에서 정한 장치가 검사 스크립트나 Git 훅처럼 범위 밖 파일을 고쳐야 하면 그 단계에서 파이프라인이 멈추고, 범위를 넓히는 결정을 한 번 더 여쭙게 됩니다. PM은 쓰이지 않을 경로가 남는 것을 막으려고 범위를 미리 넓히지 않았고, 비서실도 이 판단에 동의합니다.
  • D4: 승인하시면 최종 승인 커밋 뒤 대표님 직접 작업이 한 번 생깁니다.
  • PM 실행 기록: PM이 조회하지 않은 시각을 한 번 적었다가, 고치지 않고 정정 행을 따로 남겼습니다. 공식 진행 상태의 근거가 아니어서 승인에 영향은 없습니다.
  • 문체 지적 1건: 1절 참고 끝 문장 표현입니다. 다음 버전에서 반영되며 승인에 영향은 없습니다.
