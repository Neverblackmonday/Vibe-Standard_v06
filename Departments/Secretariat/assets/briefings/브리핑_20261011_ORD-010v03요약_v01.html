ORD-010 v03 요약

대상: Departments/Secretariat/assets/inbox/ORD-010_v03.md · ORD-010 v03 판정 3회(최초 1회, 재판정 2회, 비서실 판정 서브에이전트), 남은 지적 없음

결론

  • ORD-010은 승인 범위 밖 변경이 커밋 전 검사를 통과하는 경로를 막는 ORDER입니다. 지금 커밋 전 검사는 이미 커밋이 끝난 REQ·HOTFIX도 통과 근거로 씁니다. 그래서 끝난 REQ의 scope 안 파일은 새 승인 없이 고쳐도 검사를 통과합니다. 실제로 그런 커밋이 있었는지는 확인하지 않았고 요구 항목 4에서 확인합니다. 사고가 아닌 예방 개정이며, 분류 제안은 Critical입니다.
  • 원스톱이 진행 중이어도 다른 안건의 REQ를 쓸 수 있게 하는 규칙(요구 항목 5)도 담았습니다. v03에서는 요구 항목 6(PowerShell 커밋·푸시 확인)을 더하고, AI 비서 비교 조사와 대조해 나온 결정 네 가지(D-A~D-D)를 반영했습니다.
  • REQ 작성은 진행 중인 REQ-026의 최종 승인 커밋 뒤에 시작합니다.
  • 요구 항목 1과 3이 반영된 커밋이 끝날 때까지는 커밋 전에 스테이징 목록을 확인합니다. 커밋하는 대표님·비서실이 확인하고, v03부터는 대표님이 요청하신 PM 커밋도 대표님이 확인합니다.

대표님이 할 일

  • v03을 확인하시면 「ORD-010 확인」이라고 말씀해 주십시오. 그 시각을 ceo_checked_at에 적습니다(승인이나 REQ 작성의 착수 조건은 아닙니다).
  • PM에 커밋을 요청하실 때 「커밋 전에 git diff --cached --name-only 결과를 보고하고 확인을 받은 뒤 커밋한다」를 넣어 주십시오.
  • 대화창으로 드린 전달 문구를 AI 비서 비교 담당 세션(코워크·20261011T2138)에 붙여 넣어 주십시오.

1. 커밋 한 건이 지나는 관문

커밋 경로마다 관문이 다릅니다. 커밋 실행 확인(ask)은 명령을 실행할지 묻기만 하고 scope는 대조하지 않습니다. 그래서 판정을 거치지 않는 커밋에서 승인 범위를 기계로 확인하는 관문은 커밋 전 검사 하나뿐입니다.

원스톱 파이프라인의 최종 승인 커밋Workflow/05 1.1절대로 셸을 실행할 수 있는 비서실이 커밋 적용 밖계층 1은 Claude Code에만 적용 끝난 REQ·HOTFIX도 통과계층 4가 대신 대조함 있음그 안건 REQ의 scope로 대조
비서실의 요청 커밋(대표님 요청)·핫픽스 커밋, 대표님 직접 커밋 적용 밖 끝난 REQ·HOTFIX도 통과임시로 커밋하는 대표님·비서실이 스테이징 목록 확인 없음

대표님이 요청한 PM 커밋(PowerShell 도구) 기본 확인뿐ask 규칙이 없어, allow나 저장된 규칙이 더해지면 확인 없이 실행될 수 있음 끝난 REQ·HOTFIX도 통과임시 확인 대상(D-D, v03부터) 없음
workspace 스크립트 안의 커밋대표님 요청 없는 커밋이면 규정 위반. 계층 1을 이대로 둘지는 REQ에서 정함 확인 없음 끝난 REQ·HOTFIX도 통과 없음
초록 장치 있음노랑 조건부빨강 빈틈회색 해당 없음파란 테두리: 반영 뒤 바뀌는 칸

반영 뒤에도 끝나지 않은 다른 REQ·HOTFIX의 scope 안 변경은 통과합니다. --no-verify를 쓰거나 core.hooksPath가 설정되지 않은 PC에서는 커밋 전 검사가 실행되지 않습니다.

예: 커밋이 끝난 REQ-021_v02의 scope에 Workflow/01~07이 있어, 지금은 새 승인 없이 Workflow/를 고쳐도 커밋 전 검사를 통과합니다. 이 한계는 Workflow/06_통제장치_및_배포.md 1절 계층 3 「한계」에 이미 적혀 있습니다.

2. 요구 항목 여섯 가지

1

끝난 REQ·HOTFIX를 통과 근거에서 빼기

커밋 전 검사는 승인된 REQ와 확인된 HOTFIX 가운데 끝나지 않은 것만 통과 근거로 씁니다. 커밋 없이 끝난 안건(다른 안건에 흡수된 것, 대표님이 더 진행하지 않기로 정한 것 등)도 끝난 것으로 봅니다. 판정 fail 뒤 고쳐서 계속하는 안건은 끝난 것이 아닙니다.

종결 처리
2

종결의 기록

어느 안건이 언제, 어느 커밋이나 경로로 끝났는지 찾을 수 있게 합니다. 커밋 경로와 관계없이 기록을 남깁니다.

종결 처리
3

기존 기록의 종결

이미 끝난 REQ·HOTFIX를 끝난 상태로 만듭니다. 파생 안건 REQ-010-1과 커밋 없이 끝난 REQ-011도 포함합니다.

종결 처리
4

지난 기간의 범위 대조

끝난 안건이 통과 근거로 쓰인 기간에 승인 범위 밖 변경이 커밋되었는지 커밋 이력과 대조해 기록합니다.

종결 처리
5

REQ 작성 파이프라인의 겹쳐 실행

원스톱이 진행 중이어도 다른 안건의 REQ를 쓸 수 있습니다. 바꾸는 문서가 겹치면 진행 중인 안건이 끝난 뒤 씁니다.

병렬 운용 · 별도 REQ로 나뉠 수 있음
6

PowerShell 도구의 커밋·푸시 확인

v03 신설

PowerShell 도구로 내리는 git commit·git push도 Bash 도구처럼 실행 전에 확인을 받습니다. Workflow/06의 관련 설명도 맞춥니다.

커밋 실행 확인 · 별도 REQ로 나뉠 수 있음
