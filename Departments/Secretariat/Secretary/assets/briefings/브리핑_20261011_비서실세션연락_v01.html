브리핑: 비서실 세션 간 연락 비포·애프터

결론

  • 세션끼리 연락 파일로 주고받습니다. 1건 = 파일 1개이고 고치지 않습니다. 폴더의 파일 이름 목록이 그대로 상황판이 됩니다.
  • 대표님 손 작업은 복사·붙여넣기에서 「연락 확인」 「진행」 같은 짧은 말로 바뀝니다. 실행 전 내용 확인은 대표님이 그대로 합니다.
  • 위치는 Departments/Secretariat/workspace/연락/입니다. 시범은 진행 중인 세션과 부딪히지 않아 바로 시작할 수 있습니다. 정식 반영은 ORD-006 ⑦(추적성) 커밋 뒤로 잡았습니다.
  • 새 세션은 첫 답에서 「이비서입니다」처럼 스스로 이름을 정해 소개합니다.

대표님이 할 일

  • 아래 6절의 D1(상황판 없앰), D3(위치와 시범 근거), D4(순서), D5(이름 세부 규칙)를 정해 주십시오. D1·D3이 정해지면 시범을 바로 시작합니다.
  • D2(호출 문구·승인 전달)는 정식 반영 때 정하셔도 됩니다. D6은 대기로 기록했습니다.

1. 조사 질문

비서실 코워크 세션 여럿을 동시에 쓸 때, 대표님이 세션 사이에서 내용을 복사해 옮기는 일을 어떻게 없앨 수 있습니까? 현행 규정이 원인이면 그 규정도 고칩니다.

2. 장면별 비포·애프터(예상)

「애프터」는 이 안을 적용했을 때의 예상입니다. 표시가 없는 장면은 시범 때부터 됩니다. 「정식 반영 뒤」 표시가 있는 장면은 규정 개정(D2) 뒤에 됩니다.

장면 1. 코워크가 정리한 커밋을 Antigravity에 맡길 때 (정식 반영 뒤)

지금
  1. 코워크가 호출 문구 전문을 화면에 냄
  2. 대표님이 복사 → Antigravity 창에 붙여넣기
  3. Antigravity가 커밋하고 결과 보고
  4. 대표님이 결과를 복사 → 코워크에 붙여넣기
복사·붙여넣기 2회(긴 문구)
개선 뒤
  1. 코워크에 「박비서한테 커밋 맡겨」 → 요청 파일 생성
  2. Antigravity에 「연락 확인」 → 대표님 원문·호출 문구·승인 기록을 보여 줌
  3. 내용 보고 「진행」 → 커밋 후 회신 파일
  4. 코워크에 「연락 확인」 → 회신 요지
복사 0회, 짧은 말 4번

장면 2. 한 세션의 조사 결과를 다른 세션이 이어받을 때

지금
  1. 조사한 세션의 보고에서 요지나 경로를 복사
  2. 다른 세션에 붙여넣기하고 설명을 덧붙임
복사·붙여넣기 1회 이상
개선 뒤
  1. 조사한 세션에 「김비서한테 넘겨」 → 조사 파일 경로를 담은 요청
  2. 김비서 세션에 「연락 확인」
복사 0회

장면 3. 지금 어느 세션이 무엇을 맡고 있는지 볼 때

지금
  1. 대표님 기억에 기대거나 세션 창을 하나씩 열어 봄
  2. 확실히 하려면 ORDER마다 「담당 세션」 줄을 열어 봄
한눈에 보는 곳 없음
개선 뒤
  1. 아무 세션에 「상황판 보여줘」
  2. 세션이 연락 폴더의 파일 이름 목록으로 작업별 담당을 정리(3절 그림)
파일 이름만 읽어 토큰이 적음

장면 4. 새 세션을 열 때

지금
  1. 세션 이름이 첫 작성 시각(예: 코워크·20261011T1048)
  2. 어느 창이 어느 세션인지 대표님이 구분하기 어려움
개선 뒤
  1. 첫 답이 「이비서입니다」로 시작
  2. 이름은 다시 쓰지 않아 기록이 섞이지 않음(김비서 → 이비서 → … → 임비서 → 김비서2)

장면 5. 두 세션이 같은 작업을 잡으려 할 때

지금
  1. 파일을 고치기 직전에 다시 읽어 바뀐 것을 알아챔(사후 감지)
  2. 공유 파일(원안의 BOARD.md)이면 나중에 쓴 쪽이 앞의 줄을 지울 위험
개선 뒤
  1. 시작할 때 「착수」 파일을 남기고 목록을 다시 봄
  2. 먼저 착수한 세션이 담당. 늦은 쪽은 물러나 담당 세션에 요청
새 파일만 만들므로 덮어쓰기 없음

4. 핵심 발견

위치(D3): assets/가 아니라 workspace/

  • 표준은 assets/를 「실제 자산(코드, 조사 자료 등)」 자리로, workspace/를 「중간 산출물, 메모」 자리로 정합니다(Workflow/02 3절). 연락은 같은 폴더의 PM 실행 기록처럼 일하면서 쌓이는 기록입니다.
  • 재현 시험에서 workspace/연락/ 새 파일만 있으면 커밋 전 검사를 통과했습니다. 배포본 설정(.gitattributes)도 고칠 필요가 없습니다.
  • 지금 규정상 그 폴더는 PM 구역이라, 연락 폴더만 비서실 전용으로 바꿉니다.

순서(D4): 진행 중인 일은 끊지 않음

시범 시작(D1·D3 결정 뒤 바로)· ORD-009(진행 중)→ ORD-006 ⑦ 추적성→ 연락 ORDER 반영→ ORD-006 ⑧ ⑨→ ORD-007→ ORD-008
  • 시범은 새 폴더에 새 파일만 만들기 때문에 다른 세션의 작업과 검사에 영향이 없습니다.
  • 정식 반영은 동시에 돌리지 않습니다. 같은 작업 트리에서 REQ 파이프라인 둘이 함께 돌면 두 파이프라인의 커밋 전 검사가 모두 실패합니다(재현 시험으로 확인).
  • ⑦ 뒤에 두는 이유: ⑦이 「안건 번호 없는 비서실 산출물의 커밋 경로」를 정하므로, 연락의 커밋 방법을 그 결과에 맞춥니다. ORD-006 안의 순서 사이에 끼우는 것이라 ORD-006 담당 세션에 전할 문구를 드립니다.

바꾸는 규정

개정 항목 열한 건(조항 기준 20곳 안팎)입니다. 대부분 문구를 고치거나 한 줄을 더합니다. 검사 스크립트와 권한 설정은 손대지 않습니다. 상세는 조사 자료 4절에 있습니다.

5. 남는 한계

  • 세션은 대표님 메시지를 받아야 움직입니다. 그래서 「연락 확인」 한마디는 없앨 수 없습니다.
  • 서로 다른 작업이 같은 파일을 고치는 문제는 막지 못합니다. ORD-008 I1의 몫입니다(D6 대기).
  • 시범 기간에는 호출 문구와 승인 문구를 지금처럼 대표님이 직접 전달합니다. 장면 1은 정식 반영 뒤에 됩니다.
  • 시범 기간의 연락 파일은 커밋하지 않고 작업 폴더에 둡니다. 지금 규정상 그 폴더의 커밋을 허용하는 근거가 없어서, 정식 반영 때 한꺼번에 커밋합니다.
