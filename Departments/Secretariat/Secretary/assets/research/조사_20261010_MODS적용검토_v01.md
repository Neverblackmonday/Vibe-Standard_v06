## 2. 결론

1. **모드란**: Claude Code 안에서 실행되는 JavaScript/TypeScript 이벤트 처리 함수 묶음이며, 플러그인으로 설치합니다. 도구 호출·프롬프트·턴·화면 그리기 같은 이벤트를 관찰하거나, 바꾸거나, 대신 처리합니다. 2026-10-01 정식 공개되었고 CLI v2.1.287, 데스크톱 앱 Code 탭 v2.1.286부터 기본으로 켜집니다.
2. **적용 범위**: 표준에서 모드가 동작하는 곳은 Claude Code로 실행하는 PM 파이프라인(대표님 터미널 또는 Antigravity가 실행하는 `claude ...` 실행 명령과 그 서브에이전트)입니다. 비서실 서비스 자체(코워크, Antigravity, 채팅)에는 쓸 수 없습니다. 공식 문서의 「Where mods run」 표에 코워크가 없고, Antigravity와 채팅은 Claude Code가 아닙니다.
3. **가장 쓸모 있는 곳은 「관찰 기록」입니다.** 모드가 서브에이전트마다 실제 실행 모델과 토큰 사용량을 저장소 안 파일에 자동으로 남기면, `Workflow/06` 7절 과제 1(판정서 `model`이 자기 보고값이며 세션 기록은 저장소 밖이라 근거로 못 씀)의 공백을 줄이고, 수작업으로 만든 토큰 사용량 집계를 자동화할 수 있습니다. 관찰만 하는 모드는 모델에 보내는 내용을 바꾸지 않으므로 토큰을 더 쓰지 않습니다.
4. **통제 강화에 쓰는 일은 신중히 판단해야 합니다.** 셸 명령으로 거버넌스 파일을 쓰는 경로(`Workflow/06` 1절 계층 1 한계)를 모드로 막을 수 있으나, 사고 이력이 없어 `AGENTS.md` 「불변 원칙」 8항(규칙 비대화 방지)에 걸립니다. 또 모드는 샌드박스 밖에서 대표님 권한으로 실행되고, 내장 보호 모드(`sec-default`)가 로드되지 않는 환경(관리 설정 없음, Team·Enterprise 로그인 아님)에서는 모드가 `deny` 규칙에 걸린 호출도 허용할 수 있습니다(3.5절).
5. **권고**: 바로 표준에 넣지 않고, M1(실행 모델·토큰 자동 기록)과 M2(기본 맥락 크기 진단) 두 모드만 실험실(`Lab/`)에서 시험하고 효과가 확인되면 ORDER로 올리기를 권고합니다. 표준에 넣는 일은 거버넌스 변경이므로 ORDER → REQ → 설계 → 개발 → 품질 정규 절차를 따릅니다.
6. **조사 중 발견한 별도 사항**: `.claude/settings.json`의 `ask`에는 `Bash(git commit*)`·`Bash(git push*)`만 있고 PowerShell 규칙이 없습니다. 표준은 Bash가 거부되면 PowerShell 도구로 대신합니다(`Workflow/06` 2.1절 「명령 도구」). PowerShell 커밋·푸시는 `allow`에 없어 지금도 기본 확인을 받지만, `allow`보다 앞서는 `ask` 규칙이 없으므로 나중에 생긴 `allow` 규칙(「다시 묻지 않기」로 저장된 규칙 포함)에 맞으면 확인 없이 실행될 수 있습니다(4.2절 M4). 모드가 아니라 `ask` 규칙 추가로 막을 수 있는 공백입니다.

## 3. 모드 기능 요약

### 3.1 구성

| 파일 | 역할 |
| :--- | :--- |
| `.claude-plugin/plugin.json` | 플러그인 매니페스트 |
| `hooks/hooks.json` | `"modules": ["./register.js"]`로 코드 파일을 가리킴. 기존 설정 훅(셸 명령형)도 함께 담을 수 있음 |
| `hooks/register.js`(또는 `.ts`) | `register(on)` 함수에서 `on('이벤트', 처리 함수)`로 훅을 등록 |

- 처리 함수는 `($, e, next)`를 받습니다. `next(e)`를 그대로 부르면 관찰, 바꾼 사본을 넘기면 재작성, `next` 없이 결과를 돌려주면 대신 처리입니다.
- 파일·프로세스·네트워크·모델 호출은 모두 `$`(모드 API)를 거쳐야 합니다. 그래서 `claude plugin validate <폴더>`를 실행하면 모드가 받는 이벤트(`hooks:`)와 호출하는 API(`calls:`)가 실행 없이 나열됩니다. 처리 함수가 무엇을 돌려주는지는 나열되지 않습니다.

### 3.5 제약과 보안

- **샌드박스 없음**: 모드는 대표님 계정 권한으로 파일 읽기·쓰기, 프로세스 실행, 네트워크 접근, 환경 변수(키 포함) 읽기를 할 수 있습니다.
- **권한 우회 가능성**: `tool.check`로 허용을 돌려주는 모드는 `ask` 규칙과 관리 설정 밖의 `PreToolUse` 훅을 넘어섭니다. `deny` 규칙은 관리 설정이 있는 PC나 Team·Enterprise 요금제 로그인 환경에서 기본으로 모드보다 우선하며, 그 환경에서도 조직이 관리 설정의 `allowModsToOverrideDenyRules`를 켜면 예외가 됩니다. 그 밖의 환경에 대해 공식 문서에는 「Anywhere else, the mod can approve a call that a deny rule refuses.」라고 적혀 있습니다([Configure permissions](https://code.claude.com/docs/en/permissions) 「Extend permissions with hooks」). 그래서 표준이 쓰는 모드는 `tool.check`를 쓰지 않습니다.
- **모드 자신의 호출**: `deny` 규칙과 관리 설정 훅은 Claude의 도구 호출에만 적용되고 모드의 `$.fs`·`$.process` 호출에는 적용되지 않습니다(admin 문서 「Know what happens by default」). 따라서 모드는 `deny` 경로에도 쓸 수 있습니다.
- **시간 제한**: 훅 하나의 자체 실행 시간 10초. 넘기면 건너뛰므로 차단용 훅은 `.catch`로 실패 시 거부(fail closed)를 직접 넣어야 합니다.
- **끄는 방법**: `/plugin`에서 개별 비활성화, `claude --safe-mode`(그 세션만), `~/.claude/settings.json`의 `"disableAllHooks": true`(설정 훅과 상태 줄도 함께 꺼짐).

### 4.3 표준에 넣을 때 바뀌는 곳(M1을 채택하는 경우)

정규 절차(ORDER → REQ → 설계 → 개발 → 품질)를 거치며, 아래는 설계가 확인할 대상 목록입니다. 확정안이 아닙니다.

1. **모드 폴더 위치**: 예) `.claude/mods/run-recorder/`. `.claude/` 아래면 `AGENTS.md` 「불변 원칙」 3항 거버넌스 목록과 `settings.json` `deny`에 이미 포함됩니다. 다른 위치면 두 곳에 더할지 결정이 필요합니다.
2. **로드 방법**: `Workflow/05` 3절 실행 명령에 `--plugin-dir <모드 폴더>`를 더하는 방법이 가장 단순합니다. 이 플래그는 그 세션 하나에만 적용됩니다. 자식 `claude -p` 세션까지 붙이려면 `CLAUDE_CODE_PLUGIN_DIRS` 환경 변수(절대 경로만 받으며 Windows는 `;`로 구분)를 검토하며, 전달 여부와 `--plugin-dir`과 함께 쓸 때 중복 로드 여부는 실측이 필요합니다. 저장소 설정으로 자동 활성화하는 방법도 실측이 필요합니다(6절).
3. **기록 파일과 쓰기 방식**: PM 실행 기록(`Workflow/05` 7절)은 PM이 쓰는 문서이므로 모드가 직접 고치지 않고 별도 기계 기록을 둡니다. 설계가 정할 것은 아래와 같습니다.
   - ① **위치와 변조 방지**: 기록이 판정 근거가 되려면 PM·서브에이전트가 고치기 어려워야 합니다. `deny`는 모드 쓰기에 적용되지 않으므로(3.5절), 기록 경로를 `deny`에 넣으면 Edit·Write 수정은 막고 모드 기록은 남길 수 있습니다. 다만 셸 명령과 `allow`의 `Bash(python Departments/*/workspace/*)`로 실행되는 스크립트의 쓰기는 막지 못하므로(`Workflow/06` 1절 계층 1 한계), 계층 3·4에서 확인해야 합니다. 또 `deny` 목록은 `AGENTS.md` 「불변 원칙」 3항 목록과 일치해야 하므로(`Workflow/06` 2절), 기록 경로를 `deny`에 넣으면 3항에도 넣어 거버넌스 파일로 둘지 함께 정해야 합니다.
   - ② **쓰기 방식**: `$.fs.write`는 덧붙이기가 없고 원자적이지 않아, 서브에이전트가 동시에 끝나면 일부만 쓰인 파일이 생길 수 있습니다. 세션별 파일, `$.store`에 모았다가 한 번에 쓰기 등에서 고릅니다.
   - ③ **커밋 시점**.
   - ④ **F2(라우팅 시트)와의 관계**: F2는 대표님이 ORD-007에 넣으라고 했고, 다음 ORDER로 옮기는 안을 비서실이 권고해 확인 대기 중입니다(`ORD-007_v02` 1절 경위).
4. **통제 계층 표**: `Workflow/06` 1절에 모드를 새 계층 또는 보조 수단으로 적고, 한계(`--safe-mode`·`disableAllHooks`로 꺼짐, 10초 제한)를 적습니다.
5. **보안 점검 항목**: `Workflow/06` 1.1절에 「모드 폴더의 `claude plugin validate` 결과에서 `hooks:`에 `tool.check`가 없고, `calls:`에 `$.http.fetch`·`$.env.get`이 없는지」를 더합니다.
6. **구매자 안내**: Claude Code 최소 버전과, 모드를 끄면 기록만 빠지고 파이프라인은 그대로 동작한다는 점을 배포본 안내에 적습니다. 모드는 별도 API 키가 필요 없으므로, TypeSafe Jev를 기각한 사유(구매자마다 외부 API 계정·결제·키 설정 필요, `조사_20261008_Jev도입검토_v01.md` 3.3절 1항)에는 해당하지 않습니다.

### 4.4 시험 방법(실험실, 비서실 승인 사항)

1. `Lab/<실험 폴더>/run-recorder/`에 M1·M2 모드를 만듭니다. 작성은 PM 세션의 내장 `plugin-authoring` 스킬로 할 수 있습니다.
2. `claude plugin validate`로 `hooks:`·`calls:`를 확인합니다. `hooks:`에 `tool.check`가 없고, `calls:`에 4.3절 3항 ②에서 고른 쓰기 호출(`$.fs.write` 또는 `$.store.set`) 외의 쓰기·네트워크 호출이 없어야 합니다.
3. 대표님 터미널에서 `CLAUDE_CODE_PLUGIN_DIRS`에 모드 폴더의 절대 경로(예: `D:\Vibe Coding\Vibe Standard_v04\Lab\<실험 폴더>\run-recorder`)를 설정하고, `--plugin-dir` 없이 Minor 안건 하나를 실행합니다. 로드 방법을 변수 하나로 두어 중복 로드를 피하고, PM 세션과 자식 `claude -p` 세션 모두에 로드되는지 확인합니다.
4. 기록의 모델·토큰 합계를 세션 기록의 `cost-state`와 대조합니다. `cost-state`는 Claude Code가 저장소 밖 `~/.claude/projects/` 아래 세션 파일 끝에 남기는 세션 합계(서브에이전트 사용량 포함)입니다(`조사_20261010_토큰사용량집계_v02` 1절 「방법」).
5. 결과를 근거로 ORDER 발행 여부를 대표님이 결정합니다.

## 6. 확인하지 못한 항목

- 대표님 PC의 Claude Code 버전(모드는 v2.1.287 이상 필요): 확인 불가. 터미널에서 `claude --version`으로 확인할 수 있습니다.
- 코워크에서 모드 지원 여부: 공식 문서 표에 없음. 지원 근거를 찾지 못했습니다.
- Antigravity가 기동한 PM 세션에서 모드 화면 표시 여부: 확인 불가.
- `tool.call`에서 서브에이전트 호출을 구분하는 필드: 확인 불가.
- effort: `turn.step`은 `next({ ...e, effort })`로 바꿀 수 있다고 문서에 적혀 있으나, 이벤트에서 effort 값을 읽을 수 있는지는 타입 선언 파일 확인이 필요합니다. `agent.spawn`에는 effort 관련 항목이 없습니다.
- `CLAUDE_CODE_PLUGIN_DIRS`가 PM·서브에이전트가 띄운 자식 `claude -p` 세션에 전달되는지, `--plugin-dir`과 함께 쓸 때 같은 모드가 두 번 로드되는지: 미실측.
- 저장소 `.claude/settings.json`의 `enabledPlugins`·`extraKnownMarketplaces`로 저장소 안 모드를 자동 활성화할 수 있는지: 「Manage mods for your organization」의 관리 설정 예시만 확인했습니다.
- Windows에서 `--plugin-dir`에 상대 경로를 줄 때의 동작: 미실측.
