## 3. 검토 내용

### 3.1 Jev 개요

- Jev는 TypeSafe AI가 2026년 9월에 출시한 「System One」 모델입니다. 텍스트를 생성하지 않습니다. `state`와 타입이 정해진 질문을 받아, 확률이 붙은 답을 반환합니다.
- 질문 타입은 Choice(선택지 중 하나), Noul(예/아니오 확률), Score(단계형 루브릭 위의 위치)입니다.
- 가격은 `typesafe:jev-1.13.0` 기준 입력 100만 토큰당 $0.042이고, 출력 토큰은 무료입니다. 요청 한도는 64k 토큰이며, 그중 `state`와 가장 긴 질문을 합친 한도가 32k 토큰입니다.
- promptfoo 문서의 「Limitations」 절에는 다음 한계가 적혀 있습니다.
  - Jev 1.13은 산술, 개수 세기, 날짜 비교에 약합니다.
  - Score 값은 단계 사이를 보간하기에 충분히 보정되어 있지 않습니다.
- promptfoo는 레드팀 같은 적대적 출력에 Jev를 단독 채점기로 쓰지 말라고 권고합니다.
- 성능 수치는 회사와 고객사가 발표한 값입니다. TypeSafe는 종단 간 지연을 70~500ms로 밝혔습니다(Let's Data Science). Vercel은 p95 기준 최대 18배 빠르다고 했고, Deel은 비용 최대 59분의 1, 응답 최대 4배 빠르다고 했습니다(Dealroom). 독립 벤치마크는 확인 불가입니다.
- 이용 조건은 출처마다 다르게 적혀 있습니다. Dealroom(2026-09-28)은 대기 명단이 있는 얼리 액세스라고 했습니다. 반면 OpenRouter 문서는 대기 명단이나 TypeSafe 계정 없이 OpenRouter API 키로 쓸 수 있다고 했습니다. 어느 경우든 외부 API 키가 필요합니다.

### 3.2 검토한 적용 위치

판정서는 Claude Code의 독립된 품질 서브에이전트가 Claude Opus 5.5로 작성합니다(`AGENTS.md` 「불변 원칙」 4항, `Workflow/04_모델_운용` 「모델」). Jev는 판정서를 작성할 수 없습니다. 그래서 REQ 판정·최종 판정·핫픽스 사전 승인 직전에 자동 검사 단계를 새로 두고, 그 단계에서 Jev를 쓰는 방안을 검토했습니다.

| 위치 | 질문 타입 | 기대 효과 |
| :--- | :--- | :--- |
| REQ 판정 직전 | Noul(문장별 중의성, 체크리스트 항목별 요청 원문 대응) | REQ 판정 기준 ②·⑥에 해당하는 결함을 미리 걸러 재판정 횟수를 줄입니다 |
| REQ 판정 직전(기준 ④ 분류), 핫픽스 사전 승인 직전 | Choice(Critical·Major·Minor), Noul(새 기능 포함 여부) | 분류를 교차 확인합니다. 수정 파일 개수 조건은 `check_standard.py`가 HOTFIX `scope` 항목 수(1~3개)로 검사합니다 |
| 최종 판정 직전(최종 판정 기준 6, 사본 대조) | Noul(「용어」 표의 쓰지 않는 말을 괄호 안 맥락대로 썼는지) | `grep`으로 잡을 수 없는 맥락 판단을 처리합니다 |
| REQ 판정·최종 판정 직전(REQ, 부서 결과서) | Noul(번역투, 의인화, 불명확한 지시어) | 문체 지적을 해당 판정 전에 처리합니다 |

### 3.3 도입 조건과 장애

1. **API 연결**: Jev를 쓰려면 사용자마다 OpenRouter 또는 TypeSafe 계정을 만들고, 결제 수단과 API 키를 등록해야 합니다. 표준 구매자 전원에게 이 절차가 생깁니다. 이 항목이 기각의 직접 사유입니다.
2. **네트워크**: 2026-10-08 15:07(KST)에 코워크 클라우드 세션에서 `curl`로 `https://openrouter.ai/api/v1/models`와 `https://api.typesafe.ai/`를 호출했습니다. 모두 `CONNECT tunnel failed, response 403`을 반환했습니다. 세션의 프록시 안내 문서(`/root/.ccr/README.md`)는 403을 이 세션에 대해 조직의 외부 연결 정책이 허용하지 않은 주소로 설명합니다(원문 「The destination host is not allowed by your organization's egress policy for this session」). 클라우드 세션에서 쓰려면 조직 관리자에게 두 도메인의 허용을 요청해야 합니다.
3. **데이터 외부 전송**: REQ와 RES 본문이 제3자 서버로 전송됩니다. 공개 자료에는 일반 계정의 데이터 보존 기간이 나와 있지 않습니다. 사용자 전역 지침 「보안 및 불변 데이터 보호」에 따라, 이 전송은 사용자 승인 사항입니다.
4. **거버넌스 개정**: 정식 도입하려면 거버넌스 구역의 `check_standard.py`, `Workflow/03_라이프사이클`, `Workflow/04_모델_운용`을 고쳐야 하므로 Critical REQ가 필요합니다.
5. **버전 변동**: 모델 버전이나 가격이 바뀌면 배포본도 함께 고쳐야 합니다.

### 3.4 실측 계획(미실행)

2026-10-08 코워크 대화에서 대표님께 섀도 테스트를 제안했습니다. 파이프라인을 바꾸지 않은 채, 파일 목록 기준 판정서 43건(`Departments/Quality/results/`)에 기록된 결함을 정답으로 두고 Jev의 적중률을 재는 시험입니다. 3.3절 1항과 2항 때문에 실행하지 않았습니다. 따라서 품질 효과는 확인 불가입니다.
