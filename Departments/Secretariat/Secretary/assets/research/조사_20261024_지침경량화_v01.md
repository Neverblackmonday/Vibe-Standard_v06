   - 매뉴얼 7개와 `AGENTS.md`(302,778자) 가운데 개정 이력이 67,955자(22.4%)입니다. 다만 `Workflow/04`의 개정 이력은 판정의 모델 대조 기준으로 지금 쓰입니다(2.1섹션).
2. **`AGENTS.md`의 약 절반(4,761자)이 개정 이력이며, 여러 세션이 시작할 때 이 글을 읽습니다.**

3. **이 문제는 이미 지적되었는데, 처리 시점이 업무 순서의 뒤쪽에 정해져 있었습니다.** 조직진단_v02가 `AGENTS.md` 개정 이력 로드를 원인으로 지적했고, ORD-012_v13 요구 항목 21 둘째 REQ ⑤에 들어갔습니다. 그러나 둘째 REQ는 조직 골격 REQ와 첫째 REQ 뒤이고, 매뉴얼의 개정 이력과 ORDER의 경위 기록은 대상이 아니었습니다.

### 3.4 규정과의 관계

- 사용자 전역 지침 「보안 및 불변 데이터 보호」의 「사람이 확정했거나 마감 날짜가 지정된 기록은 수정하지 않고 새 기록을 추가(Append)한다」: 개정 이력과 ORDER 경위를 글자 그대로 다른 파일로 옮기면 기록의 내용은 바뀌지 않지만, 승인된 매뉴얼과 ORDER에서 그 부분을 지우게 됩니다. 이것을 허용되는 보관 위치 변경으로 볼지는 대표님 해석이 필요합니다.
- 「지침 문서 수정 전 사용자 승인」: 원문의 대상은 「위 계층의 지침 문서와 저장소의 서비스별 지침 파일(`CLAUDE.md`, `GEMINI.md`, `.agents/rules/` 등)」이며 「수정안을 제시하고 승인을 받은 뒤 수정한다」입니다. `AGENTS.md`(저장소 지침, 계층 ③)는 대상이고, `Workflow/` 매뉴얼을 대상으로 보는 것은 비서실 해석입니다. Critical·Major REQ에는 문구안을 적지 않으므로(`Workflow/03` 3절 1항), 수정안 승인은 적용본을 담은 최종 판정서의 승인으로 받습니다.
- 「버전 관리」(내용이 바뀌면 버전 번호를 올려 새 파일로 저장): 덧붙이기만 하는 경위 기록·개정 이력 파일은 버전 번호를 붙이지 않는 예외가 필요합니다. `Workflow/05` 8.6절 8항(새로 만들기만 하고 고치거나 지우지 않으며 버전을 붙이지 않음)과는 덧붙이기를 허용한다는 점이 다릅니다.
- `AGENTS.md` 2절 8항 「REQ 하나에는 목적 하나」: L1과 L4는 목적이 하나(읽는 글 줄이기)이지만, 고칠 곳이 매뉴얼·서식·검사 장치에 걸칩니다. REQ를 둘로 나눌지는 PM이 REQ 분할 기준으로 정하게 합니다.

## 4. 진행 방식

- **ORDER**: 새 ORDER(가칭 ORD-013 「지침 경량화」)로 발행합니다. ORD-012의 요구 항목으로 넣으면 ORD-012 v14를 먼저 써야 하기 때문입니다. 번호는 저장 직전에 inbox를 다시 조회해 정합니다(`Workflow/07` 「번호와 버전」).
- **겹침과 순서**: ORD-013은 ORD-012의 조직 골격 요구 항목(v14에서 신설 예정)과 요구 항목 21이 고칠 파일을 먼저 고칩니다. 발행 전 작업 큐 겹침 확인(`Workflow/05` 8.7절 4항)에서 요구 항목 21과의 겹침(3.3섹션)을 적습니다. 조직 골격 요구 항목은 아직 ORDER에 없으므로, v14 뒤 작업 큐 새 버전에서 다시 확인합니다. 순서는 작업 큐에만 적습니다(ORDER 5섹션에는 적지 않음. 8.7절 2항).
- **원스톱 실행 방식**: ORD-012_v13 3절 50항(원스톱마다 실행 방식·실행 주체·결과 기록 방법을 대표님이 정함)은 ORD-012의 원스톱에만 적용됩니다. ORD-013에도 같은 방식을 쓸지 ORDER 3섹션에 적습니다.
- **조직 골격 REQ에 미치는 영향**: 경량화 REQ가 먼저이면 조직 골격 REQ는 새 이력 파일과 ORDER 경위 파일도 옮길 대상에 넣습니다. 매뉴얼은 개정 이력이 빠져 조직 골격 REQ에서 고칠 글자가 줄어듭니다.
