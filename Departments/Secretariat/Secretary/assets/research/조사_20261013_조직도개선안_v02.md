## 2. 결론

1. **6부(실 포함), 15팀, 29파트(활성 20, 대기 9)로 둡니다.** 모든 파트는 팀에 속합니다. 예외는 실행할 때마다 소속 부가 정해지는 X01 「실험」 하나입니다(결정 ③ 확정).
2. **비서실에 형상통제팀을 신설합니다.** 지침을 잘게 나눠 관리하므로, 나뉜 지침이 원천과 맞는지 대조하고 다시 합쳐 생성하며, 기준선을 확정하는 팀이 필요합니다. 파트는 C01 지침 통합, C02 저장소 반영, C03 형상 현황판입니다(4·6절).
3. **구조 변경 세 건(두 건 + 형상통제팀 신설)은 별도 ORDER로 진행합니다(결정 ④ 대안).** 그 ORDER를 마이그레이션 ORDER로 합칠 것을 권고합니다(결정 ⑧). 핫픽스는 개발부 핫픽스팀(V03)으로, 커밋·푸시는 형상통제팀(C02)으로 옮깁니다. 참고안은 PM팀을 제안했으나, 커밋과 기준선 확정은 형상 관리이므로 형상통제팀이 맞습니다.
4. **부 지침에는 권한 한계와 폴더·산출물 위치만 둡니다(약 300~500자).** 같은 팀 파트가 함께 쓰는 규정은 팀 지침에, 그 파트만 쓰는 규정은 파트 카드에 둡니다(5절).
5. **이름과 코드**: 부는 「○○부」, 실은 대표실과 비서실에만 씁니다. 파트는 명사구 하나입니다. 코드는 부 머리글자 + 두 자리 번호이고(결정 ② 확정), 비서실만 팀 머리글자(S, P, C)를 씁니다. 마케팅과 콘텐츠는 마케팅부로 합칩니다(결정 ① 확정).
6. **대시보드에서 대표님이 슬라이스 지침을 나무로 보고, 파트별 모델을 정합니다(12절).** 기본값은 절차(`Workflow/04` 원장)에 두고, 대표님 설정은 대표님 구역(`CEO/`)의 설정 파일에 저장합니다. 새로고침 버튼 하나로 설정 파일을 비우고 저장해 기본값으로 되돌립니다. 기본값을 바꾸는 것은 REQ 절차입니다.
7. **마이그레이션은 ORDER를 발행해 v05 저장소에서 진행할 것을 권고합니다(13절).** 대표님이 폴더를 복사하실 필요는 없고, 승인과 설정만 하시면 됩니다. v04는 그동안 그대로 운영하며, 같은 종류의 안건을 v04와 v05에서 돌려 비교한 뒤 전환합니다.
8. **폴더 이름은 바꾸지 않습니다.** 부서 폴더 이름은 영문이라 한글 부 이름을 바꿔도 경로가 바뀌지 않습니다.

## 5. 팀 지침과 분량

부 직속을 없애도 파트가 하나뿐인 팀은 그 자체로 지침을 줄이지 않습니다. 효과는 부 지침을 얇게 묶어 두고, 공유 규정을 필요한 팀에만 싣는 데서 나옵니다.

- **배치 규칙**: 규정 문장의 원천은 매뉴얼 절 한 곳입니다. 한 팀의 파트들만 쓰는 규정은 그 팀 지침에, 여러 팀이 쓰는 규정은 해당하는 팀 지침마다 생성으로 싣고, 한 파트만 쓰는 규정은 그 파트 카드에 싣습니다(개선안 v02 7.4절의 생성 방식).

- **이름의 원천**: 부·팀·파트의 이름과 코드는 `Workflow/02`의 조직 표 한 곳을 원천으로 둡니다. 개선안 v02 13.3절의 `process_map.yaml`은 코드만 갖고, 이름은 생성할 때 이 표에서 읽습니다. 대시보드와 Vibe Office도 이 표를 따릅니다(개선안 v02 13.3절 수정 사항).
- **바꾸는 시점**: 아래 「바꾸는 곳」은 모두 마이그레이션 ORDER의 조직 개정 REQ(13.3절 3단계) 하나에서 한꺼번에 바꿉니다(결정 ⑧ 권고안 기준). 결정 ⑧에서 구조 변경을 따로 ORDER로 하면, 이름 변경도 그 ORDER의 REQ 하나에서 함께 바꿉니다. 그 전에는 규정 문서에 옛 이름과 새 이름을 섞어 쓰지 않습니다.
- **바꾸는 곳**:
  - `AGENTS.md` 1절 조직 표의 부 이름
  - `Workflow/02` 1.1절·2절(부서별 책임)의 부 이름, 새 조직 표, 구·신 대응표(대응은 이 표 한 곳에만 둠)
  - 매뉴얼 본문에서 조직을 가리키는 부 이름. 참고로 「품질」이라는 글자는 `Workflow/01` 14곳, `Workflow/03` 48곳, `Workflow/06` 13곳, `Workflow/07` 5곳 나오지만, 「품질 판정」처럼 조직이 아닌 뜻도 섞여 있어 조직을 가리키는 곳만 바꿉니다.
  - `Workflow/01` 「용어」: 옛 이름을 읽을 때 `Workflow/02`의 구·신 대응표를 보라는 참조만 둡니다.
  - 개선안 v02의 코드가 나오는 곳: 5.2·5.3·5.4절, 6.2절 원장, 7.3·7.4절, 8.1·8.2절, 9.2절(K4·K5), 11절(정의 파일 목록), 13.3절, 카드 파일 이름(예: `v1-impl.md`). 코드는 이 문서의 코드로 바꿔 읽습니다. 담당이 바뀐 곳은 따로 고칩니다: v02 S2의 대시보드 생성·주간 지표 집계(v02 11·13.1절) → C03, v02 S4(8.1·8.2절 「반영·커밋」) → S03·C02, v02 S3 → V03.
- **바꾸지 않는 곳**:
  - 부서 폴더(`Departments/Secretariat`, `Design`, `Development`, `Quality`, `Operations`, `Marketing`)
  - 사람이 확정한 기존 기록(승인된 REQ, EC, 판정서 등). 옛 이름은 `Workflow/02`의 구·신 대응표로 읽습니다.
- **서브에이전트 이름**: 파트별 정의(예: `q02-ec-judge`)는 13.3절 5단계에 생성하고, 현행 부서 정의(`quality`, `engineering` 등)는 8단계에 삭제합니다. 7단계 병행 검증 동안은 두 이름이 함께 있습니다.

## 12. 대시보드: 지침 나무와 모델 설정

개선안 v02 13절의 대시보드에 대표님 요건을 더합니다. 대시보드는 형상통제팀(C03)이 생성하는 단일 HTML 파일입니다.

### 12.1 지침 나무

| 항목 | 내용 |
| :--- | :--- |
| 모양 | 왼쪽에 나무: 전역 공통 → 표준 공통 → 부 → 팀 → 파트. 마이그레이션 대시보드의 계층 트리 뷰어와 같은 방식 |
| 노드를 누르면 | 그 노드가 실리는 계층별 지침의 실제 문장(전역·표준·부·팀·카드), 계층별 글자 수 막대와 합계, 원천 절 ID, 원천 해시 일치 여부(C01 검사 결과), 그 파트가 맡는 공정 지도 노드 |

### 12.2 모델 설정

| 항목 | 내용 |
| :--- | :--- |
| 화면 | 파트 × 역할(작성·판정·기록) × 안건 분류(Critical·Major·Minor) 칸마다 모델 등급(최고급·고급·중급)이나 모델을 고르는 표. 칸마다 기본값과 현재 값을 함께 표시 |
| 기본값 | 절차의 원천인 `Workflow/04` 1.2절 원장. 대시보드는 읽기만 함. 기본값을 바꾸려면 REQ로 원장을 개정 |
| 대표님 설정 저장 | 「저장」 버튼이 대표님 구역의 설정 파일(안: `CEO/settings/model_override.json`)에 바뀐 칸만 씀. `CEO/`는 AI가 읽기만 하는 구역이라 AI가 대표님 설정을 고칠 수 없음 |
| 새로고침 | 「기본값으로」 버튼 하나로 확인 창을 거쳐 설정 파일을 비우고 저장함(칸별 되돌리기도 둠). 다음 실행부터 기본값으로 돌아감 |
| 경고 | 판정 파트나 Critical을 고급 아래로 내리면 저장 전에 확인 창을 띄움. 막을지는 결정 ⑦ |
| 설정할 수 없는 칸 | 코워크에서 실행하는 비서팀(S01~S03)은 앱에서 모델을 고르므로 「앱에서 선택」으로 표시 |
| 적용 | Claude Code 세션을 기동하는 실행 명령마다 시작할 때 설정 파일을 읽어 기본값 위에 덮어 쓰고, 그 실행이 끝날 때까지 그 값을 씀(지금 모델 ID 갱신과 같은 방식). PM 실행 명령은 P01·P02와 PM이 기동하는 서브에이전트, 핫픽스 실행 명령은 V03, 형상통제 실행 명령은 C01~C03에 적용 |
| 기록 | 판정이 있는 실행: 실행을 시작한 세션이 그때의 설정 내용을 판정 지시문에 그대로 붙이고, 판정서는 그 값을 「기준 모델」로 적음(실행 기록은 근거로 쓰지 않으므로 판정서가 근거 기록). 판정이 없는 실행: 핫픽스(V03)는 HOTFIX 머리말에, 형상통제팀(C01~C03)은 커밋 근거 줄에 그때의 설정 값을 적음 |
| 대조 | 판정서 모델 대조와 최종 판정 기준 10은 판정서에 적힌 「기본값 + 그 실행 시작 때의 대표님 설정」을 기준으로 함 |
| 현황 | C03이 유효 모델 표(기본값과 설정을 합친 값)를 대시보드에 표시 |

- **저장 방식의 한계**: 로컬 HTML 파일이 디스크에 직접 쓰려면 브라우저의 파일 시스템 접근 기능이 필요합니다. 동작하지 않으면 「내려받기」로 설정 파일을 받아 대표님이 지정 위치에 두는 방식으로 대신합니다(11절).
