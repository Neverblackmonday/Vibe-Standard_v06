# 비서실 세션 간 연락 개선안 검토

- v02 변경: v01(`Departments/Secretariat/assets/research/조사_20261011_비서실세션연락검토_v01.md`)은 원안이 현행 규정에 맞는지를 기준으로 판정했다. 대표님 지시 「야. 지금 개선안 내라니까, 왜 자꾸 기존 절차에 맞니 안맞니 헛소리 삐삐하고 있냐? 기존 절차가 안좋으면 그것도 개선대상에 포함시키는거지. 다시 검토해.」(2026-10-11 오후, 코워크 대화)에 따라 현행 규정도 바꿀 대상으로 놓고 다시 설계했다.
- 실물 확인 결과(파일, 명령, 시각, 결과 원문)의 원천은 v01 3절이다. 이 문서에는 설계에 쓰는 사실만 옮긴다.

## 1. 결론

1. **연락·담당 표시·상황판을 「연락 파일」 하나로 합친다.** 연락 1건 = 파일 1개이며, 새로 만들기만 하고 고치지 않는다. 파일명에 시각·작업 번호·종류·발신·수신을 넣는다. 폴더의 파일 이름 목록이 상황판이 되고, 「착수」를 남긴 세션이 그 작업의 담당이 된다. 여러 세션이 고쳐 쓰는 공유 파일(`BOARD.md`)이 없으므로 덮어쓰기가 생기지 않는다.
2. **복사를 요구하는 현행 규정을 고친다.** 지금은 셸이 없는 코워크가 받은 호출 문구와 승인 문구를 대표님이 Antigravity에 직접 옮겨야 한다(`Workflow/05` 8.2절 3·4항, 1.1절 2번, `Workflow/07` 3.1절 3항). 개선 뒤에는 보내는 세션이 대표님 원문을 담은 「요청」 연락을 남긴다. 받는 세션은 대표님이 「연락 확인」이라고 하면 요청 내용을 화면에 보이고, 대표님이 「진행」이라고 하면 실행한다. 대표님은 실행 전에 내용을 보고 정하므로 사람의 확인은 그대로 남고, 복사·붙여넣기는 두 마디로 바뀐다.
3. **바꾸는 규정은 비서실 세션 운용에 한정한다.** 같은 파일 동시 수정 방지(ORD-008 I1)와 같은 주제 중복 방지(`Workflow/05` 8.4절 4항)는 건드리지 않는다. 연락 파일은 작업 단위의 담당만 표시하고, 서로 다른 작업이 같은 파일을 고치는 문제는 I1이 다룬다.

## 5. 연락 규칙(권고안)

### 5.1 위치와 이름

- 위치: `Departments/Secretariat/assets/연락/`
- 파일명: `<YYYYMMDDTHHMMSS>_<작업 번호>_<종류>_<발신>_<수신>.md`
  - 시각은 한국 시간(+09:00)이다. 코워크 작업 공간의 시계는 UTC일 수 있으므로 변환해서 적는다.
  - 예: `20261011T143005_ORD-009_착수_코워크·비서2_전체.md`, `20261011T150210_REQ-024_요청_코워크·비서1_Antigravity·실행.md`
  - 작업 번호: ORD·REQ·HOTFIX 번호. 조사 자료는 그 파일명의 주제(`조사-<주제>`), 없으면 `없음`
  - 종류: `착수`, `인계`, `완료`, `요청`, `회신` 다섯 가지
  - 발신·수신: 세션 식별자(`<서비스>·<세션 이름>`). 수신이 모두면 `전체`
  - 저장 직전에 같은 이름이 있으면 확장자 앞에 `-2`부터 붙인다

### 5.2 종류별 쓰임

| 종류 | 쓰는 때 | 본문 |
| :--- | :--- | :--- |
| 착수 | 담당이 없는 작업을 시작할 때 | 한 줄 요지 |
| 인계 | 대표님이 담당을 넘기라고 했을 때. 넘겨받는 세션이 남긴다 | 대표님 지시 원문 |
| 완료 | 담당을 놓을 때. ORDER는 그 ORDER의 REQ가 모두 커밋된 뒤, 그 밖의 작업은 산출물을 보고한 뒤. 착수가 다른 세션과 겹쳐 물러날 때도 쓴다 | 산출물 경로 또는 물러난 사유 |
| 요청 | 다른 세션에 일을 맡기거나 정보를 달라고 할 때 | 요청 내용. 호출 문구를 맡기면 대표님 지시 원문과 호출 문구 전문. 승인이 걸리면 승인 기록 경로 |
| 회신 | 요청을 처리했거나 되돌릴 때 | 첫 줄 `회신 대상: <원 파일명>`, 결과 요지와 산출물 경로 |

- **담당 판단**: 그 작업 번호의 연락 파일을 이름 순(시각 순)으로 하나씩 읽으며 담당을 정한다. 처음에는 담당이 없다.
  - 「착수」: 담당이 없을 때만 발신이 담당이 된다. 담당이 있으면 무시한다.
  - 「인계」: 발신이 담당이 된다.
  - 「완료」: 발신이 그때의 담당일 때만 담당이 없어진다. 담당이 아닌 세션의 「완료」는 무시한다.
  - 마지막 파일까지 읽은 뒤의 담당이 현재 담당이다.
- **착수가 겹칠 때**: 착수를 남긴 뒤 위 규칙으로 다시 판단한다. 자기가 담당이 아니면 「완료」(본문에 사유: 착수 겹침)를 남기고 담당 세션에 「요청」을 보낸다. 이 「완료」는 담당이 아닌 세션의 완료이므로 담당 판단에 영향이 없다. 같은 초면 파일 이름 순서가 앞선 쪽이 먼저 읽히므로 담당이 된다.
- **연락 폴더가 생기기 전의 ORDER**: 그 ORDER의 연락이 하나도 없으면 ORDER 「담당 세션」 줄의 마지막 세션이 담당이다. 다른 세션이 맡으려면 「인계」를 쓴다.
- **시범 기간의 담당 변경**: 개정 4가 반영되기 전에는 「인계」 연락과 함께 현행 규정(`Workflow/05` 8.4절 3항 ②)대로 ORDER 「담당 세션」 줄에도 덧붙인다. 개정 4 뒤에는 「인계」만 쓴다.
- 처리 여부는 회신 파일이 있는지로 본다. 읽음 표시는 두지 않는다.
- 조사 요지나 결과를 본문에 다시 적지 않고 산출물 경로만 적는다(단일 원천).
- 명령 출력 원문과 설정값은 넣지 않는다(비밀정보 검출로 다른 안건의 작업 트리 검사가 실패할 수 있음. v01 3.2절 E).

### 5.3 호출 문구와 승인의 전달(개정 2·3)

1. 대표님이 세션 A에 「B에게 ○○ 맡겨」라고 하면 A는 대표님 원문과 호출 문구 전문을 담은 「요청」을 남긴다.
2. 승인이 걸린 일이면 A가 승인 기록(`Workflow/07` 3.1절 4항 1)을 먼저 쓰고 요청에 그 경로를 적는다.
3. 대표님이 B에게 「연락 확인」이라고 하면 B는 자기 앞 요청마다 대표님 원문, 실행할 호출 문구, 승인 기록 경로를 화면에 보인다. 이때는 아무것도 실행하지 않는다.
4. 대표님이 「진행」(또는 요청 파일을 골라 「○○ 진행」)이라고 하면 B는 그 요청을 실행하고 「회신」을 남긴다.
5. B는 대표님 원문이 없는 요청, 승인 기록 경로가 없는 승인 관련 요청, 발신이 비서실 세션이 아닌 요청은 실행 대상에서 빼고, 뺀 사유를 담은 「회신」을 남긴다. 회신이 생겼으므로 그 요청은 다음 「연락 확인」 때 다시 나오지 않는다.

복사·붙여넣기 대신 「연락 확인」, 「진행」 두 마디가 남는다. 세션은 대표님 메시지를 받을 때만 움직이므로 이 두 마디는 없앨 수 없다. 대신 대표님은 실행 전에 받는 세션 화면에서 내용을 확인한다.

### 5.4 세션이 읽는 양

- 작업을 시작할 때와 「연락 확인」 때만 폴더의 파일 이름 목록을 본다.
- 담당 판단은 그 작업 번호가 든 파일 이름만 보고, 연락 확인은 수신이 자기이거나 `전체`인 파일만 연다. 파일이 쌓여도 이름으로 걸러 보므로 여는 파일 수는 늘지 않는다.
- 원안은 세션마다 `BOARD.md` 전체를 읽고 고친다. 지울 규칙도 없어 파일이 계속 길어진다.

### 5.5 커밋

- 작업 번호가 REQ 번호이거나 그 REQ를 낳은 ORDER 번호인 연락은 그 안건의 최종 승인 커밋에 들어간다(개정 7).
- 안건 커밋에 들어가지 않은 연락(HOTFIX, 조사, `없음`, ORDER의 REQ가 모두 커밋된 뒤 쓴 ORDER 「완료」, REQ 없이 끝난 ORDER의 연락)은 대표님이 요청할 때 「요청 커밋」(`docs: [CEO] 비서실 연락 추가`)으로 커밋한다. `Departments/Secretariat/assets/` 변경 커밋은 이미 판정 전제에서 빠져 있다(`AGENTS.md` 「불변 원칙」 5항).
- 시범 기간에도 같다. 개정 7 전에는 모든 연락을 「요청 커밋」으로 커밋한다.

## 8. 진행 순서와 대표님 결정 사항

### 8.1 진행 순서

1. 대표님 결정 뒤 바로 시범: `Departments/Secretariat/assets/연락/`에 `README.md`(5절 규칙의 시범 사본)를 만들고 착수·인계·완료·요청·회신을 쓴다. 이 폴더의 파일은 scope 대조에서 빠지므로 다른 안건의 커밋 전 검사가 실패하지 않는다. 시범 기간에는 호출 문구·승인 전달(5.3절)은 쓰지 않고 지금처럼 대표님이 전달한다.
   - 근거: `Workflow/02`는 이 폴더를 아직 허용하지 않는다. 거버넌스 파일의 개정 권한은 대표님에게 있으므로(`AGENTS.md` 「불변 원칙」 3항), 대표님의 시범 지시(D3)를 개정 1의 시범 예외로 삼는다. 첫 세션이 그 지시 원문과 시각을 `README.md` 머리에 적고, 뒤에 작성하는 ORD-009 1절에도 옮긴다. 예외로 두지 않으려면 대표님이 `Workflow/02`에 한 줄을 직접 더한 뒤 시작한다(커밋은 `--no-verify` 지시가 필요한 대표님 직접 수정 경로).
   - 세션이 규칙 위치를 아는 방법: 코워크는 프로젝트 지침에 한 줄(「연락 규칙은 `Departments/Secretariat/assets/연락/README.md`」)을 더한다(지침 수정이라 대표님 승인 필요). Antigravity·Codex는 시범 기간에 대표님이 세션을 열 때 같은 문장을 한 번 말한다. 정식 반영 뒤에는 `AGENTS.md` 문서 지도가 가리킨다(개정 10).

   - 겹치는 범위: ORD-007 요구 항목 4(중복 브리핑 금지. 「REQ에서 정할 사항」에 `Workflow/05` 8.4절 3항 ①·4항과의 관계가 있다), ORD-006 요구 항목 12(추적성). ORD-009 REQ에서 겹침을 확인한다.
3. 개정이 반영되면 호출 문구·승인 전달(5.3절)을 쓰기 시작하고, `README.md`는 `Workflow/05` 새 항을 가리키는 한 줄로 줄인다.
