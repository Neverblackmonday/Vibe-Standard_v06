## 2. 결론

1. **원문 2로 범위가 줄었습니다.** 업데이트 수용 방식(M2)은 로컬 개발 단계에만 필요하고, SaaS 단계에서는 본사 릴리스가 그대로 적용됩니다. 고객 제안의 접수는 이메일로 정해졌으므로(원문 2) v01 M3의 제안서 서식·접수 위치는 빼고, 접수 이메일을 릴리스 노트(M1)에 적습니다. 폴더 브리핑에서 받아들인 한 줄 규정(「포크에서 나온 개정 제안은 대표님이 본사 비서실에 전달해 본사 ORDER로 처리」)은 대표님 프로젝트의 부적합 기록 제안에도 필요하므로 M3으로 줄여 남깁니다.
2. **「표준을 쓰면 보안 기본 설정이 된다」의 바탕은 이미 있습니다.** 거버넌스 파일 쓰기 차단(`deny`), Bash 삭제·커밋·푸시 확인(`ask`), 커밋 전 비밀정보 검출, 배포 전 보안 점검은 이미 배포본에 들어 있습니다(`Workflow/06` 1.1·2·4절). 공식 문서상 거부 규칙과 명시한 확인 규칙은 모든 권한 모드에서 작동하고, 고객이 개인 설정에 허용 규칙을 더해도 표준의 거부 규칙은 풀리지 않습니다.
3. **빠진 것은 여섯 가지이고, 정리할 것이 하나 있습니다.** 빠진 것은 비밀정보 파일(`.env`), 확인 요청을 건너뛰는 모드 막기, 시작 권한 모드(최신 Claude Code는 대화형 세션을 자동 모드로 시작함), 프로젝트 폴더 밖 읽기 막기, PowerShell 명령의 확인 공백, 원격 저장소 공개 위험입니다. 정리할 것은 효과 없는 `Write` 규칙입니다(6절). 앞의 넷은 설정 몇 줄입니다.
4. **설정만으로 막을 수 없는 것도 있습니다.** 공식 문서상 셸 명령 샌드박스는 Windows에서 바로 쓸 수 없고(WSL2 필요), Bash 권한 규칙은 명령 문자열로만 맞춥니다. 또 관리형 설정이 없고 Team·Enterprise 요금제가 아닌 PC에서는, 사용자가 설치한 mod가 거부 규칙에 걸린 호출도 승인할 수 있습니다(공식 문서 「Configure permissions」). 그래서 표준이 약속할 수 있는 것은 「사고를 줄이는 기본 설정」이며 「완전한 차단」은 아닙니다. 이 한계를 표준과 설치 안내에 적어야 고객에게 과장 없이 설명할 수 있습니다.
5. **보안 밖에서 표준에 더할 것은 없습니다.** 판매에 필요한 나머지(라이선스, SaaS 자동 적용 동의, 고객 데이터의 위치)는 표준 규정이 아니라 사업·제품 기획 사항입니다(4절, 9절). 설치 안내는 ORD-008 요구 항목 30(J2)이 이미 다룹니다.

## 5. 비밀정보 파일(.env) 관리

| 항목 | 현행 | 공백 | 권고 |
| :--- | :--- | :--- | :--- |
| Git 제외 | `.gitignore`에 `.env` 한 줄 | `.env.local`·`.env.production` 같은 변형, 키 파일(`*.pem`, `*.key`)은 빠지지 않습니다 | `.gitignore`에 `.env`, `.env.*`, `!.env.example`(견본은 다시 추적) 세 줄을 둡니다. 키 파일 규칙은 REQ에서 정합니다 |
| 에이전트 읽기 차단 | `settings.json` `deny`에 읽기 규칙이 없습니다 | 에이전트가 `.env`를 읽어 값이 대화·출력·로그에 남을 수 있습니다 | `deny`에 `Read(.env)`, `Read(.env.*)`, `Read(!.env.example)`을 이 순서로 넣습니다. 공식 문서 「Settings」의 예시(`Read(./.env)`)는 현재 폴더의 `.env`에만 맞고, 앞에 경로가 없는 `Read(.env)`는 하위 폴더 어디의 `.env`에도 맞습니다. `!` 규칙은 같은 목록에서 앞의 규칙에서 견본만 빼냅니다. `Read` 거부는 같은 경로의 편집·새 파일 쓰기도 막으므로(Claude Code v2.1.208 이상 편집, v2.1.228 이상 쓰기), 에이전트는 `.env`를 만들거나 고칠 수 없고 값 입력은 사람이 합니다(공식 문서 「Configure permissions」) |

## 9. 확인하지 못한 항목

- `CEO/` 아래 파일이 커밋되어 있는지(v01 부록의 확인 명령 결과 대기).
- 판매 형태별 구조(SaaS의 고객 데이터 위치, 로컬 HTML 엔진의 업데이트 수신 방식). 제품 기획 전이라 대상이 없습니다.
- 라이선스, SaaS 자동 적용에 대한 고객 동의, 고객 수정본의 권리. 법률 검토 대상이며 이 자료는 다루지 않았습니다.
- 5절 `Read` 규칙과 6.2절 ②③④ 설정의 실제 동작(대표님 PC의 Claude Code 버전, Windows 경로). 공식 문서 기술만 확인했고 실측하지 않았습니다.
- `blockReadsOutsideWorkingDirectories`와 `cleanupPeriodDays`의 기본값. 「Settings reference」에서 키의 한 줄 설명만 확인했습니다.
- 대표님 PC와 고객 PC의 Claude Code 버전과 실제 시작 권한 모드(6.2절 ③).
- 6.2절 ④를 켰을 때 `tar --force-local -tf`가 파일을 읽는 Bash 명령으로 인식되는지.
- 6.2절 ⑥의 `Write` 규칙 처리. 공식 문서 기술과 `Workflow/06` 2절의 실측 서술이 다를 수 있어 실제 버전에서 확인이 필요합니다.
