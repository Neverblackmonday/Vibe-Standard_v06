# ORD-010 REQ 작성 결과 검토

- 검토 대상: `ORD-010_v05`의 REQ 작성 파이프라인 결과(`REQ-028_v02`, `REQ-029_v04`, `REQ-030_v02`와 판정서·부적합 기록), PM 완료 보고(Claude Code 비서실 세션이 대화로 전한 보고)의 스테이징 이상
- 함께 다룬 요청: 대표님의 「비서실 업무끼리의 순서를 정하거나, 꼬이지 않도록 관리」 개선안이 진행 중인지(8절)
- 확인 방법: 대표님 PC의 파일을 이 세션으로 가져와 읽었다(2절). 이 세션은 대표님 PC에서 Git 명령을 실행할 수 없어 스테이징 상태는 PM 보고만 근거로 쓴다.

## 1. 결론

1. **세 REQ는 ORD-010 요구 항목 1~6과 「REQ에서 정할 사항」을 빠짐없이 덮는다(3절).** 결정 사항의 권고안도 ORD-010·ORD-011과 어긋나는 곳이 없다(4절. 8.2절 대장 권고와의 관계는 4절 `REQ-029` D9 행). 세 REQ를 지금 권고안대로(`REQ-029` D7은 4절 D7 행의 결정 문안으로) 승인하고, 원스톱은 `REQ-028` → `REQ-029` → `REQ-030` 순서로 앞 안건의 최종 승인 커밋 뒤 하나씩 실행하기를 권고한다.
2. **판정 쪽 절차 위반이 2건 있다(5절).** `RES-029-REQ_v01`과 `RES-030-REQ_v01`은 `fail`인데 부적합 기록이 없다(`Workflow/03_라이프사이클` 13절 3항 위반). 늦게 만드는 경로가 표준에 없으므로 늦은 기록은 만들지 않고, 누락 사실과 이후 누적에 남는 영향을 ORD-008에 근거로 전하기를 권고한다.
3. **부적합 기록의 표준 개정 제안 3건(C1 2건, C5 1건)은 새 ORDER 없이 ORD-008 요구 항목 1(A1)·2(A2)에 전하기를 권고한다(6절).** C5는 A1이 같은 작성 기준을 다룬다. C1 두 건은 A2(`NCR-029_02`는 32도)와 주제가 가깝지만 대상 단계(REQ 작성)가 넓어지므로, 보강 근거와 함께 범위 확장을 전한다.
4. **스테이징 이상은 `REQ-028`의 최종 승인 커밋 전에 반드시 풀어야 한다(7절).** 스테이징된 파일이 그대로 있으면 그 커밋에 다른 파일이 섞인다.
5. **비서실 업무 순서를 한곳에서 관리하는 개선안은 진행 중인 것이 없다(8절).** 겹치는 항목은 있으나 ORDER 사이의 처리 순서를 한곳에 두는 장치는 없다. ORD-011 새 버전에 요구 항목으로 넣기를 권고한다.

- 영향: 부적합 기록의 누적 건수(13절 5항)가 실제보다 적게 세어졌다. 다만 C1·C5는 이미 제안 기준(13절 6항, 2건 이상)에 이르러 제안이 나왔으므로 이번 제안 여부는 바뀌지 않는다. 빠진 기록에는 원인 분류가 붙지 않았으므로, C1·C5 밖의 분류는 이후 누적에서도 적게 세어질 수 있다(예: `C7`은 `NCR-028_01` 1건뿐이다).
- 처리 권고: 부적합 기록은 판정 때 품질 서브에이전트가 남기는 기록이며 늦게 만드는 경로가 표준에 없다. 늦은 기록을 만들지 않고, 이 사실(동시 판정과 기록 누락)을 ORD-008의 보강 근거로 전한다(6절 전달 문구 3).
