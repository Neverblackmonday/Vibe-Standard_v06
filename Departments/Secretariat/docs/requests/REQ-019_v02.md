## 2. 배경 및 목적
- **배경**
  - 아래 사실은 2026-10-09T21:48:11+09:00 이후 이 저장소에서 조회한 것이다. 최신 커밋은 `69ba21d`(REQ-018)다.
  - **시각을 조회하지 못한 판정서**: `Departments/Quality/results/`의 판정서 가운데 `RES-016-REQ_v02.md`, `RES-016-REQ_v04.md`, `RES-017-REQ_v02.md`, `RES-017-REQ_v04.md`, `RES-018-REQ_v01.md`의 `completed_at`이 「확인 불가」다. 각 판정서 머리말 주석은 셸(Bash·PowerShell) 실행이 권한 거부되어 시각을 조회하지 못했다고 적었다. `RES-016-REQ_v03.md`는 지시받은 Bash `date`가 권한 거부되어 PowerShell `Get-Date`로 조회했다고 적었다. `RES-018-REQ_v02`~`v05`, `RES-018-EC_v01`~`v03`의 `completed_at` 주석은 PowerShell `Get-Date -Format o`로 조회했다고 적었다.
  - **그 밖의 명령 실행 문제**: `Departments/Secretariat/workspace/실행기록_REQ-018.md`는 EC 판정 세션의 `git diff --no-index` 실행이 권한 검사에 막혀 `diff -U0`으로 대신한 일(2026-10-09T20:28:35, 20:31:05 행), 인수 시험 세션의 환경 변수 설정 명령이 권한 확인 대상이라 다른 방법으로 Red를 확인한 일(20:48:55 행)을 적었다. ORDER 1절 경위(요구 항목 8의 사실)는 `REQ-018_v04`·`v05`의 REQ 판정 세션에서 `git` 명령이 권한 확인 요청으로 실행되지 않았다고 적었다(`RES-018-REQ_v04.md`·`v05.md` 4절). 반면 `RES-016_v01` 최종 판정 세션은 `git`과 커밋 전 검사를 막힘 없이 실행했다(ORDER 1절 경위). 이 REQ의 첫 판정 세션(`RES-019-REQ_v01.md` 4절)에서는 `date ...; git -C ... log ...`처럼 두 명령을 `;`로 묶은 Bash 명령이 `Permission to use Bash has been denied.`로 거부되었고, 같은 두 명령을 하나씩 따로 실행하자 확인 없이 실행되었다. 같은 시각대의 `REQ-020` 판정 세션(`RES-020-REQ_v01.md` 4절)에서는 Bash `git -C ... status --porcelain -uall -- <경로>`와 PowerShell `git status --porcelain -uall` 두 가지가 권한 거부되었고, Bash `git ls-files`와 `sed`·`date` 조합 명령도 거부되었다. 이 관찰들이 앞의 사례에 모두 해당하는지는 확인되지 않았다.
  - **현행 권한 설정**: `.claude/settings.json`의 `allow`에는 `Bash(git status*)`, `Bash(git diff*)`, `Bash(git log*)`, `Bash(git show*)`, `Bash(git ls-files*)`, `Bash(date*)`, `Bash(python Departments/Development/assets/scripts/check_standard.py*)`, `Bash(python -m pytest*)` 등 Bash 규칙만 있고 PowerShell 규칙은 없다. `ask`에는 `rm`, `del`, `mv`, `move`, `git commit`, `git push`가 있다. 저장소에 `.claude/settings.local.json`은 없다(Glob `.claude/*` 결과 `settings.json` 하나). `Workflow/06_통제장치_및_배포` 2.1절은 「검증 명령은 Bash 도구로 실행한다. PowerShell 도구에는 `Bash(...)` 규칙이 적용되지 않는다」고 적었다. `.claude/agents/quality.md`는 `model: inherit`, `disallowedTools: Agent`만 지정하고 도구·권한에 관한 다른 설정이 없다.
  - **원인**: 위 사례에서 `allow`에 있는 명령(예: `RES-016-REQ_v03`의 Bash `date`)도 거부된 까닭은 확인되지 않았다(ORDER 1절 경위 「원인은 확인되지 않았다」).
  - **현행 처리 규정**: 판정 모델을 확인할 수 없으면 판정서를 발행하지 않고 오케스트레이터에 보고한다(`Workflow/04_모델_운용` 「모델 메타데이터 기록」). 그 밖의 명령을 실행하지 못했을 때의 처리는 정해져 있지 않아, 위 판정서들은 「확인 불가」로 적거나 다른 명령으로 대신하고 판정을 계속했다. `ask` 목록 명령이나 `allow` 목록 밖 명령의 권한 확인 요청이 생기면 파이프라인은 멈춘다(`Workflow/03_라이프사이클` 「중단 조건」 5항).
- **목적**: 품질 서브에이전트가 판정·인수 시험·부적합 기록에 필요한 명령을 권한 거부나 권한 확인 요청 없이 실행하게 한다. 지금까지의 거부·확인 요청 사례의 원인을 확인하고, 그 원인이 다시 생기지 않게 한다. 판정 세션이 그래도 명령을 실행하지 못했을 때의 처리를 표준에 둔다. 원인 확인은 EC 작성 전의 실험 단계에서 하고, 설정·정의 파일의 변경 내용, 처리 규정의 문구와 위치는 EC에서 정한다.

## 5. 검증 및 완료 기준 (체크리스트)
> 작성 기준은 `Workflow/03_라이프사이클` 「REQ 작성 파이프라인」을 따른다. 확인 방법이 명령·시험의 실행 결과인 항목은 인수 시험의 대상이 된다(`Workflow/03_라이프사이클` 「시험실」). 「적용본」은 설계·개발 적용본 폴더의 최신 버전을 가리킨다. 「대상 명령」은 D3 권고안의 범위(시각 조회, Git 조회(`git diff --no-index` 포함), 커밋 전 검사 실행, 인수 시험 실행)를 가리킨다. 「재현 시험」은 개발이 수정 전 조건과 적용본 조건에서 대상 명령의 실행을 비교한 시험이며, 결과서에 명령과 결과 원문이 있어야 한다. 「원인을 확인한 사례」는 ①에서 원인과 근거가 적힌 사례이고, 「원인을 확인하지 못한 사례」는 ①에서 「확인 불가」로 적힌 사례다.

| 번호 | 요청 원문 항목 | 확인 방법 |
| :---: | :--- | :--- |
| 8 | 요구 항목 8: 판정 세션의 셸 권한 | ① 개발 결과서 6절 「실험 결과」(실험 단계의 `DEV-019_v01.md`와 구현 단계 결과서에 옮긴 6절)에 2절 「배경」의 사례(시각 조회 거부, `allow`에 있는 `date`의 거부, `git` 명령의 권한 확인 요청, `git diff --no-index`의 막힘, 인수 시험 세션의 권한 확인 대상 명령, 두 명령을 `;`로 묶은 Bash 명령의 거부, `RES-020-REQ_v01`의 `git status`·`git ls-files` 거부)마다 확인한 원인과 그 근거(재현 결과 원문 또는 근거 기록 경로)가 있다. 재현하지 못한 사례는 「확인 불가」와 사유가 있다. EC가 이 결과서 경로와 6절을 인용한다 ② 원인을 확인한 사례마다, 재현 시험에서 대상 명령이 수정 전 조건에서는 그 원인대로 거부·확인 요청되고 적용본 조건에서는 거부·확인 요청 없이 실행된다. 결함이 있는 사본(수정 전 설정)에서 같은 시험이 실패해 시험이 실제로 차이를 확인한다(Red 확인). 원인을 확인하지 못한 사례는 ②의 대상이 아니며, 대신 그 사례가 `Workflow/06` 적용본 7절 「알려진 과제」에 남은 범위와 상태로 있고, 그 사례가 다시 생겨도 ③의 처리로 판정 근거가 빠진 판정서가 발행되지 않는다 ③ 적용본을 열람하면 D2 권고안의 처리(대신할 수 있으면 대신하고 판정서에 실행하지 못한 명령과 대신한 수단을 적음. 시각 조회를 다른 허용 명령·도구로 대신한 경우도 여기에 든다. 대신할 수 없으면(어떤 허용 명령·도구로도 시각을 조회하지 못한 경우 포함) 판정서를 발행하지 않고 오케스트레이터에 보고해 파이프라인이 멈춤, `completed_at`에 「확인 불가」를 적지 않음)가 한 문서에만 있고, `RES_TEMPLATE.md`·`Workflow/07` 적용본의 `completed_at` 안내와 맞는다 ④ 적용본 `settings.json`의 `deny`가 원본과 같고(`AGENTS.md` 「불변 원칙」 3항의 거버넌스 쓰기 차단 유지), `ask`에서 빠진 항목이 없다(`git diff --no-index`로 원본과 비교한 결과가 결과서에 있다) ⑤ 개정된 규칙과 `settings.json`·`.claude/agents/`·`check_standard.py`의 대조 결과가 개발 결과서에 있고 어긋남이 없다 ⑥ `Workflow/06` 적용본 2.1절 「무인 실행 권한」과 7절 「알려진 과제」가 확인한 원인과 맞고(원인이 남아 있으면 7절에 남은 범위와 상태가 있다), 2.1절의 「PowerShell 도구에는 `Bash(...)` 규칙이 적용되지 않는다」 서술이 조치 결과와 어긋나지 않는다 |
