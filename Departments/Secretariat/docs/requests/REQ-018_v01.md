## 2. 배경 및 목적
- **배경**
  - 아래 사실은 2026-10-09T13:07:36+09:00 이후 이 저장소에서 조회한 것이다. 최신 커밋은 `610558b`(2026-10-09T13:01:07+09:00)이다.
  - **운영의 현행 책무**: `AGENTS.md` 1절 운영 행의 권한 한계는 「승인되지 않은 파라미터·인프라를 바꾸지 않는다」이다. `Workflow/02` 2절 운영 행의 책임은 「런타임 파라미터, 배포 묶음, 운영 기록」, 산출물은 `assets/live/`, `assets/releases/`, `assets/logs/`, `docs/`, `results/`다. `.claude/agents/operations.md`는 책임을 `Workflow/02`에서 읽게 하고 금지 사항(scope 밖 수정, 코드·명세 수정)만 적는다. 운영 폴더에서 추적하는 파일은 `.gitkeep`뿐이다(`git ls-files Departments/Operations`). 운영은 REQ `workflow:`에 적힌 경우에만 기동하는 서브에이전트다(`Workflow/03` 2절, `Workflow/05` 3절).
  - **보안의 현행 서술**: 표준에는 보안을 맡는 조직이 정해져 있지 않다. 비밀정보의 노출 금지와 대리 입력 금지는 사용자 전역 지침 「보안 및 불변 데이터 보호」가 정하고, `.gitignore`는 `.env`와 `.claude/settings.local.json`을 무시한다. `.claude/settings.json`은 거버넌스 파일·`CEO/`·`_archive/`의 쓰기를 막고(`deny`), 삭제·이동·커밋·푸시를 확인받는다(`ask`). `Workflow/06` 2.1절은 `Bash(python Departments/*/workspace/*)` 허용이 사실상 임의 명령 실행을 허용하는 완화라고 적고 있다. 커밋 전 검사(`check_standard.py`)에는 비밀정보를 찾는 검사가 없다.
  - **사고 이력**: 이 저장소의 커밋 이력에서 비밀정보 노출을 고친 커밋은 확인되지 않았다(`git log -i -E --grep="보안|비밀|secret|token|키 "` 결과 1건 `3801c62`는 `secretariat` 폴더 이름이 걸린 것이며 보안 수정 커밋이 아니다). 이 저장소에는 API 키를 쓰는 코드가 없다(`Departments/Development/assets/src/`의 추적 파일은 `.gitkeep`뿐이다). 처음 제안 표 4번은 자동 검출의 도입 시점을 「키를 쓰는 프로젝트가 생길 때」로 권고했다(ORDER 1절 경위).
  - **비서실의 보고 경로**: 비서실은 PM의 완료 보고를 `Workflow/05` 5절 양식으로 다시 작성해 대표님께 보고하고(5절 6항), 브리핑 종류는 조사·승인·진행 현황·기획 브리핑 네 가지다(6절 3항).
- **목적**: 표준에 운영의 보안 책임(보안 정책, 키 관리, 정기 점검)을 지정하고, 정기 점검의 시점·항목과 점검 결과가 운영에서 비서실을 거쳐 대표님께 보고되는 경로를 정한다. 비밀정보 자동 검출의 도입 시점과 운영 권한 한계의 변경 여부를 함께 정한다. 반영 문구, 절 구성, 점검 결과의 서식은 EC에서 정한다.

## 3. 결정 사항 및 선택지
> 정할 일의 작성 기준은 `Workflow/03_라이프사이클` 「REQ 작성 파이프라인」 1항을 따른다. D1~D4는 ORDER 2절 「REQ에서 정할 사항」 가운데 이 REQ가 맡는 세 항목을 ORDER 순서대로 옮긴 것이다. 첫 항목(정기 점검 주기와 항목, 점검 결과를 넘기는 방식)은 D1·D2로 나누었고, 자동 검출 항목은 D3, 권한 한계 항목은 D4다. D5는 ORDER에 없으나 요구 항목 6의 「보안 정책」을 이번에 어디까지 만드는지 정해야 하므로 더했다. D6은 서식이 정한 effort 선택이다.

## 5. 검증 및 완료 기준 (체크리스트)
> 작성 기준은 `Workflow/03_라이프사이클` 「REQ 작성 파이프라인」을 따른다. 「적용본」은 설계·개발 적용본 폴더의 최신 버전을 가리킨다. 「한 문서에만 있다」는 Grep으로 확인하며, 다른 문서가 그 절을 참조하는 문장은 세지 않는다.
