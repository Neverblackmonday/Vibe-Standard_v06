## 5. 검증 및 완료 기준 (체크리스트)
| 번호 | 요청 원문 항목 | 확인 방법 |
| :---: | :--- | :--- |
| 1 | 1번: `git diff` 설명 오류 | 04 적용본 「타깃 컨텍스트 규칙」 3항에 「옵션 없는 `git diff`가 HEAD 대비 차이」라는 뜻의 문장이 없고, 그 항이 지정한 각 `git diff` 명령의 비교 대상이 Git 공식 동작과 맞다 |
| 2 | 2번: 적용본 재판정 비교 대상, 새 파일 전문 첨부 예외 | 04 적용본 같은 항에서 ① 적용본 재판정의 변경분이 직전 판정 대상 적용본과 새 적용본의 차이로 정해져 있다 ② 새 파일 전문 첨부 규칙이 같은 항에서 따로 변경분을 구하도록 정한 파일(기록 문서 새 버전, 거버넌스 적용본)을 제외한다 |
| 3 | 3번: `--no-verify` 단독 커밋 조건 | 06 적용본 「커밋 전 검사」에 `--no-verify` 커밋은 그 대상 변경만 담고 다른 변경과 섞지 않는다는 조건이 있다 |
| 4 | 4번: HOTFIX scope 표기로 거버넌스 검사 우회 | `DEV-008`에 임시 Git 저장소 재현 시험의 명령·시각·결과가 있다. 시험은 `confirmed:`가 형식에 맞는 HOTFIX의 scope에 거버넌스 경로의 상위 폴더(예: `Departments/Development/assets`)와 확장자를 뺀 거버넌스 파일명(예: `AGENTS`)을 각각 적고 해당 거버넌스 파일을 바꾼 경우를 포함한다. 원본 `check_standard.py`에서는 통과하고(우회 재현), 적용본에서는 `[FAIL]`과 종료 코드 1이 나온다. 같은 시험에서 거버넌스와 무관한 정상 HOTFIX는 적용본에서도 통과한다 |
| 5 | 5번: 「확인 불가」 과제 실측 | `DEV-008`에 06 「알려진 과제」 1·2·4·5·6행 각각의 실측 명령·시각·결과가 있거나, 파이프라인 안에서 실측할 수 없는 행은 그 사유와 대표님이 직접 실행할 확인 절차가 있다(D1). 06 적용본의 「알려진 과제」 절은 원본과 같다(4절) |
