# REQ-007: 패키지 폴더 재편(Package_sample·Package_update)

## 1. 요청 원문
> 요구 메모 `Departments/Secretariat/assets/inbox/요구메모_20261006_패키지폴더_v01.md`의 대표님 지시를 원형 그대로 인용한다.

> 요청사항1.
> Update package 폴더를 Package_update로 변경.
> Package_sample폴더 신설.
>
> Package_sample은 신규 프로젝트 때 해당폴더 복사해서 들고가는용도.
> Package_update는 업데이트 용.
>
> 근데 만약 업데이트가 너무 복잡한 경우는 어떻게되지? 그냥 표준업데이트파일 안만들고 그때그때 정리하는게 낫나?

항목 구분:
1. `Update_Package` 폴더를 `Package_update`로 변경한다.
2. `Package_sample` 폴더를 신설한다.
3. `Package_sample`의 용도는 신규 프로젝트 때 폴더째 복사해 가져가는 것이다.
4. `Package_update`의 용도는 기존 프로젝트의 업데이트다.
5. 업데이트가 복잡한 경우의 처리 방법을 정한다.

## 2. 배경 및 목적
- **배경**
  - `Workflow/06_통제장치_및_배포` 「배포본과 업데이트 패키지」는 배포본과 업데이트 패키지의 용도를 구분한다. 그러나 두 묶음 모두 「보류」 상태다.
  - 배포본에는 담을 폴더가 없다. 업데이트 패키지 폴더 이름(`Update_Package`)은 대표님이 정한 이름과 다르다.
  - `Update_Package`를 참조하는 곳은 `.gitattributes` 7·8행, `Workflow/01_표준_개요` 「용어」, `Workflow/02_부서_구조_및_작업구역` 「저장소 구조」다(2026-10-06 창구 조회).
- **목적**: 신규 프로젝트용 묶음과 업데이트용 묶음을 이름과 폴더로 구분하고, 각 묶음을 만드는 절차와 복잡한 업데이트의 처리 기준을 규정한다.

## 3. 결정 사항 및 선택지
| 번호 | 정할 일 | 권고안 | 대안 | 결정 |
| :---: | :--- | :--- | :--- | :--- |
| D1 | 패키지 폴더 내용물의 Git 관리 | 폴더는 `.gitkeep`만 커밋한다. 내용물은 `.gitignore`로 제외하고 필요할 때 생성한다 | 내용물까지 커밋 | 대표님이 기재 |
| D2 | `Package_sample` 생성 방법 | `git archive HEAD`로 만든 배포본을 비운 `Package_sample/`에 푼다(06 6.1절 절차를 대상 폴더만 바꿔 사용) | 수동 복사 | 대표님이 기재 |
| D3 | `Package_update` 생성 방법 | `git archive HEAD -- <거버넌스 파일 목록>`의 결과와 `변경요지.md`를 함께 둔다. 빌더 스크립트는 만들지 않는다 | v02 빌더 복원 | 대표님이 기재 |
| D4 | 복잡한 업데이트의 처리 | 업데이트를 두 유형으로 나눈다. 덮어쓰기형은 패키지를 덮어쓰면 끝난다. 이관형은 패키지에 `이관지침.md`를 넣고, 대상 프로젝트가 「표준 이관 REQ」(Critical)로 처리한다 | 패키지 없이 그때그때 정리 | 대표님이 기재 |
| D5 | 이관형 판단 기준 | 다음 가운데 하나라도 해당하면 이관형이다: 폴더 구조 변경, 기록 파일명·머리말 형식 변경, 고객 작업 구역 파일 수정 필요, 대상 프로젝트의 거버넌스 파일 자체 개정 이력 | 대표님이 매번 판단 | 대표님이 기재 |
| D6 | 이번 안건에서 패키지 내용물을 실제로 생성할지 | 생성하지 않는다. 폴더와 절차만 정한다 | 이번에 생성 | 대표님이 기재 |
| D7 | effort | `medium` | `high` | 대표님이 기재 |
