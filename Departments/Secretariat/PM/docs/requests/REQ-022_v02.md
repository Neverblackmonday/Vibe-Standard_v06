**요구 항목**(ORDER 2절 가운데 이 REQ가 맡는 항목):

10. **분류 재정의**: 분류(Critical·Major·Minor)를 항공 품질의 Critical·Major·Minor 수준 관리를 차용해 REQ의 중요도와 난이도로 정한다. 기능상 중대 결함이 우려되는 항목도 Critical로 관리한다. 분류에 따라 후속 업무의 품질 평가 단계나 AI 강도(모델 등급)를 강화한다. effort 기본값은 등급과 관계없이 `medium`이며 `high`는 REQ에 명시해 대표님 승인을 받을 때 쓴다(3절 12항). 모델 등급(최고급·고급·중급), 분류별 기본 등급, 판정 단계의 모델(REQ 판정과 최종 판정은 고급. effort `high`로 구현한 안건의 최종 판정은 effort `high`. 3절 15·16항)을 표준에 두고, 등급별 기본 모델·effort와 기본값 밖의 모델·effort를 쓸 때의 명시 방식을 둔다. 최고급(Fable급·Astra)은 기본 등급이 아니며, 쓸 때 대표님 승인을 받는다. REQ 안건에서는 REQ에 명시해 승인을 받는다(3절 12항). 최고급을 쓸 수 있는 분류(Minor 포함 여부)는 REQ에서 정한다. 핫픽스에는 모델 등급 규정을 두지 않고 HOTFIX에 실제로 작업한 모델을 적는다(3절 17항). 분류는 비서실이 ORDER에 제안하고 PM이 REQ마다 확정하며, REQ 판정이 확인하고 대표님이 REQ 승인 때 최종 결정한다. REQ 작성 파이프라인은 늘 고급으로 실행한다(3절 14·15항). REQ 안건의 모델 등급은 PM이 REQ에 정하는 분류로 정해지며, 비서실을 뺀 원스톱 파이프라인 전체(PM, 설계, 개발, 품질 판정 등 원스톱 파이프라인 안의 모든 세션)에 적용한다(최종 판정은 3절 16항). 현행 `Workflow/04_모델_운용` 「모델」의 Fable 사용 금지와 판정 모델 고정 규정을 없앤다(3절 11~13항). 최종 판정 반려 누적 때의 격상 규정도 새 분류 기준에 맞춘다(3절 5항, 1절 경위의 원문 L 뒤 항목).

**REQ에서 정할 사항**(ORDER 2절 「REQ에서 정할 사항」 가운데 이 REQ가 맡는 항목):

> - 분류별 정의 기준(항공 품질의 Critical·Major·Minor 수준 가운데 무엇을 이 저장소의 어느 분류로 보는지. 정의 문구는 EC에서 정한다)과 분류별 품질 평가 단계(3절 11~13·15~17항으로 정해진 모델 등급과 기본값은 다시 올리지 않는다)

- **목적**: 분류를 REQ의 중요도와 난이도로 다시 정의하고, 분류가 후속 단계의 품질 평가와 모델 등급을 정하게 한다. ORDER 3절 11~17항의 모델 등급, 등급별 기본 모델·effort, 단계별 모델, 기본값 밖 사용의 명시·승인을 표준에 두고, 현행 Fable 사용 금지와 판정 모델 고정 규정을 없애며, 그 규정에 묶인 판정 모델 확인·중단·원인 분류를 새 기준에 맞춘다. 분류 제안·확정·확인 경로와 격상 규정도 새 기준에 맞춘다. 세션별 모델 지정과 실제 실행 모델 확인이 가능한지는 EC 판단 전의 실험 단계에서 확인하고, 규정의 문구와 위치, 실행 명령·서식·서브에이전트 정의의 변경 내용은 EC에서 정한다.

## 3. 결정 사항 및 선택지
> 정할 일의 작성 기준은 `Workflow/03_라이프사이클` 「REQ 작성 파이프라인」 1항을 따른다. D1·D2는 ORDER 「REQ에서 정할 사항」 첫째 항목을 정의 기준과 품질 평가 단계로 나눈 것이다. D3은 둘째, D4는 셋째, D5는 넷째, D6은 다섯째, D7은 여섯째, D8은 일곱째 항목이다. D9·D10은 여덟째 항목을 정할 일마다 나눈 것이고, D11은 아홉째 항목이다. D12는 실험 단계에서 현행 모델 규정 밖의 모델을 쓰는지로, 실험 단계(2절 「목적」)를 두면서 생겼다. D13은 Claude Code에서 실행할 수 없는 등급 모델을 파이프라인과 판정에 쓰는지로, ORDER 3절 12항의 등급에 Claude가 아닌 모델이 있어 더했다. D14는 서식이 정한 effort 선택이다. ORDER 3절 11~17항으로 정해진 모델 등급과 기본값은 결정 사항으로 다시 올리지 않는다.

## 5. 검증 및 완료 기준 (체크리스트)
> 작성 기준은 `Workflow/03_라이프사이클` 「REQ 작성 파이프라인」을 따른다. 확인 방법이 명령·시험의 실행 결과인 항목은 인수 시험의 대상이 된다(`Workflow/03_라이프사이클` 「시험실」). 「적용본」은 설계·개발 적용본 폴더의 최신 버전을 가리킨다. 각 항목은 3절 D1~D14의 권고안을 전제로 한다.

| 번호 | 요청 원문 항목 | 확인 방법 |
| :---: | :--- | :--- |
| 10 | 요구 항목 10: 분류 재정의 | ① 적용본에 분류의 정의 기준이 한 문서에만 있다. 분류를 REQ의 중요도와 난이도로 정하고, 중요도는 항공 품질의 Critical·Major·Minor 결함 수준을 차용하며, 기능상 중대 결함이 우려되는 변경을 Critical에 넣고, 난이도가 높으면 한 단계 올리되 난이도로 낮추지 않는다(D1). 다른 문서는 그 문서와 절을 참조한다 ② 적용본에 분류마다 품질 평가 단계(명세 판정·인수 시험의 적용)와 기본 모델 등급이 한 문서에 있다. Critical·Major는 기본 고급이며 중급으로 낮추지 않고, Minor는 기본 중급이며 고급은 REQ 명시와 대표님 승인으로 올린다. 인수 시험은 Critical·Major에 두고 Minor에는 두지 않는다(D2, D4) ③ 적용본에 모델 등급 세 가지와 등급별 모델(최고급: Fable급, Astra. 고급: Opus, Sol급, Gemini Pro급. 중급: Sonnet급, GPT Luna급, Gemini Flash급), 「항상 최신 버전」, 기본값(고급 Opus 최신 버전·`medium`, 중급 Sonnet 최신 버전·`medium`), 「최고급은 기본 등급이 아니다」가 한 문서에만 있다 ④ 적용본에 단계별 모델이 있다.
