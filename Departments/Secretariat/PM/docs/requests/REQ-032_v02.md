  - **경로가 범위를 정하는 곳**: `AGENTS.md` 「불변 원칙」 3항(거버넌스 구역의 `Departments/Development/assets/scripts/`)과 5항(판정 전제 제외의 `Departments/Secretariat/assets/`), `.gitattributes`의 배포본 제외 규칙(`Departments/*/results/**`, `Departments/*/workspace/**`, `Departments/Secretariat/assets/*/**` 등 부서 바로 아래 한 단계 패턴), `.claude/settings.json`의 `deny`(`Edit(Departments/Development/assets/scripts/**)` 등)와 `allow`(`Bash(python Departments/*/workspace/*)`, 커밋 전 검사 스크립트 경로), `check_standard.py`의 `WHITELIST_PREFIXES`(`Departments/Secretariat/docs/requests/REQ-`, `Departments/Secretariat/assets/` 등)와 부서 직속 `results/`·`workspace/` 대조 제외, `.githooks/pre-commit`의 스크립트 경로가 있다. Grep 도구로 `Departments/`를 세면 `AGENTS.md` 10줄, `Workflow/01`~`07`에 92줄이 나온다.
  - **연락 폴더와 셸 작업 폴더**: 연락 파일은 `Departments/Secretariat/assets/inbox/연락/`에, 셸 작업 지시·결과 파일은 `Departments/Secretariat/assets/inbox/셸작업/`에 있다. 연락 시범은 끝났고 연락 파일은 기록으로 둔다(ORDER 3절 31항).
- **목적**: 폴더를 「부 → 팀」 두 단계로 다시 잡고 파트 폴더는 두지 않으며, 파트별 쓰기 경로를 작업 구역 표에 적어 커밋 전 검사가 경로와 작성 파트를 대조하게 한다. 옛 경로와 새 경로의 대응을 옛 이름·새 이름 대응과 같은 곳에 두고, 경로를 가리키는 모든 곳을 고치며, 옛 경로가 남지 않았음을 검사로 확인하고 남으면 커밋되지 않게 한다. 경로가 권한·제외 범위를 정하는 곳은 옮기는 동안에도 보호가 빠지지 않게 한다. 반영할 문구와 위치, 폴더 생성·파일 이동·검사의 수단은 EC(없으면 명세 단계 산출물)에서 정한다.
- **분류 근거**: 중요도는 Critical이다. 이 REQ는 권한 설정(`deny`·`allow`), 판정 전제 제외 경로, 커밋 전 검사의 제외 목록과 작성 파트 대조, 배포본 제외 규칙의 경로를 바꾼다. 결함이 생기면 보호 범위에서 빠지는 경로가 생겨 거버넌스 파일이 판정 없이 고쳐지거나 내부 기록이 배포본에 들어가는 등 모든 안건의 통제와 보안이 무너진다(`Workflow/03_라이프사이클` 「분류별 단계」 표 Critical 행 「모든 안건의 통제가 무너지거나 보안·데이터에 피해가 생기는 변경」). 고치는 파일도 거버넌스 파일과 보안·권한 설정이다(같은 표의 예). ORDER `classification_proposal`(Critical)과 같다.

## 5. 검증 및 완료 기준 (체크리스트)
> 작성 기준은 `Workflow/03_라이프사이클` 「REQ 작성 파이프라인」을 따른다. 확인 방법이 명령·시험의 실행 결과인 항목은 인수 시험의 대상이 된다(`Workflow/03_라이프사이클` 「시험실」). 「적용본」은 설계·개발 적용본 폴더의 최신 버전을 가리킨다. 「현행 거버넌스 파일」은 `AGENTS.md`, `Workflow/` 전체, `.claude/` 전체, `.githooks/`, `.gitattributes`, `check_standard.py`에서, 적용본이 있는 파일은 적용본을, 없는 파일은 원본을 말한다. 「규정이 있다」는 현행 거버넌스 파일 가운데 EC(없으면 명세 단계 산출물)가 정한 위치에 그 내용이 있다는 뜻이다. 「반영 뒤 상태」는 결과서의 반영 명령(이동 포함)을 시험 저장소(pytest `tmp_path` 아래)에 적용한 상태를 말한다. 개정 이력 표는 Grep 확인에서 뺀다. 각 항목은 3절 D1~D12의 권고안을 전제로 한다.

| 번호 | 요청 원문 항목 | 확인 방법 |
| :---: | :--- | :--- |
| 18 | 요구 항목 18: 폴더와 작업 구역 재편 | ① 현행 `Workflow/02` 저장소 구조·공통 하위 폴더에 「부 → 팀」 두 단계 구조, 팀 폴더 안의 공통 하위 폴더, 파트 폴더를 두지 않는다는 규정과 한 파트만 쓰는 자산을 팀 폴더 아래 용도 이름 하위 폴더에 둔다는 규정이 있고, 팀 폴더 이름이 팀의 영문 이름이다(D1) ② 반영 뒤 상태에서 부서 폴더 이름 여섯 개가 그대로 있고, 활성 파트가 있는 팀의 폴더만 있으며 대기 팀 폴더와 파트 폴더가 없고, 운영부·마케팅부 폴더는 그 바로 아래 폴더 자리 하나만 있다(D3. 반영 명령을 시험 저장소에 적용한 실행 결과) ③ 반영 뒤 상태에서 기존 파일이 결과서의 이동 목록대로 새 경로에 있고 내용이 바뀌지 않았다(이동 전후 파일 해시 대조 실행 결과)(D2) ④ 현행 `Workflow/02` 4절 작업 구역 표에 파트 단위 쓰기 경로가 있고, 커밋 전 검사가 작성 주체 칸으로 경로를 대조해 다른 파트의 경로에 쓴 머리말 있는 파일을 실패시키며, 머리말이 없거나 작성 주체 칸이 없는 파일은 작성 파트를 대조하지 않는다(시험 저장소 실행 결과)(D7·D9) ⑤ 옛 경로·새 경로 대응이 `Workflow/02`의 옛 이름·새 이름 대응과 같은 곳에 있다 ⑥ 반영 뒤 상태에서 옛 경로 잔존 검사를 실행하면 D12의 대상 범위에서 옛 경로가 0건이고 뺀 범위가 실행 결과에 출력되며, 옛 경로를 하나 넣은 대상 범위 안 파일을 스테이징하면 커밋 전 검사가 실패한다(시험 저장소 실행 결과)(D8·D12) ⑦ 판정 전제 제외, 거버넌스 구역의 스크립트 경로, 배포본 제외 규칙, `deny`·`ask`·`allow` 규칙, 커밋 전 검사의 대조 제외 목록마다 옛 범위와 새 범위의 대응이 EC(없으면 명세 단계 산출물)에 있고, 반영 뒤 상태에서 각 규칙이 옛 범위와 같은 종류의 파일을 덮는다(배포본 제외는 `git archive` 목록, 대조 제외는 커밋 전 검사 실행 결과로 확인)(D4) ⑧ PM팀 폴더의 REQ·실행 기록이 `AGENTS.md` 「불변 원칙」 5항의 판정 전제 제외에 들지 않고, 커밋 전 검사의 대조 제외에는 지금처럼 든다(D4) ⑨ 반영 명령이 파일 이동과 권한 설정·배포본 제외·커밋 전 검사·훅·규정 문서의 변경을 같은 커밋에 반영하도록 적혀 있다(결과서 열람)(D5) ⑩ 연락 폴더와 셸 작업 폴더의 새 위치가 비서팀 폴더 `workspace/` 아래로 규정에 있고, 그 두 폴더가 판정 전제 제외·커밋 전 검사 대조 제외·배포본 제외에 들어 있다(D6) ⑪ 이미 작성된 기록(판정서, 결과서, 승인 기록, 요청 기록, 연락 파일 등)의 내용이 바뀌지 않았다(`git diff`로 내용 변경 없음 확인) ⑫ 이 REQ가 바꾼 규정과 경로의 적용 시점이 규정에 있다(D10) |
