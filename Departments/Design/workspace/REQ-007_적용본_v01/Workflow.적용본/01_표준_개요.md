# 01. 표준 개요

> 이 문서가 정하는 것: 표준의 목적, 구성 수단, 표준 구역과 고객 작업 구역의 구분, 용어.
> 다른 문서가 정하는 것: 부서·폴더 → `Workflow/02_부서_구조_및_작업구역`, 진행 절차 → `Workflow/03_라이프사이클`, 배포본 → `Workflow/06_통제장치_및_배포`.

## 1. 목적

바이브 코딩 표준은 여러 AI 에이전트가 한 저장소에서 소프트웨어를 함께 만들 때 생기는 세 가지 문제를 막는 작업 표준이다.

- 승인 없는 수정
- 승인 범위를 벗어난 수정
- 작성한 세션의 자기 판정

## 2. 구성 수단

1. **문서 체계**: 모든 작업은 승인된 안건(REQ)에서 시작해 최종 판정서(RES)로 끝난다. 긴급 결함은 핫픽스 기록(HOTFIX)으로 처리한다.
2. **폴더 체계**: 부서별 작업 공간을 나누고, 모든 부서가 같은 1차 하위폴더 4개를 쓴다.
3. **기계적 통제**: Claude Code 권한 설정과 커밋 전 검사로 규칙 위반을 막는다.
4. **독립 판정**: 품질 판정은 작성 세션과 분리된 Claude Code 품질 서브에이전트가 수행한다.

## 3. 표준 구역과 고객 작업 구역

이 저장소는 신규 프로젝트의 출발점으로 복제해 쓰는 상품이다. 내용을 아래 네 구역으로 나눈다.

| 구역 | 경로 | 내용 |
| :--- | :--- | :--- |
| 표준 구역 | 거버넌스 파일(`AGENTS.md` 「불변 원칙」 3항의 목록) | 표준 자체의 규정, 매뉴얼, 서식, 통제 장치 |
| 고객 작업 구역 | `Departments/`(거버넌스 경로 제외), `Audits/` | 이 저장소로 만드는 제품의 안건, 명세, 코드, 판정서, 외부 검토 보고서 |
| 대표님 구역 | `CEO/` | 대표님 전용 자료(권한 한계는 `AGENTS.md` 「부서와 권한 한계」) |
| 보관 구역 | `_archive/` | 지난 버전의 기록. 대표님만 수정한다(`Workflow/02_부서_구조_및_작업구역` 「작업 구역」) |

- 표준 자체의 설계를 제품 명세(PRD·TAD)로 작성하지 않는다. 표준 개정 안건의 기록(REQ·EC·결과서·판정서)은 다른 안건과 같은 위치에 둔다.
- 표준을 개정한 기록(REQ·RES 등)은 배포본에서 뺀다(`Workflow/06_통제장치_및_배포` 「배포본과 업데이트 패키지」).

## 4. 용어 (REQ-007_v09)

| 용어 | 뜻 | 쓰지 않는 말 |
| :--- | :--- | :--- |
| 창구 | 대표님과 대화하며 요구를 모으고 결과를 보고하는 AI 세션(코워크, Antigravity 등). 요구 메모, 검토 보고서, 승인 기록, 승인 필드와 「결정」 열(`Workflow/07_문서_서식_및_번호` 「승인 기록」) 외에는 저장소 파일을 고치지 않는다 | 비서실 에이전트(창구를 가리킬 때) |
| 비서실 세션 | Claude Code의 `secretariat` 서브에이전트. REQ와 체크리스트를 작성하고 핫픽스를 수행한다 | — |
| 오케스트레이터 | 실행 명령으로 기동한 Claude Code 메인 세션. 서브에이전트를 순서대로 기동하고 인계한다. 대표님에게서 직접 받은 승인 문구로 승인 기록을 남기고 승인 필드와 「결정」 열을 기재할 수 있다(`Workflow/07_문서_서식_및_번호` 「승인 기록」) | — |
| 독립 세션 | 이전 단계의 대화 내용 없이 새로 기동한 서브에이전트 | — |
| REQ 판정 | 승인 전 REQ의 품질 판정. 판정서 `RES-xxx-REQ` | REQ 검토 |
| EC 판정 | EC의 품질 판정. 판정서 `RES-xxx-EC` | 1차 게이트, 사전 승인(EC 판정을 가리킬 때) |
| 최종 판정 | 구현 결과의 품질 판정. 판정서 `RES-xxx` | 2차 게이트, 삼중 검수 |
| 체크리스트 | REQ 「검증 및 완료 기준」 절의 번호 목록(작성 기준은 `Workflow/03_라이프사이클` 「REQ 작성 파이프라인」) | 점검표, 전수 점검표 |
| 파생 안건 | 원 안건에서 미결로 남거나 새로 생긴 작업. 번호는 `REQ-xxx-n` | 재작업 절차서(RP), 재의뢰 |
| 적용본 | 거버넌스 파일을 고쳐 쓴 사본. 담당 부서 `workspace/`에 작성하고 대표님이 원본에 반영한다 | 개정안(적용본을 가리킬 때) |
| 배포본 | 신규 프로젝트용으로 내보내는 저장소 묶음. 푸는 자리는 `Package_sample/`이다 | sample(파일명 `vibe_sample.tar`, 폴더명 `Package_sample` 제외) |
| 업데이트 패키지 | 기존 프로젝트에 덮어쓰는 표준 구역 파일 묶음. 푸는 자리는 `Package_update/`이다 | Update_Package(옛 폴더명) |
