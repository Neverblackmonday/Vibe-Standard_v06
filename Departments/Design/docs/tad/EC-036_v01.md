### 3.4 파일별 변경 내용
명세·구현 단계는 아래 항목을 적용본에 반영한다. 문구는 이 절의 뜻을 바꾸지 않는 범위에서 작성 부서가 정한다.

**F1. `.claude/settings.json`(구현)**
- **`ask`**: `permissions.ask`의 기존 Bash 규칙 여섯 개 뒤에 아래 규칙을 더한다. 형식은 기존 규칙과 같이 명령 앞부분 뒤에 `*`를 붙인다(커밋·푸시는 `PowerShell(git commit*)`, `PowerShell(git push*)`, 그 밖은 `PowerShell(<명령> *)`).
  - 커밋·푸시: `git commit`, `git push`
  - 삭제: `Remove-Item`과 그 기본 별칭. PowerShell 5.1의 예상 별칭은 `rm`, `del`, `erase`, `rd`, `rmdir`, `ri`다.
  - 이동: `Move-Item`과 그 기본 별칭. 예상 별칭은 `mv`, `move`, `mi`다.
  - 별칭 목록은 구현 단계에서 부서 `workspace/`의 스크립트(`Bash(python Departments/*/workspace/*)` 규칙)로 `Get-Alias -Definition Remove-Item, Move-Item` 결과를 조회해 확정하고, 조회 명령과 결과 원문을 결과서에 적는다.
  - 기존 `allow`·`deny`와 Bash `ask` 여섯 개는 바꾸지 않는다(체크리스트 1 ②).
- **훅**: `hooks.PreToolUse`에 항목 하나를 둔다. `matcher`는 서브에이전트 기동 도구 이름(`Agent`. Claude Code가 쓰는 이름은 구현 실측으로 확정한다)이고, `type: command`의 명령 하나가 아래 규칙으로 검사한다. 입력은 표준 입력의 JSON(`tool_input`의 `subagent_type`, `model`, `prompt`)이다.
  - H1 대상: `tool_input.subagent_type`이 `quality`인 호출만 검사하고, 그 밖의 호출은 통과시킨다(D6. 다른 부서 서브에이전트의 기동은 바뀌지 않는다).
  - H2 최종 판정 기동의 판단: `tool_input.prompt`의 단계명 표기(`단계명:` 뒤의 값. F4 「3절 1항」)가 「최종 판정」으로 시작하면 최종 판정 기동으로 본다. 「최종」과 「판정」 사이의 공백 유무, `단계명:` 앞뒤의 공백은 따지지 않는다.
  - H3 최종 판정 기동: 호출 인자 `model`이 없거나, 값에 고급 이상 계열의 이름이 없으면 막는다. 고급 이상 계열은 `Workflow/04_모델_운용` 1.1절 표의 고급·최고급 가운데 Claude Code에서 실행할 수 있는 계열(지금은 `opus`, `fable`. 대소문자를 따지지 않는다)이다. 모델 ID(`claude-opus-5-5`)와 별칭(`opus`)이 모두 맞으며, 같은 계열의 새 버전으로 바꾸는 모델 ID 갱신(`Workflow/07_문서_서식_및_번호` 「모델 ID 갱신의 예외」)에는 고칠 곳이 없다.
  - H4 그 밖의 품질 기동: 호출 인자 `model`이 있으면 막는다. 없으면 통과시켜 정의 파일의 `model: inherit`로 PM 모델을 이어받게 한다.
  - H5 막을 때: 종료 코드 2로 끝내고, 표준 오류에 막은 사유와 조치(최종 판정은 1.2절 표 넷째 행의 모델 ID를 호출 인자로 줌, 그 밖은 호출 인자를 빼고 다시 기동함, 근거 `Workflow/04_모델_운용` 1.2절 「PM의 책임」 ⑥)를 출력한다.
  - H6 명령의 형태: 명령은 `settings.json` 안에 둔다(별도 스크립트 파일을 만들지 않는다. 2.3절). 검사가 실행되지 않거나(예: `python`을 찾지 못함) 오류로 끝나면 통과시키지 않고 막는다(종료 코드 2). 종료 코드 2가 아닌 실패는 Claude Code가 도구 실행을 막지 않기 때문이다. 표준 입력은 UTF-8로 읽고, 명령 문자열의 한글은 셸·코드 페이지에 따라 깨지지 않게 한다(예: 유니코드 이스케이프). 구체 형태는 구현이 정하고 실측한다.

**F2. `.gitattributes`(구현)**
- 맨 앞(기존 `*.bat` 줄 앞)에 기본 규칙 `* text=auto eol=lf`와 그 위 주석 한 줄을 둔다. 주석에는 텍스트 파일은 작업 트리에서도 LF이고, 같은 파일에 여러 규칙이 맞으면 뒤의 규칙이 앞서므로 뒤의 `*.bat`·`*.cmd`(CRLF)와 `.githooks/*`(LF) 규칙이 기본 규칙보다 앞선다는 뜻을 적는다.
- 기존 줄바꿈 규칙 세 줄과 배포본 제외 규칙은 바꾸지 않는다.
- **D4 참고 명령**: 개발 결과서에 반영 명령 표와 나뉜 「참고 명령(대표님이 최종 승인 커밋 뒤 실행)」을 적는다. 조건은 아래와 같다.
  - 저장소 루트에서 Git 명령만으로 실행한다. 부서 `workspace/` 스크립트는 최종 승인 커밋 때 삭제 대상으로 정리될 수 있으므로(`Workflow/03_라이프사이클` 최종 판정 기준 7) 쓰지 않는다.
  - 실행 뒤 추적 텍스트 파일(유지하는 예외 `*.bat`·`*.cmd` 제외)의 작업 트리 줄바꿈이 LF이고, 수정한 추적 파일과 미추적 파일의 내용이 줄바꿈 밖에서 바뀌지 않는다(체크리스트 2 ③).
  - 후보 순서는 `git stash push --include-untracked`, `git rm --cached -r -q .`, `git reset --hard`, `git stash pop`이다. 구현이 임시 복제에서 실측해 조건을 충족하는 명령을 확정한다. 후보가 조건을 충족하지 못하면 다른 Git 명령으로 바꾸고, 바꾼 까닭을 적는다.
  - 실행 전 확인(`git status --porcelain -uall`로 진행 중인 변경을 확인)과, 되돌릴 수 없는 명령(`git reset --hard`)이 들어 있다는 주의를 함께 적는다.
  - 대상 파일 수는 구현 때 `git ls-files --eol`로 다시 세어 적는다(D4 문안의 989개는 2026-10-26 조회 값).

**F3. `Workflow/03_라이프사이클.md`(명세)**

**구현 실측(개발)**
아래 실측은 부서 `workspace/`의 일회성 스크립트(2.1절 11번)로 임시 폴더에서 하고, 명령·시각·결과 원문을 결과서에 적는다. 저장소 파일은 적용본과 결과서 밖에서 바꾸지 않는다.
- ① 요구 항목 1: 별칭 목록 조회(F1 「`ask`」).
- ② 요구 항목 2: 적용본 `.gitattributes`를 넣은 임시 저장소에서 `core.autocrlf=true`·`false` 체크아웃의 텍스트 파일 해시와 줄바꿈, `*.bat`·`*.cmd`·`.githooks/*`의 줄바꿈(체크리스트 2 ①②와 같은 내용). 이어서 CRLF로 체크아웃된 작업 트리(`core.autocrlf=true`)에 적용본 `.gitattributes`만 바꿔 넣었을 때 `git status --porcelain -uall`에 `.gitattributes` 밖의 경로가 나오지 않는지(4절 위험 6).
- ③ D4: 임시 복제(수정한 추적 파일과 미추적 파일을 둔 상태)에서 F2 「D4 참고 명령」을 실행한 결과(체크리스트 2 ③).
- ④ 요구 항목 4(훅 명령의 직접 실행): 적용본 훅 명령에 표준 입력 JSON을 주어 실행한 종료 코드와 출력. 경우는 최소한 품질 밖 기동(통과), 그 밖의 품질 기동의 인자 없음(통과)·인자 있음(막음), 최종 판정 기동의 인자 없음·중급 모델 ID·`sonnet`·`haiku`(막음)과 고급 모델 ID·`opus`(통과), 「최종판정」 표기(최종 판정으로 봄), 깨진 JSON(막음)이다.
- ⑤ 요구 항목 4(실제 기동 시도): 적용본 `settings.json`과 정의 파일을 둔 임시 복제에서, PM 모델과 판정 모델이 다른 경우(Minor 안건의 최종 판정: PM 세션 `claude-sonnet-5-5`)를 재현한 Claude Code 세션이 품질 서브에이전트를 판정 모델과 다른 모델로 기동하려는 시도(인자 없이 기동, 인자 `sonnet`으로 기동)가 막히는지와, 인자 `claude-opus-5-5`로 기동하면 판정 모델로 실행되는지를 확인한다(체크리스트 4 ①). 실행 모델의 확인 수단과 그 한계(예: 세션 기록 파일의 `model` 값. `Workflow/06` 7절 1행)를 함께 적는다. 이 시도를 실행할 수 없으면 `Workflow/03_라이프사이클` 「판정 세션 밖의 명령 실행」대로 결과서 「실행하지 못한 명령」 표에 적는다.
- ⑥ 훅이 실행되는 셸에서 F1 H6의 처리(검사가 실행되지 않거나 오류로 끝나면 막음)가 동작하는지.

| 8 | 훅의 고급 이상 계열 이름이 `Workflow/04` 1.1절 표와 어긋남 | 등급 배정이나 계열이 바뀐 뒤 훅이 맞는 기동을 막거나 틀린 기동을 통과시킨다 | 계열 이름만 쓰므로 같은 계열의 모델 ID 갱신에는 고칠 곳이 없다. 등급 배정·계열 변경은 ORDER·REQ로 하므로(`Workflow/04` 1.1절 「갱신」 ①) 그 개정 때 함께 고친다는 것을 `Workflow/06` 2절 「훅」에 적는다(F5) |
| 9 | 훅 명령이 `settings.json`의 한 줄 문자열이라 읽고 고치기 어렵다 | 뒤의 개정에서 규칙을 잘못 고칠 수 있다 | 규칙의 요지를 `Workflow/06` 2절 「훅」에 적고, 구현 실측 ④의 경우 목록을 결과서에 남긴다. 별도 스크립트 파일은 이 REQ `scope:` 밖이다(REQ 3절 「D5와 `scope:`」) |
