### 3.3 적용본 설계 (명세 단계)
적용본은 원본을 복사한 뒤 아래 위치만 고친다. 「바꿀 요지」는 `RPT-009` 6.1절의 해당 번호를 따르고, 아래에는 그 위에 더하는 제약만 적는다. 위치는 행 번호가 아니라 절과 문구로 찾는다. 원본 문구가 `RPT-009`이 인용한 문구와 다르면 고치지 말고 그 사실을 `RPT-010`에 적은 뒤 대응표에 반영 여부를 적는다. 모든 적용본은 01 적용본 「용어」의 「쓰지 않는 말」을 그 맥락대로 쓰지 않는다.

1. **01 적용본**(6.1절 6·7·8번, E1·E4·E6)
   - 「용어」 표: 창구 행 → 비서실 행(대상 서비스: 코워크, Antigravity, 채팅 서비스(claude.ai 채팅 등)). 비서실 세션 행 삭제. 오케스트레이터 행 → PM 행(Claude Code 메인 세션, 실행 명령으로 기동, REQ 작성과 파이프라인 지휘, 승인 기재는 07 「승인 기록」 참조, 「오케스트레이터」는 PM의 다른 호칭). ORDER 행 신설(비서실이 대표님 지시를 정리한 작업 지시서, 위치·서식·번호는 07 참조, 승인 필드가 없음).
   - 「쓰지 않는 말」은 E1을 따른다.
2. **02 적용본**(6.1절 2·3·9~14번, E6)
   - 머리(9번), 2절 표 비서실 행(10번): 서브에이전트 열은 「—」와 「저장소 밖 서비스」의 뜻이 드러나게 적는다. 책임 열에 비서실(ORDER 작성, 핫픽스)과 PM(REQ와 체크리스트 작성)을 구분해 적는다.
   - 2.1절(11·12·2번): 제목 「비서실과 PM의 책무」. 표는 `RPT-009` 3.1절 책무 1~6과 3.2절 책무 1~4다. 2.1절 문장(2번)의 비서실 수정 범위는 `RPT-009` 3.1절 「수정할 수 있는 경로」와 같게 하고, PM의 수정 범위는 4절 「작업 구역」을 참조한다.
   - 4절 「작업 구역」(3·13·14번): `RPT-009` 3.1·3.2절 「수정할 수 있는 경로」와 행마다 같아야 한다. PM 행에는 ORDER 머리말 `related_req` 필드를 넣는다. 「승인 기재」 행의 주체는 「비서실, PM」이며 PM이 오케스트레이터와 같은 주체임은 01 「용어」 참조로 드러낸다.
