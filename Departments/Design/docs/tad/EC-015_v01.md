```text
    ├── 8.3 고정 절차          (승인 기록, 최종 승인 커밋, 요청 커밋, 요청 푸시, 핫픽스, PM 기동 + 예외)
    └── 8.4 비서실 동시 운용   (대상, 세션 식별자, 담당 세션, 번호·주제 충돌, 같은 파일과 Git 작업)
```

일회성 파일의 흐름은 아래와 같다.

```text
각 부서: 부서 workspace/에 <REQ 번호>_<내용>... 이름으로 일회성 파일 작성 (07 2절)
→ 품질(최종 판정): 범위 대조 때 조회한 작업 트리에서 기준(03 5절 기준 7)에 맞는 파일을 판정서 「삭제 대상」에 기재
→ 비서실: 1절 ⑦ 보고·승인 브리핑에 그 목록 포함
→ 대표님: 최종 판정서 승인 (= 목록의 삭제 승인, 05 1.1절 1번)
→ 비서실: 1.1절 5번 정리(미추적은 삭제, 추적 중이면 git rm) → 6번 ⑥으로 커밋에 포함
```

명세는 이 결정을 따르고, `RPT-015` 반영 대응표의 해당 행에 결정 번호를 적는다.

| F7 | 실패의 정의와 정지 뒤 처리 | 실패: ① 종료 코드가 0이 아니다 ② 출력에 `[FAIL]`, `error:`, `fatal:`이 있다 ③ 절차가 정한 확인 결과가 기대와 다르다(예: 커밋된 파일 목록이 스테이징한 목록과 다르다) ④ 권한 확인을 대표님이 거부했다. `[WARN]`은 실패가 아니며 보고에 적는다. 실패하거나 고정 절차에 없는 상황이 생기면 그 단계에서 멈추고, 이미 한 변경을 되돌리지 않으며, 다른 명령·옵션으로 우회하거나 다시 시도하지 않고, 5절 3항 ①의 상세 보고를 한다. 상세 보고에는 멈춘 단계, 실행한 명령, 종료 코드, 출력 원문, 멈춘 때의 `git status --porcelain -uall` 결과를 적는다 | ORDER 원인 B 「실패 정의」, 「멈춘 뒤 되돌리지 않음」. 되돌리면 대표님이 멈춘 상태를 확인할 수 없고, 되돌리는 명령은 F6 ①이다. 상세 보고의 원천은 5절 3항 ①이며 8.1절은 비서실 작업에서 더 적을 항목만 정한다 |

| F10 | Git 작업을 한 번에 한 세션만 하는 방법 | 스테이징을 시작하기 전과 푸시하기 전에 `git diff --cached --name-only` 결과가 비어 있는지 확인한다. 비어 있지 않으면 다른 세션이나 대표님이 Git 작업 중인 것으로 보고 멈춘 뒤 보고한다. 스테이징은 경로를 지정해 한다. 커밋 뒤 `git show --name-status --format= HEAD`의 파일 목록이 스테이징한 목록과 같은지 확인한다 | D7 ④ 권고안. 별도 잠금 파일을 두지 않고 Git의 스테이징 영역 상태로 진행 중인 작업을 알아낸다(`AGENTS.md` 「불변 원칙」 6항). 동시 Git 명령은 Git의 `index.lock`이 실패로 만든다(F7 ①) |

     3. **실행 대상**: 대표님이 보낸 호출 문구나 대표님 지시만 실행하고, 그 대상 밖 작업을 더하지 않는다. 호출 문구의 발신자 규칙은 8.2절을 따른다.
