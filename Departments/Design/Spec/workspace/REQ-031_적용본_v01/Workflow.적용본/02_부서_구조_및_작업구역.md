# 02. 부서 구조 및 작업구역

> 이 문서가 정하는 것: 저장소 구조, 구역과 관리 책임, 부서별 책임과 산출물, 조직 표(부·팀·파트와 코드), 옛 이름과 새 이름의 대응, 비서실·PM의 책무, 작업 구역(누가 언제 어디를 수정할 수 있는가).
> 다른 문서가 정하는 것: 조직·구역의 권한 한계 → `AGENTS.md` 「조직·구역과 권한 한계」, 산출물 이름·번호 → `Workflow/07_문서_서식_및_번호`.


### 1.1 구역과 관리 책임 (REQ-031_v03)

조직(비서실과 부서)과 그 기능은 정규 규칙(REQ·scope·판정)을 따르므로 `Departments/` 안에 둔다. 정규 규칙 밖이거나 독립해야 하는 구역은 저장소 루트에 둔다. 구역마다 관리 책임 조직을 하나씩 정한다.

| 구역 | 경로 | 쓰임 | 관리 책임 조직 |
| :--- | :--- | :--- | :--- |
| 표준 | `Workflow/` | 매뉴얼과 서식 | 대표실 |
| 대표님 자료 | `CEO/` | 대표님 전용 자료 | 대표실 |
| 보관 | `_archive/` | 지난 버전 기록 | 대표실 |
| 외부감사실 | `Audits/` | 외부 보고서 | 비서실 |
| 실험실 | `Lab/` | 버리는 코드와 시안 | 비서실 |
| 자료실 | `Storage/` | 서버실(`server/`)과 패키지 자리(`package/sample/`, `package/update/`) | 운영부 |

- 관리 책임은 그 구역의 쓰임과 정리를 책임지는 것이며, 수정 권한(4절)을 바꾸지 않는다.

- 서브에이전트 정의는 `.claude/agents/<서브에이전트>.md`에 둔다. 정의 파일은 역할과 참조할 절만 적고, 이 문서의 책임·산출물을 다시 적지 않는다.
- 설계 파라미터(`Design/assets/live/`)는 명세가 정하는 기준값이고, 런타임 파라미터(`Operations/assets/live/`)는 운영 중 바뀌는 값이다.

- 설계부 서브에이전트 이름 `engineering`과, 시각 디자인을 마케팅부의 기능으로 둔 조직 구성은 `REQ-027` 커밋 뒤에 기동하는 PM 세션(실행 명령으로 기동하는 파이프라인 실행)부터 적용한다. 이미 실행 중인 PM 세션은 기동 때의 규정으로 진행한다. 이미 작성된 기록(머리말 `author.agent`, 판정서·결과서 본문의 서브에이전트 이름과 부서 폴더 경로 등)은 바꾸지 않는다.
- 조직 개편(부·팀·파트와 이름), 핫픽스·커밋·푸시의 주체, 비서실의 정의·경계와 Claude Code로 연 비서실·핫픽스 세션의 권한 등 `REQ-031`이 바꾼 규정은 `REQ-031` 커밋 뒤에 기동하는 세션(PM 세션, 비서실 세션이 시작하는 실행 절차, 형상통제팀(C02)·핫픽스팀(V03) 세션)부터 적용한다. 이미 실행 중인 세션은 기동 때의 규정으로 진행한다(`Workflow/03_라이프사이클` 「판정 세션 밖의 명령 실행」 7항과 같은 방식). 이미 작성된 기록(승인된 REQ, 판정서, 결과서, HOTFIX, 승인 기록, 요청 기록, 커밋 메시지 등)의 옛 이름·옛 주체 표기는 고치지 않고 2.3절로 읽는다. v05의 번호 예외는 `Workflow/07_문서_서식_및_번호` 「번호와 버전」, REQ 작성 시각과 원스톱 착수 대조의 적용 시점은 `Workflow/03_라이프사이클` 「원스톱 착수 조건」 8항을 따른다.

### 2.1 비서실과 PM의 책무 (REQ-031_v03)

| 주체 | 책무 |
| :--- | :--- |
| 비서실(비서팀 S01~S03, 형상통제팀 C01~C03) | ① (S01) 대표님과 대화해 요구를 모으고 `Departments/Secretariat/assets/inbox/`에 ORDER를 작성한다. - **파트의 일을 맡는 세션**: 비서팀·형상통제팀 파트는 비서실 세션이, PM팀 파트는 PM이 맡는다. 핫픽스팀(V03)은 핫픽스 실행 명령으로 기동한 세션이 맡는다(`Workflow/03_라이프사이클` 「핫픽스 트랙」). 그 밖의 파트는 파트별 서브에이전트 정의를 두기 전까지 그 부의 서브에이전트(2절 표의 서브에이전트 칸)가 맡는다(예: 판정팀 Q01~Q05는 `quality`). X01은 실험 단계를 맡는 부의 서브에이전트가 맡는다.

## 3. 공통 1차 하위폴더

```text
Departments/<부서>/
├── docs/       # 정제된 문서(기획서, 명세, 안건)
├── assets/     # 실제 자산(코드, 테스트, 스크립트, 파라미터, 조사 자료)
├── results/    # 공식 결과서와 판정서
└── workspace/  # 중간 산출물, 메모, 거버넌스 적용본
```

빈 폴더는 `.gitkeep`으로 유지한다. 비서실 `assets/`에는 바로 아래에 파일을 두지 않고 하위 폴더(`inbox/`, `research/`, `planning/`, `briefings/`)에만 둔다. 최종 산출물은 `docs/`, `assets/`, `results/`에만 둔다.
