# 작업 큐

> 파일명은 `작업큐_v<두 자리 버전>.md`이고 위치는 `Departments/Secretariat/Secretary/assets/queue/`다. 작업 큐는 하나이며 가장 높은 버전이 현행본이다. 관리 주체, 순서 변경, 진행 상태를 읽는 방법, 겹침·충돌 확인은 `Workflow/05_인수인계_및_실행명령` 「작업 큐」를, 버전을 올리는 시점은 `Workflow/07_문서_서식_및_번호` 「번호와 버전」의 「비서실 산출물의 버전」을 따른다. 이 안내문은 작성할 때 지운다.

## 작성 정보
- 작성 세션: 이 버전을 작성한 비서팀(S01) 세션의 세션 식별자(`Workflow/05_인수인계_및_실행명령` 「비서실 동시 운용」)와 모델
- 상태를 읽은 시각: `YYYY-MM-DDTHH:MM:SS+09:00`(진행 상태를 단계 산출물과 종결 기록에서 읽은 시각)
- 순서의 근거: 이 버전의 순서를 정한 대표님 결정 문구 원문과 문구를 받은 시각. 첫 버전이면 옮긴 원천(비서실 임시 대장 최신 버전과 이미 발행된 ORDER 5절의 경로)과 대표님 확인 문구
- 버전별 변경 요지: `vNN 변경: <요지>` 형태로 버전마다 한 줄씩 더한다. v01이면 「없음」으로 적는다

## 처리 순서
> 행마다 ORDER나 REQ 하나를 적는다. 「진행 상태」는 「ORDER만 있음」, 「REQ 판정 중」, 「REQ 승인 대기」, 「원스톱 실행 중(<최신 단계 산출물>)」, 「최종 판정서 승인 대기」, 「끝남(<종결 기록 경로>)」 가운데 하나이며, 따로 판단하지 않고 「상태 근거」 열의 파일에서 읽어 적는다.

| 순서 | 기록(ORDER·REQ 이름) | 착수 조건(앞서 끝나야 하는 기록) | 담당 비서실 세션 | 실행 위치(로컬·클라우드) | 진행 상태 | 상태 근거(산출물·종결 기록 경로) |
| :---: | :--- | :--- | :--- | :--- | :--- | :--- |
