Claude Code는 `Write(...)` 11개마다 「파일 권한 검사에 쓰이지 않는다(Edit 규칙이 모든 파일 편집 도구를 덮는다)」고 경고했다. 이름 하나짜리 규칙과 첫 이름 하나에 `/**`를 붙인 규칙은 하위 폴더의 같은 이름에도 맞았고(Write 기준), 여러 단계 경로 규칙(`Departments/Development/assets/scripts/**`)은 저장소 루트 기준 경로에만 맞았다(W12·D13 통과, D8 거부). `.적용본`을 붙인 이름은 막히지 않았다(W13~W15). 실측하지 못한 것: `Write(...)` 규칙 자체의 효력(N1), 실제 거버넌스 경로의 Write 거부(N2), `ask` 규칙의 효력(N3), 셸 명령으로 `deny` 경로에 쓰는 것(N4).

### 3.6 검사·준비 명령 설계 (구현 단계)
모든 명령은 `Departments/Development/Implementation/assets/scripts/` 아래 Python 스크립트이며, 공통 함수(기록 파일명, 머리말 읽기, `scope:` 일치, 승인 필드 형식, 종결 기록)는 `check_standard.py`를 `import`해 쓰고 같은 로직을 다시 구현하지 않는다(근거 자료 3절 1번의 위험). 출력은 지금처럼 `[PASS]`·`[INFO]`·`[WARN]`·`[FAIL]`과 원인·조치이며 UTF-8로 고정한다. 새 명령 안에는 커밋·삭제·이동·파일 쓰기·Git 설정 변경을 하는 명령이 없다(하위 요구 ⑦, 체크리스트 20 ⑦). 각 명령 첫머리 설명에 규칙의 원천 절을 적는다.

1. **작성 파트 대조**(`check_standard.py` 새 순서 5. G6)
   - 대상: 순서 3의 `CEO/` 처리 뒤 남은 변경 경로 가운데 `Departments/` 아래이고 커밋 대상(작업 트리 검사는 작업 트리)에 내용이 있는 파일(대조 제외 구역 포함). `--staged`에서 이름 변경 가운데 내용이 같은 것(`git diff --cached --name-status -M`의 `R100`)의 새 경로는 작성이 아니므로 뺀다.
   - 근거: 파일이 `---`로 시작하는 YAML 머리말을 가지면 `author:` 또는 `auditor:` 아래 `agent:` 값. 머리말이 없거나 두 칸이 모두 없으면 대조하지 않는다(D7).
   - 대조: 값이 파트 코드(`^[SPCEVQOMX]\d{2}$`)면 그 파트의 경로, 부 표기(`Secretariat`→S01~S03·C01~C03, `PM`→P01·P02, `Design`→E01~E04, `Development`→V01~V03, `Quality`→Q01~Q07, `Operations`→O01·O02, `Marketing`→M01~M04)면 그 부 파트들 경로의 합집합에 파일이 있어야 한다. 경로 목록은 3.4절 표의 `Departments/` 아래 경로를 옮긴 상수(`PART_WRITE_PATHS`)이며, REQ `scope:`에 따라 달라지는 칸(「구현」·「명세」·「실험」 행의 `scope:` 경로)은 대조하지 않고 고정 경로만 쓴다. 그 밖의 값(예: `External`, 옛 표기 「창구(Claude 코워크)」)은 실패로 하고 원인(값이 07 3절의 작성 주체 값이 아님)과 조치를 출력한다.
   - 적용 시점(D9): `HEAD`에 `Departments/Development/Implementation/assets/scripts/check_standard.py`가 없으면 이 순서를 생략하고 `[INFO]`(작성 파트 대조는 `REQ-032` 커밋 뒤의 커밋부터 적용)를 출력한다. 파트 코드 값이 없는 동안은 위 부 표기 대조로 부 단위 대조가 된다.
   - 실패: `[FAIL]`, 파일 경로, 작성 주체 값, 허용 경로, 조치(`Workflow/02_부서_구조_및_작업구역` 「작업 구역」의 쓰기 경로로 옮기거나 작성 주체를 확인).

## 6. 실행하지 못한 명령
> 판정 세션 밖 서브에이전트가 이 문서를 작성하는 단계에서 실행하지 못한 명령과, 권한 확인 요청이 승인되어 실행한 명령을 적는다. 기준과 오케스트레이터의 확인은 `Workflow/03_라이프사이클` 「판정 세션 밖의 명령 실행」을 따른다. 대신하지 못했으면 마지막 칸을 「대신하지 못함」으로 시작하고, 승인되어 실행했으면 「확인 요청 승인 뒤 실행」을 적는다. 없으면 표 대신 「없음」을 적는다.
