## 7. 명세 단계에서 정한 사항
EC가 문구를 정하지 않아 명세 단계에서 정한 사항이다. 최종 판정의 대조 대상이다.

1. **07 추적 관계 문장(3절 30번)**: ORDER를 맨 앞에 넣으면 원본 「모두 같은 안건 번호를 쓴다」가 ORDER의 별도 번호(2절)와 어긋나므로 「ORDER를 뺀 문서는 모두 같은 안건 번호를 쓴다. ORDER 번호는 2절을 따른다」로 바꿨다.
2. **07 ORDER 번호 항목(31번)**: 「문서 종류 부분은 `ORD`다(예: `ORD-001_v01.md`)」를 더했다. 1절 표의 파일명과 2절 「기본」 형식(`<종류>-<세 자리 번호>_v<두 자리 버전>.md`)의 관계를 보이기 위해서다.
3. **07 3절 ORDER 필드 설명(32번)**: `ceo_checked_at`은 「비어 있을 수 있다」, `classification_proposal`은 「비서실의 제안이며 확정은 REQ `classification`」, `related_req`는 「버전 없는 이름 목록」으로 적었다(`RPT-009` 4.2절 값 형식). `ceo_checked_at` 기재 자체가 버전을 올리는지는 07에 적지 않았다. ORDER 서식 안내문(`ceo_checked_at` 기재 뒤 본문을 바꾸면 새 버전)이 정하며, `RPT-009` 6.1절 32번이 요구하지 않은 규칙이기 때문이다.
4. **02 2.1절 비서실 ④(11번)**: 핫픽스 절차의 세부 주체는 03 「핫픽스 트랙」 참조로 넘겼다. 03 9절과 02에 같은 절차를 다시 적지 않기 위해서다(기준 ③).
5. **02 2.1절 둘째 항목(12번)**: 3절 표 12번 비고와 같다.
6. **04 1절 비서실 행(19번, E2)**: EC 3.2절 E2 문구 「HOTFIX를 작성하고 핫픽스를 수정하지만」을 「핫픽스 대상 파일을 수정하고 HOTFIX를 작성하지만」으로 적었다. 「핫픽스를 수정」이 핫픽스 기록을 고친다는 뜻으로 읽히지 않게 했고, 절차 순서(수정 → HOTFIX 작성, 03 9절 2항)에 맞췄다. 뜻은 E2와 같다.
7. **06 1절 계층 1(26번, E3)**: 4.4절 R1 처리 결과의 문구다.
8. **REQ 서식 1절 안내(33번)**: ORDER가 여러 REQ로 나뉘는 경우(ORDER 서식 2절 안내)를 함께 덮도록 「이 REQ가 맡는 요구 항목」을 넣었다.
